# WORK-085: 장바구니·주문 할인 표시

상태: 검증 대기 · 작성일: 2026-10-23 · 담당: 준혁

## 목표와 완료 기준

- 장바구니가 할인 상품의 남은 시간과 번개 드롭 재고를 보여 준다.
- 주문하기가 장바구니에서 본 단가와 할인 구분을 보내고, 가격이 바뀌어 거절되면 새 가격을 보여 준다.

## 근거와 범위

- 선행 작업: WORK-082 장바구니 할인 반영, WORK-083 주문하기 할인 반영. 생성 클라이언트는 oag PR에서 만든 것을 쓴다.
- 장바구니의 할인가, 정가 취소선, "특가"·"번개 드롭" 표시는 장바구니 화면에 이미 있다. 이번에는 남은 시간과 번개 드롭 재고, 주문 요청 변경을 더한다.
- 남은 수량 등을 반복해서 다시 불러오지 않는다. 장바구니를 열거나 새로고침할 때 서버에서 새로 읽고, 그 사이에 가격이나 한도가 바뀐 경우는 주문하기에서 서버가 막는다. 카운트다운이 0이 되는 순간에만 한 번 다시 읽는다.
- 카운트다운은 기기 시계 기준이다. 기기 시계가 틀리면 그만큼 일찍·늦게 끝나 보이지만 실제 가격은 주문할 때 서버가 정한다.

## 구현 결과

- `CartItemRow`: 할인 상품에 "남은 시간 HH:MM:SS"(하루가 넘으면 "N일 HH:MM:SS")를 1초마다 갱신해 보여 주고, 번개 드롭은 "재고 N / M개"(남은 수량 / 한정 수량)를 보여 준다. 0이 되면 "할인 종료"로 바뀌고 장바구니를 한 번 다시 읽는다.
- `SaleCountdown`(신규), `formatRemaining`(`cart/format.ts`).
- `domains/cart/api.ts`: 항목 타입에 `saleEndsAt`, `flashDropLimit`.
- `domains/order/api.ts`, `CartSummary`: 주문하기가 `items: [{cartItemId, unitPrice, saleType}]`를 보낸다. 가격 변경(409 `ORDER_010`)을 받으면 서버 메시지를 알리고 장바구니를 다시 읽는다. 멱등 키는 체크한 항목, 수량, 단가, 할인 구분이 바뀌면 새로 만든다.
- `docs/requirements/screens.md`: 장바구니 데이터, 목록, 주문하기 항목.
