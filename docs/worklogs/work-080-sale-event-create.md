# WORK-080: 할인 행사 등록 API

상태: 검증 완료 · 작성일: 2026-10-23 · 담당: 준혁

## 목표와 완료 기준

- 관리자가 특가(상품 여러 개)와 번개 드롭(상품 하나, 한정 수량)을 등록한다.
- 등록 화면의 상품 표에 쓸, 행사에 넣을 수 있는 상품 목록을 준다.
- 같은 상품을 동시에 등록해도 행사는 하나만 저장된다.

## 근거와 범위

- 선행 작업: 없음. 할인 행사 엔티티(`SaleEvent`, `SaleEventItem`)는 dev에 있다.
- 등록 API는 특가와 번개 드롭 둘로 나눴다. 요청 모양(상품 여러 개, 한정 수량)이 달라 하나로 합치면 구분 값에 따라 필드 검증이 갈린다.
- 한 상품은 예정·진행 중인 행사 하나에만 들어간다. 상품 행을 잠근 뒤 행사 여부를 읽어, 같은 상품의 동시 등록은 앞 요청이 끝난 뒤 그 행사를 보고 거절한다. 정가도 잠근 값으로 읽는다.
- 판매 중이 아닌 상품(품절, 판매 중지)은 거절한다.
- 할인가는 서버가 정가에서 할인율만큼 빼고 원 아래를 버려 저장한다.
- 번개 드롭 한정 수량은 재고를 넘을 수 없다. 1인 구매 한도는 1개로 고정이라 받지 않는다.
- 시각은 한국 시간(`Asia/Seoul`)으로 비교한다. 시작 시각은 지금 이후여야 하고 종료는 시작보다 늦어야 한다.
- 등록할 상품 목록은 처음에 "상품 번호를 보내면 재고와 행사 여부를 붙여 주는" API로 만들었다가, 화면에서 행사 중·품절 상품을 숨기려면 페이지가 비지 않게 서버가 걸러 줘야 해서 목록 API로 바꿨다.
- 행사 목록·수정·종료 API와 알림은 이 작업에 넣지 않았다.

## 구현 결과

### API

| 요청 | 설명 | 성공 |
|---|---|---|
| `POST /api/admin/sale-events/special` | 특가 등록. `startsAt`, `endsAt`, `items[{productId, discountRate}]` | 201 `{ saleEventId }` |
| `POST /api/admin/sale-events/flash-drop` | 번개 드롭 등록. `startsAt`, `endsAt`, `productId`, `discountRate`, `limitedQuantity` | 201 `{ saleEventId }` |
| `GET /api/admin/sale-events/products` | 등록할 수 있는 상품 목록. `keyword`, `type`, `page`(기본 1), `size`(기본 10, 최대 100) | 200 `PageResponse<{ productId, productType, name, imageUrl, price, stock }>` |

- 등록 오류: 입력값 오류(할인율 1~99를 벗어남, 종료가 시작보다 빠름, 같은 상품 두 번, 시작이 지금보다 과거, 한정 수량이 재고보다 많음) 400, 없는 상품 404, 품절·판매 중지 409 `PRODUCT_005`, 이미 행사가 있는 상품 409 `SALE_001`(신규).
- 목록에는 판매 중이고 재고가 있으며 예정·진행 중인 행사에 들지 않은 상품만 나온다. 최신 상품(번호 내림차순)이 먼저 온다.
- 모두 관리자만 부를 수 있다.

### 구조

- `SaleEventCreateService`: 특가·번개 드롭 등록. 상품을 ID 순으로 잠가 읽고 판매 여부, 중복 행사, 한정 수량을 확인한다.
- `SaleEventItemRepositoryCustom`·`SaleEventItemRepositoryImpl`(QueryDSL), `SaleCandidateProductQueryService`: 목록 조회.
- `SaleEventItem`: 생성자가 정가와 할인율로 할인가를 계산한다. `SaleEvent.ZONE`(한국 시간)을 둔다.
- `ErrorCode.SALE_EVENT_PRODUCT_DUPLICATED`(`SALE_001`, 409).
