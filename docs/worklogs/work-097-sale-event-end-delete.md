# WORK-097: 할인 행사 종료·삭제 API

상태: 검증 대기 · 작성일: 2026-10-26 · 담당: 준혁

## 목표와 완료 기준

- 관리자가 진행 중인 할인 행사를 중간에 종료한다.
- 관리자가 시작 전인 할인 행사를 행사 항목까지 지운다.
- 시작하지 않았거나 이미 끝난 할인 행사를 종료하거나, 시작한 할인 행사를 삭제하지 못한다.
- 종료한 할인 행사의 상품은 진행 중 할인 조회에서 빠지고 후보 상품에 다시 나온다.

## 근거와 범위

- 선행 작업: WORK-092 할인 행사 수정·상세 조회 API. 할인 행사 상태별 정책은 WORK-092를 따른다(예정 할인 행사는 수정·삭제, 진행 중 할인 행사는 종료만, 종료된 할인 행사는 변경하지 않는다).
- 종료는 새 상태를 만들지 않고 기존 `ENDED`로 바꾼다. 스케줄러(`closeDue`는 열린 상태만, `openDue`는 예정만 바꾼다), 진행 중 할인 조회, 후보 상품 조회가 모두 `ENDED`를 닫힌 할인 행사로 다루기 때문에 그대로 맞는다.
- 종료해도 등록한 종료 시각은 바꾸지 않는다. 종료한 상품은 곧바로 다른 할인 행사에 다시 등록할 수 있다.
- 종료할 수 있는지는 상태가 `SCHEDULED` 또는 `ACTIVE`이고 시작 시각 ≤ 지금 < 종료 시각인지로 본다. 상태 정리 스케줄러가 늦어도 시각으로 진행 중인지 판단한다.
- 삭제할 수 있는지는 상태가 `SCHEDULED`이고 시작 시각이 아직 지나지 않았는지로 본다. 수정 가능 기준(`isEditable`)과 같다. 시작 전 할인 행사의 행사 항목은 주문에 쓰일 수 없어 주문 상품을 따로 확인하지 않는다. 처음에는 주문 상품 확인과 에러 코드를 넣었다가, 지금 구조에서는 걸릴 일이 없는 방어 코드라서 뺐다.
- 두 동작 모두 할인 행사 행을 `FOR UPDATE`로 잠근 뒤 조건을 확인한다. 상태 정리가 같은 할인 행사를 바꾸려 하면 이 요청이 끝날 때까지 기다린다.
- 할인 행사 단위로 동작한다. 예전에 묶어 등록한 할인 행사는 행사 항목이 여럿이어도 한 번에 종료·삭제된다.
- 변경하지 않은 것: 예고 알림 처리, 사용자 화면.

## 구현 결과

- `PATCH /api/admin/sale-events/{saleEventId}/end`(ADMIN): 진행 중인 할인 행사를 `ENDED`로 바꾼다. 200과 데이터 없는 `ApiResponse`를 준다.
- `DELETE /api/admin/sale-events/{saleEventId}`(ADMIN): 시작 전인 할인 행사의 행사 항목과 할인 행사를 지운다. 200과 데이터 없는 `ApiResponse`를 준다.
- 새 ErrorCode(모두 409): `SALE_EVENT_NOT_ENDABLE`(`SALE_004`, 진행 중인 할인 행사만 종료할 수 있습니다), `SALE_EVENT_NOT_DELETABLE`(`SALE_005`, 시작 전인 할인 행사만 삭제할 수 있습니다). 없는 할인 행사는 기존 `SALE_002`(404)다.
- `SaleEventTerminationService`(`end`, `delete`)를 추가했다. 종료는 영속 상태 엔티티의 `end()`를 불러 더티 체킹으로 저장한다.
- `SaleEvent`에 `isEndable(now)`, `isDeletable(now)`, `end()`를 추가했다.
