# WORK-094: 특가·번개 드롭을 상품마다 행사 하나로 등록

상태: 검증 대기 · 작성일: 2026-10-25 · 담당: 준혁

## 목표와 완료 기준

- 특가와 번개 드롭을 등록하면 고른 상품마다 행사가 하나씩 따로 만들어진다.
- 번개 드롭도 상품 여러 개를 한 번에 등록할 수 있다(상품마다 한정 수량이 따로 있다).
- 행사의 시각 수정·삭제·종료가 상품 하나에 대한 동작이 되게 한다.

## 근거와 범위

- 선행 작업: WORK-080 할인 행사 등록 API.
- 처음에는 특가 한 번에 고른 상품 여럿을 한 행사에 묶었고, 번개 드롭은 상품 하나만 등록했다. 한 행사에 상품이 여럿이면 한 상품의 시각을 고칠 때 같은 행사의 다른 상품 시각도 함께 바뀌어, 목록(상품 한 줄)과 수정 동작이 어긋난다. 그래서 등록 화면은 상품 여럿을 고르고 기간을 한 번 입력하는 그대로 두고, 서버가 상품 수만큼 행사를 만든다.
- 번개 드롭도 같은 방식이면 여러 상품을 한 번에 등록하는 것이 일관되고 관리자에게 편하다. 상품마다 한정 수량이 다르고 재고 검사도 상품마다 한다.
- 같은 요청에서 만든 행사들은 시작·종료 시각이 같다. 한 트랜잭션이라 한 상품이라도 거절되면 아무 행사도 만들어지지 않는다.
- 이미 묶여 등록된 행사는 그대로 둔다. 수정은 행사 단위로 열려 있어, 행사 항목이 여럿이면 항목 전부를 보여 준다.
- 변경하지 않은 것: 행사 테이블과 행사 상품 테이블 구조, 기존 행사 자료, 1인 구매 한도(번개 드롭은 1개 고정).

## 구현 결과

- `POST /api/admin/sale-events/special`: 요청은 그대로이고, 응답이 `saleEventId` 하나에서 상품 순서대로 만든 행사 번호 목록 `saleEventIds`로 바뀐다.
- `POST /api/admin/sale-events/flash-drop`: 요청이 상품 하나(`productId`, `discountRate`, `limitedQuantity`)에서 `startsAt`, `endsAt`, `items[{productId, discountRate, limitedQuantity}]`로 바뀌고, 응답은 특가와 같은 `saleEventIds`다. 상품은 한 번에 여러 개 넣을 수 있고 같은 상품을 두 번 넣을 수 없다.
- 한정 수량이 재고보다 많은 상품이 하나라도 있으면 400으로 거절하고 아무것도 저장하지 않는다.
