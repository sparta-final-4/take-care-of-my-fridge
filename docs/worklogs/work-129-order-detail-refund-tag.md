# WORK-129: 주문 상세 상품별 환불 태그·확정 수량, 환불 상세 환불 금액

상태: 구현 중 · 작성일: 2026-10-30 · 담당: 준혁

## 목표와 완료 기준

- 주문 상세의 상품 행마다 환불한 상품에는 "환불", 일부만 환불한 상품에는 "부분 환불" 태그가 보인다.
- 구매 확정된 주문은 수량과 금액을 확정 수량 기준으로 보인다.
- 확정 수량이 0인 상품도 행이 남고 흐리게 보인다.

## 근거와 범위

- 선행 작업: WORK-102 구매 확정 수량, 환불 신청 화면의 환불 표시.
- 프론트만 바꾼다. 응답의 `confirmedQuantity`(확정 전 null)와 환불 가능 상품 조회를 쓴다.
- 최종 결제 금액은 지금처럼 결제 금액에서 완료된 환불 금액을 뺀다. 확정 수량 기준 행 금액과의 합계 맞춤은 다음 작업에서 정한다.

## 구현 결과

- `OrderItemRow`: `refundState`를 받아 이름 오른쪽에 할인 태그와 환불 태그를 둔다. 확정 수량이 있으면 수량은 확정 수량, 금액은 단가 × 확정 수량으로 보인다. 확정 수량이 0이면 `rowEmpty`로 흐리게 보인다. 수량은 `??`로 읽어 0이 주문 수량으로 돌아가지 않는다.
- `OrderDetailSection`: 환불 가능 상품 조회 결과를 상품 번호로 짝지어 `getOrderItemRefundState`로 태그를 정한다. 조회를 못 읽으면 태그 없이 보인다.
- `getOrderItemRefundState`: 특가·번개 드롭도 환불한 수량이 있으면 `full`·`partial`을 돌려준다. 환불한 수량이 없을 때만 `saleBlocked`다.
- `RefundDetailSection`: "결제·환불 금액" 카드를 "환불 금액" 카드로 바꿨다. 상품·할인·결제·최종 결제 금액 줄을 빼고, 완료된 환불 합계와 진행 중인 환불 금액(있을 때)만 보인다.
- `docs/requirements/screens.md` 주문 상세 항목을 갱신했다.

## 검증

- `pnpm lint`, `pnpm format:check`, `pnpm typecheck` 통과.
- 화면 확인(375 / 768 / 1440px)은 백엔드를 띄운 뒤 진행한다.

## 후속 작업 고려사항

- 전부 환불된 주문의 상태 표시: 주문 상세와 주문 내역 목록 둘 다 "전액 환불"로 보이게 한다. 상세만 바꾸면 같은 주문이 화면마다 다르게 보여서 이 작업에서는 뺐다.
  - 주문 내역 목록 응답(`OrderSummaryResponse`)에 전액 환불 여부(예: `fullyRefunded`)를 더하고, 상세의 `isFullyRefunded`와 같은 기준(결제 완료 주문의 모든 상품을 완료된 환불이 주문 수량만큼 채움)으로 계산한다.
  - 목록의 환불 합계는 페이지의 주문 id들로 한 번에 조회해 주문마다 따로 읽지 않는다.
  - 오픈API 생성 파일을 갱신하고, 목록과 상세가 같은 값을 쓰게 한다.
