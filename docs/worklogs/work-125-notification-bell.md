# WORK-125: 헤더 종 아이콘 알림

상태: 검증 완료 · 작성일: 2026-10-30 · 담당: 준혁

## 목표와 완료 기준

- 모든 화면 헤더의 종 아이콘 배지에 안 읽은 알림 수가 보인다.
- 종을 열면 내 알림이 최신순으로 5개씩 보이고, "더 보기"로 이전 알림을 이어 볼 수 있다.
- 종을 열면 그때 받은 알림까지 읽음이 되고 배지가 줄어든다.
- 알림을 누르면 알림의 이동 경로(번개 드롭은 상품 상세)로 간다.

## 근거와 범위

- 선행 작업: WORK-123 내 알림 목록·안 읽은 수·전부 읽음 API, WORK-122 알림 요청 받아 저장, WORK-124 번개 드롭 알림 발행.
- 종 아이콘은 안 읽은 수 3이 고정된 임시 화면이었다. 생성 클라이언트에는 알림 API가 이미 있었다.
- 새 알림은 화면 이동과 탭 복귀 때 안 읽은 수를 다시 불러 반영한다. 실시간 전달은 따로 한다.

## 구현 결과

- 로그인하지 않았을 때
  - 종은 배지 없이 보이고, 누르면 로그인 화면으로 간다. 헤더 "마이페이지"와 같은 동작이다.
  - 알림 API는 부르지 않는다.
- 배지
  - `GET /api/notifications/unread-count`로 보여 준다.
  - 화면을 옮길 때 다시 불러온다. 탭으로 돌아올 때도 다시 불러오도록 이 조회만 켰다(앱 기본값은 꺼짐).
- 종을 열었을 때
  - 모든 화면 크기에서 종 아래 팝오버로 연다.
  - 목록(`GET /api/notifications`)을 받으면 그중 가장 최신 알림 ID로 전부 읽음(`PATCH /api/notifications/read-all`)을 부르고, 성공하면 안 읽은 수를 다시 불러온다. 받은 알림이 없으면 부르지 않는다.
  - 전부 읽음이 실패해도 알리지 않는다. 배지가 그대로 남고 다음에 열 때 다시 보낸다.
- 목록
  - 열기 전에 안 읽었던 알림은 앞에 점을 두고 문구를 굵게 보여 준다. 응답의 읽음 여부를 그대로 쓴다.
  - "더 보기"는 화면의 마지막 알림 ID를 `beforeId`로 보내 5개씩 이어 받는다. 더 받을 알림이 없으면 버튼이 사라진다.
  - 팝오버를 닫으면 목록을 버린다. 다시 열면 최신 5개부터 새로 받는다.
  - 로딩은 `Skeleton`, 빈 목록은 "알림이 없습니다", 첫 조회 실패는 "알림을 불러오지 못했습니다"와 "다시 시도"다. "더 보기" 실패는 서버 메시지를 알리고 버튼을 남긴다.
- 알림을 누르면 `linkUrl`로 이동하고 팝오버를 닫는다.
- 좁은 화면
  - 종 오른쪽에 메뉴 버튼이 있어 종 기준으로 정렬하면 목록이 화면 왼쪽으로 넘쳤다. 팝오버를 화면 안으로 밀어 넣는다.
  - 밀어 넣으면 화면 끝에 붙으므로, md 미만에서는 목록이 화면 폭을 채운다. md 이상은 너비 360px이다.
- 파일
  - `common/api/clients.ts`: 알림 API 인스턴스 추가.
  - `domains/notification/api.ts`, `queries.ts`: 목록·안 읽은 수·전부 읽음 함수와 쿼리.
  - `domains/notification/components/NotificationBell.tsx`: 배지와 팝오버.
  - `domains/notification/components/NotificationList.tsx`, `.module.scss`: 목록.
  - `styles/_variables.scss`: 목록 너비, 최대 높이, 점 칸 너비.
- API·DB 변경 없음.
- 문서: 화면 명세에 헤더 종 아이콘을 추가했다. 알림 설계의 알림 이동을 구현 완료로 바꾸고, 알림 설계와 API 명세의 배지 다시 불러오기 시점에 탭 복귀를 더했다.
