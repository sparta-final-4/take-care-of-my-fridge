# WORK-067: 주문하기

상태: 검증 완료 · 작성일: 2026-10-20 · 담당: 준혁

## 목표와 완료 기준

- 장바구니에서 고른 항목으로 결제 대기(`PENDING`) 주문을 만들고, 그 순간 재고를 뺀다.
- 여러 회원이 동시에 주문해도 재고보다 많이 팔리지 않는다.
- 같은 주문 요청이 여러 번 와도(따닥, 재전송) 주문은 하나만 생긴다.
- 새로 누른 주문은 같은 상품이어도 만들어진다. 한 회원이 여러 건 주문할 수 있다.

## 근거와 범위

- 선행 작업: WORK-039 장바구니 담기, WORK-041 장바구니 조회, WORK-066 장바구니 상품 연동.
- 주문하기 전체를 트랜잭션 하나로 처리한다. 하나라도 실패하면 앞서 뺀 재고까지 롤백한다.
- 외부 호출이 없어 퍼사드를 두지 않았다.
- 주문 서비스는 기능별로 나눈다. 이번에는 주문하기만 `OrderCreateService`에 둔다.
- 중복 요청은 `Idempotency-Key` 헤더로 구분한다.
- 장바구니 항목은 지우지 않는다. 결제 완료 때 지운다.
- 상품 도메인 코드에 재고 차감 메서드(`Product.decreaseStock`)와 잠금 조회(`ProductRepository.findAllByIdInForUpdate`)를 추가했다.

### 처리 순서

1. 회원의 장바구니 행을 잠근다.
2. 고른 장바구니 항목을 읽는다.
3. 같은 멱등 키로 만든 주문이 있으면 그 주문을 돌려준다.
4. 고른 장바구니 항목이 모두 내 것인지 확인한다.
5. 상품 행을 ID 순으로 잠그고 읽는다.
6. 판매 중지 상품이면 거절한다.
7. 재고를 확인하고 뺀다.
8. 주문과 주문 상품을 저장한다.

### 재고 차감

- 상품을 `SELECT … FOR UPDATE … ORDER BY id`로 잠그고 읽은 뒤 `Product.decreaseStock`으로 뺀다. 저장은 더티 체킹에 맡긴다.
- 한 문장에서 ID 순으로 잠그므로 주문끼리 잠금 순서가 엇갈리지 않는다.
- 재고 규칙과 화면 문구는 엔티티 한 곳에 둔다.
  - 수량이 0 이하면 400 `INVALID_INPUT_VALUE`. 재고가 늘어나는 것을 막는다.
  - 재고가 모자라면 409 `INSUFFICIENT_STOCK`. 문구에 상품명을 담는다("재고 부족 · 대파", 재고 0이면 "품절 · 대파").

### 중복 요청 (멱등 키)

- 주문에 멱등 키를 저장한다. `orders.idempotency_key`에 `(member_id, idempotency_key)` 유니크를 건다.
- 장바구니 행 잠금(`findByMemberIdForUpdate`)으로 같은 회원의 주문하기를 하나씩 순서대로 처리한다. 그래서 같은 키로 동시에 온 요청도 모두 같은 주문을 받는다.
  - 이 잠금은 트랜잭션의 첫 조회여야 한다.
  - 유니크 제약은 잠금이 빠졌을 때 주문이 두 번 생기는 것을 막는 마지막 장치다.
- 같은 키 확인은 장바구니 항목 검증보다 먼저 한다. 처음 주문 뒤 장바구니 항목이 지워져도(결제 완료, 사용자 삭제) 재전송에는 처음 주문을 돌려준다.
- 같은 키인데 고른 상품·수량이 처음 주문과 다르면 409 `ORDER_IDEMPOTENCY_KEY_REUSED`로 거절한다.
  - 처음 주문의 주문 상품과 비교하므로 따로 저장하는 값은 없다.
  - 장바구니 항목이 일부 사라져 비교할 수 없으면 처음 주문을 그대로 돌려준다.

### 주문번호

- `OrderNumberGenerator`가 밀리초 시각 17자리와 같은 밀리초 안의 순번 3자리로 20자리 숫자를 만든다. DB를 조회하지 않는다.
- 서버 1대 기준이다.
- 시각은 서버 시간대와 관계없이 `Asia/Seoul`로 찍는다.
- 시계가 뒤로 가면 마지막 시각에 머문다. 그동안 순번이 999를 넘으면 다음 밀리초로 넘겨 20자리를 지킨다.

### 주문 상품

- 주문 당시 상품명·이미지·정가·단가를 복사한다.
- `order_items.product_image_url`(NULL 허용) 컬럼을 추가했다.

### 오류

| 상황 | HTTP | 코드 | 메시지 |
|---|---|---|---|
| `Idempotency-Key` 없음, 64자 초과 | 400 | `INVALID_INPUT_VALUE` | Idempotency-Key 헤더가 필요합니다. (64자 이하) |
| `cartItemIds` 비었거나 50개 초과 | 400 | `INVALID_INPUT_VALUE` | |
| 내 장바구니 항목이 아님 | 404 | `CART_ITEM_NOT_FOUND` | |
| 장바구니 항목의 상품이 없음 | 404 | `PRODUCT_NOT_FOUND` | |
| 판매 중지 상품 | 409 | `PRODUCT_NOT_ON_SALE` | |
| 재고 부족, 품절 | 409 | `INSUFFICIENT_STOCK` | 재고 부족 · 상품명 / 품절 · 상품명 |
| 같은 키, 다른 상품·수량 (신규) | 409 | `ORDER_IDEMPOTENCY_KEY_REUSED` (`ORDER_006`) | 다른 주문 요청에 이미 쓴 Idempotency-Key입니다. |
| 주문번호·멱등 키 유니크 위반 (신규, 드묾) | 409 | `ORDER_NUMBER_CONFLICT` (`ORDER_005`) | 잠시 후 다시 주문해 주세요. |

`ORDER_NUMBER_CONFLICT`는 제약 이름(`uk_orders_order_number`, `uk_orders_member_id_idempotency_key`)일 때만 바꾼다. 그 밖의 제약 위반은 원인을 가리지 않도록 그대로 던진다. 원인 예외는 모두 경고 로그로 남긴다.

<summary><code>OrderCreateServiceTransactionTest</code></summary>

- 정상 주문

- 거절과 롤백
  - 두 번째 상품 재고가 모자라면 첫 상품 재고까지 롤백된다.
  - 재고 0이면 품절로 거절한다.

- 멱등 키
  - 같은 키로 다시 보내면 처음 주문을 돌려주고 재고는 한 번만 빠진다.
  - 주문 뒤 장바구니 항목을 지우고 같은 키로 다시 보내도 처음 주문을 돌려준다.
  - 같은 키로 다른 상품을 보내면 거절하고, 처음 주문과 재고는 그대로다.
  - 키가 다르면 같은 상품도 새 주문이 된다.
  - 다른 회원은 같은 키를 써도 각자 주문된다.
  - 키가 없거나 64자를 넘으면 거절한다.
- 동시성
  - 재고 5개에 20명이 동시에 주문하면 정확히 5건만 성공하고 재고는 0이다.
  - 같은 키로 동시에 5번 주문하면 주문은 1건이고 모두 같은 주문을 받는다.
  - 담은 순서가 엇갈린 주문 20건을 동시에 보내면 데드락 없이 모두 성공하고 재고가 맞는다.

## 다음 작업

주문 확인 화면(02) 프론트를 만든다. 장바구니 화면의 주문하기 버튼을 이 API에 연결하고, 응답으로 주문 확인 화면을 그린다.

<details>
<summary>화면에서 지킬 것</summary>

- 고른 장바구니 항목 번호를 `cartItemIds`로 보낸다.
- `Idempotency-Key`는 주문 시도 하나에 하나를 만든다.
  - 같은 시도의 재전송·따닥 클릭에는 같은 값을 쓴다.
  - 응답을 받은 뒤 다음 시도에는 새 값을 쓴다.
  - 버튼은 누른 직후 비활성화한다.
- 201과 200은 같은 주문 응답이므로 둘 다 주문 확인 화면으로 넘어간다.
- 409는 메시지를 알림으로 띄운다.
  - 재고 부족·품절: "재고 부족 · 상품명" 형식
  - `ORDER_006`: 화면 버그 신호
  - `ORDER_005`: 다시 주문 안내
- 상품 이미지(`productImageUrl`)가 null이면 빈 이미지를 보여 준다.
- 새로고침·재진입은 주문 상세 조회 API가 생긴 뒤 붙인다.

</details>

그다음은 주문 상세 조회, 주문 취소(결제하기 전만)와 재고 되돌리기, 5분 만료 순서다.
