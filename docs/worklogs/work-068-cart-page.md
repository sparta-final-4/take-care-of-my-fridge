# WORK-068: 장바구니 화면

상태: 검증 완료 · 작성일: 2026-10-20 · 담당: 준혁

## 목표와 완료 기준

- 로그인 회원이 `/cart`에서 담은 상품을 보고, 수량을 바꾸고, 지우고, 체크한 상품의 결제 예정 금액을 확인한다.
- 헤더 "장바구니" 메뉴로 이동하고, 배지가 장바구니 줄 수를 보여 준다.

## 근거와 범위

- 선행 작업: WORK-041 장바구니 조회, WORK-043 수량 변경, WORK-055 삭제, WORK-066 상품 연동.
- 화면 상세는 `docs/requirements/screens.md`의 "8 장바구니"에 적었다.
- 주문 API가 아직 없어 "주문하기"는 비활성으로 둔다.
- 상품 목록 화면이 아직 없어 화면에서 담는 동작은 이번 범위에서 뺐다.

## 구현 결과

- 백엔드: 조회 줄 응답(`CartItemResponse`)에 `imageUrl`을 추가했다. 상품 이미지가 없으면 null이다.
- 프론트
  - `domains/cart/api.ts`: 조회·수량 변경·삭제. 삭제는 `cartItemIds=1,2` 형식으로 보낸다(axios 기본 배열 직렬화 `cartItemIds[]=1`은 백엔드가 받지 못한다).
  - `domains/cart/queries.ts`: `cartQueries.items()`. 헤더 배지와 장바구니 화면이 같은 쿼리를 쓴다.
  - `CartSection`: 체크 상태, 수량 변경·삭제 요청. 체크는 해제한 줄만 기록해 새 줄과 품절이 풀린 줄이 처음부터 체크된다. 요청 중인 줄은 버튼을 막는다. 실패 알림은 전역 `MutationCache`가 서버 메시지로 띄우고, 수량은 다시 불러온 서버 값을 따른다.
  - `CartItemRow`: 이미지, 할인 표시(정가 취소선, 특가·번개 드롭), −/+, X. 품절 줄은 흐리게 표시하고 체크·수량 변경을 막는다. 번개 드롭은 1에서 "+"를 막는다. 모바일에서 버튼 터치 영역은 44px이다.
  - `CartSummary`: 체크한 줄의 상품 금액(정가 합), 할인 금액, 합계.
  - `pages/order/CartPage`, `ROUTES.cart`(`RequireAuth` 아래), 헤더 연결과 배지.
- mutation은 프론트 규칙대로 `queries.ts`에 훅을 두지 않고 컴포넌트의 `useMutation`으로 썼다. 기존 냉장고·후기 도메인은 `queries.ts`에 mutation 훅을 둔다.
- 줄의 X는 확인 없이 지운다. 줄 하나는 다시 담으면 되는 동작이라 와이어프레임대로 두었다. 여러 줄을 지우는 선택 삭제·전체 삭제만 확인 창을 띄운다.

## 연결과 남은 작업

- 여러 줄을 한 번에 지우는 요청(`cartItemIds=1,2`)은 화면에서 확인하지 않았다. 확인할 때 선택한 줄이 하나였다.
- "주문하기"는 주문 API가 붙으면 체크한 줄 번호로 주문을 만들도록 연결한다.
- 할인가·할인 구분·번개 드롭 남은 수량은 할인 행사 조회가 생기면 백엔드 응답에 채워지고, 화면은 이미 그 필드를 표시한다.
- 화면에서 담는 동작은 상품 목록 화면에서 붙인다.
