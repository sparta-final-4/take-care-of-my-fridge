# WORK-081: 할인 행사 열기·닫기와 진행 중 할인 조회

상태: 검증 완료 · 작성일: 2026-10-23 · 담당: 준혁

## 목표와 완료 기준

- 등록된 행사가 시작·종료 시각에 맞춰 시작하고 끝난다.
- 장바구니·주문이 상품 번호 여러 개의 진행 중 할인(구분, 할인가, 할인율, 종료 시각, 남은 수량)을 한 번에 조회한다.

## 근거와 범위

- 선행 작업: WORK-080 할인 행사 등록 API.
- 진행 중인지는 행사 상태가 아니라 시간으로 판단한다. `시작 ≤ 지금 < 종료`이고 종료로 닫지 않은 행사(예정·진행 중 상태)가 진행 중이다. 상태 정리가 늦어도 시작·종료가 그 시각에 반영되고, 정확한 시각 예약을 관리할 필요가 없다.
- 스케줄러는 그래서 상태 정리용이며 1분에 한 번 돈다. 처음에는 상태 기준이라 10초로 잡았다.
- 같은 기준을 등록 때의 "이미 행사가 있는 상품" 검사와 등록할 상품 목록에도 쓴다.
- 번개 드롭이 다 팔려도 행사는 닫지 않고 남은 수량 0으로 둔다. 취소로 수량이 돌아오면 다시 팔 수 있다.
- 진행 중 할인 조회는 화면에 표시하는 경로가 아니라 서버가 금액을 정하는 경로다. 상품 목록·상세에 할인을 보여 주는 퍼사드는 이 작업에 넣지 않았다.
- 알림(번개 드롭 시작 전·시작)은 알림 도메인에 받는 쪽이 생긴 뒤에 붙인다.

## 구현 결과

### 구조

- `SaleEventStatusService.openAndCloseDue(now)`: 종료 시각이 지난 예정·진행 중 행사를 종료로, 시작 시각이 된 예정 행사를 진행 중으로 일괄 UPDATE한다. 닫기를 먼저 해서, 열기 전에 이미 끝난 예정 행사가 진행 중을 거치지 않고 바로 종료된다. 같은 시각에 두 번 실행해도 결과가 같다.
- `SaleEventScheduler`: `@Scheduled(fixedDelay = 60_000)`로 실행끼리 겹치지 않는다. 실패하면 기록하고 다음 실행에서 다시 처리한다.
- `SaleEventReader.findActiveSales(productIds)`: 진행 중 할인을 `Map<상품 번호, ActiveSale>`로 돌려준다. 할인이 없는 상품은 맵에 없다.
- `ActiveSale`: 상품 번호, 행사 상품 번호, 구분, 할인가, 할인율, 종료 시각, 남은 수량, 한정 수량(특가는 둘 다 null).
- 진행 중 할인 조회는 엔티티가 아니라 값(`ActiveSale`)으로 읽는다. 엔티티로 읽으면 영속성 컨텍스트에 남아, 뒤이어 남은 수량을 잠그고 읽을 때 최신 값 대신 이 시점의 값이 돌아온다. 번개 드롭 3개를 10명이 동시에 주문하는 테스트가 처음에 전원 성공해 이 문제를 찾았다.
- `SaleEventItemRepository`: `findActiveByProductIds`, `findProductIdsInOpenSaleEvent`, 남은 수량 행 잠금 조회 `findAllByIdInForUpdate`.
