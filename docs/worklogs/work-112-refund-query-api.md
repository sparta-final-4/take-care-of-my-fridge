# WORK-112: 환불 가능 수량·환불 내역·환불 요약 조회 API

상태: 완료 · 작성일: 2026-10-26 · 담당: 결제·환불

## 목표와 완료 기준

- 환불 신청 화면이 주문 상품마다 남은 환불 가능 수량을 보여 줄 수 있다.
- 환불 상세 화면이 주문의 환불 내역을 최신순으로 보여 줄 수 있다.
- 주문 목록·상세가 주문마다 환불 상태(진행 중·부분·전체)를 보여 줄 수 있다.

## 근거와 범위

- PR: #228(환불 가능 수량, 10/23), #238(주문별 환불 내역, 10/24), #285(주문별 환불 요약, 10/26).
- 환불 신청과 환불 가능 수량 조회가 같은 규칙을 쓰도록 주문 상태 규칙(`RefundableOrderPolicy`)과 누적 상태(`RefundStatus.COUNTED`)를 공유한다.
- 환불 요약은 결제 테이블을 건드리지 않고 환불 기록으로만 계산한다. 결과를 저장하지 않는다.

## 구현 결과

- `GET /api/refunds/refundable-items?orderId=`: 주문 상품 순서대로 주문·환불·남은 수량과 환불 가능 여부. 특가·번개 드롭은 `refundable=false`, 남은 수량 0. 요청·완료 수량만 빼고 실패한 수량은 다시 환불할 수 있게 계산한다.
- `GET /api/refunds?orderId=`: 환불을 상태와 관계없이 최신순으로, 환불마다 자기 상품만 묶어 돌려준다. 구매 확정된 주문의 지난 환불도 보여 준다. PG 오류 원문(`fail_reason`)은 응답에 넣지 않는다.
- `GET /api/refunds/summaries?orderIds=`: 주문마다 `NONE`·`IN_PROGRESS`·`PARTIAL`·`FULL`과 완료된 환불 금액.
  - 판정 순서: 요청 상태 환불이 있으면 `IN_PROGRESS` → 특가·번개 드롭을 뺀 환불 가능한 상품을 모두 환불했으면 `FULL` → 완료된 환불이 있으면 `PARTIAL` → `NONE`.
  - 주문 수와 관계없이 주문 상품, 상품별 완료 수량, 주문별 상태별 금액을 한 번씩만 읽는다.
  - 회원 본인 주문만 요청한 순서대로 돌려준다. 빈 값과 중복을 뺀 고유 주문 1~50건이 아니면 `REFUND_013`.
- 리뷰 반영(#285): 진행 중 판정을 요청 상태 금액 대신 요청 상태 기록 유무로 바꿨다. 빈 값 요소(`orderIds=10,,11`)와 중복 요청 테스트를 더했다.
