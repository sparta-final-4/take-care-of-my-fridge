# WORK-098: 할인 행사 종료·삭제 버튼

상태: 검증 대기 · 작성일: 2026-10-26 · 담당: 준혁

## 목표와 완료 기준

- 관리자가 할인 행사 목록의 작업 열에서 진행 중인 할인 행사를 종료하고, 예정 할인 행사를 삭제한다.
- 누르면 확인 창이 열리고, 확인한 뒤에만 요청한다.
- 끝나면 목록이 새로 고쳐지고, 실패하면 서버 메시지를 보여 준다.

## 근거와 범위

- 선행 작업: WORK-097 할인 행사 종료·삭제 API, WORK-093 할인 행사 수정 화면(작업 열의 비활성 버튼).
- 종료는 진행 중 행에만, 삭제는 예정 행에만 버튼이 있고 종료된 행에는 없다.
- 확인 창 문구에 상품 이름과 할인 종류(특가·번개 드롭)를 넣어, 같은 상품의 다른 할인 행사와 헷갈리지 않게 한다.
- 성공하든 실패하든 목록을 다시 읽는다. 실패는 대개 그 사이 상태가 바뀐 경우라 목록을 새로 보여 주는 편이 맞다.
- 종료해도 등록한 종료 시각은 그대로여서 종료된 행의 종료 열에는 그 시각이 보인다.
- 변경하지 않은 것: 수정 화면, 사용자 화면.

## 구현 결과

- 작업 열의 비활성이던 종료·삭제 버튼을 켰다. 삭제 버튼 클릭이 행 클릭(수정 칸 열기)으로 번지지 않게 막았다.
- 확인 창 제목과 버튼은 "할인 행사 종료", "할인 행사 삭제"다. 종료 본문은 "진행 중인 {상품 이름} {종류} 할인 행사를 종료합니다. 종료한 할인 행사는 다시 진행할 수 없습니다.", 삭제 본문은 "예정된 {상품 이름} {종류} 할인 행사를 삭제합니다. 삭제한 할인 행사는 되돌릴 수 없습니다."다.
- 성공하면 "{종류} 할인 행사를 종료했습니다." 또는 "{종류} 할인 행사를 삭제했습니다." 토스트를 띄운다. 실패하면(409 등) 서버 메시지를 오류 토스트로 보여 준다.
- `domains/sale/api.ts`에 `endSaleEvent`, `deleteSaleEvent`를 추가했다.
- 장바구니 할인 카운트다운이 0이 되어도 장바구니를 다시 불러오지 않고 "할인 종료"로만 바뀐다. 가격은 새로고침하면 바뀐다.
- `docs/requirements/screens.md`의 할인 행사 화면 설명에 종료·삭제를 더하고, 누를 수 없다던 문장을 지웠다.
