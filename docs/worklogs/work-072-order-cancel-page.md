# WORK-072: 주문 확인 화면의 취소하기와 나가기 확인

상태: 검증 완료 · 작성일: 2026-10-21 · 담당: 준혁

## 목표와 완료 기준

- 주문 확인 화면의 "취소하기"로 주문을 취소하고 장바구니로 돌아간다.
- 주문 확인 화면에서 앱 안으로 이동(뒤로 가기, 메뉴)하면 "나가면 주문이 취소됩니다" 확인 창을 띄우고, 나가기를 고르면 취소한 뒤 이동한다.
- 새로고침·탭 닫기에는 묻지 않는다. 그렇게 남은 결제 대기 주문은 주문 만료가 5분 뒤 취소한다.

## 근거와 범위

- 선행 작업: WORK-070 주문 확인 화면, WORK-071 주문 취소 API. WORK-071이 머지된 뒤 머지한다.
- 화면 상세는 `docs/requirements/screens.md`의 "9 주문 확인"을 갱신했다.

## 구현 결과

- `useCancelOnLeave` (신규 훅): 이동 붙잡기와 취소를 한곳에서 다룬다.
  - React Router `useBlocker`로 경로가 바뀌는 앱 안 이동만 붙잡는다. `useBlocker`는 브라우저 새로고침·탭 닫기에는 동작하지 않아 묻지 않는다는 정책과 맞는다.
  - 취소에 성공하면 그 뒤의 이동은 다시 붙잡지 않는다. 취소하기로 연 경우는 장바구니로, 이동을 붙잡은 경우는 가려던 곳으로 간다.
  - 취소에 실패하면 창을 닫고 화면에 남는다. 실패 알림은 전역 mutation 알림이 띄운다.
- 확인 창은 취소하기와 나가기가 같은 `Modal`을 쓰고 제목·버튼 문구만 다르다. 위험 동작 확인 패턴인 `Popconfirm` 대신, 같은 결과(주문 취소)를 경로마다 같은 모양으로 묻도록 했다.
- 결제창에서 결제를 마치고 떠나는 이동은 붙잡지 않는다(`allowLeave`). 붙잡으면 나가기 확인에서 방금 결제한 주문이 취소된다.
- 붙잡기는 결제 대기 주문을 보여 주는 동안(`isSuccess`)만 켠다. 다시 조회하다 409를 받으면 `data`에 이전 값이 남아 있어, `data`로 판단하면 취소된 주문 안내의 "장바구니로 가기"까지 막혔다.
