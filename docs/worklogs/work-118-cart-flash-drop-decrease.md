# WORK-118: 번개 드롭으로 바뀐 장바구니 항목의 수량 내리기

상태: 검증 완료 · 작성일: 2026-10-30 · 담당: 준혁

## 목표와 완료 기준

- 일반 상품을 2개 이상 담아 둔 뒤 그 상품이 번개 드롭이 되어도, 장바구니에서 수량을 내릴 수 있다.
- 수량을 올리는 요청은 지금처럼 구매 한도에서 거절한다.

## 근거와 범위

- 선행 작업: WORK-082 장바구니 할인 반영.
- 수량 변경은 요청 수량이 1을 넘으면 올리는지 내리는지 보지 않고 `CART_003`으로 거절했다. 3개가 담긴 항목에서 "−"를 누르면 2로 바꾸는 요청이 거절되어, 삭제 말고는 수량을 줄일 방법이 없었다.
- 같은 메서드의 재고 확인은 이미 "담아 둔 뒤 재고가 줄었어도 내리는 것은 막지 않는다"로 처리한다. 구매 한도도 이 기준에 맞춘다.
- 장바구니에 1개를 넘게 남아 있어도 주문하기가 구매 한도를 다시 확인하므로, 넘는 수량으로 주문되지 않는다.

## 구현 결과

- 백엔드 `CartService.changeQuantity`: 번개 드롭 구매 한도는 요청 수량이 지금 담긴 수량보다 클 때만 확인한다. 재고 확인과 같은 주석 하나로 묶었다.
- 프론트 `CartItemRow`: 번개 드롭 항목의 "−"는 한 번에 1로 요청한다. 1개를 넘게 담긴 번개 드롭은 어차피 주문할 수 없어, 여러 번 누르지 않게 했다.
- API·DB 변경 없음.
- 문서: 장바구니 도메인 문서, API 명세, 테스트 전략(CART-02)의 번개 드롭 한도 설명에 "담은 뒤 번개 드롭이 되었으면 내리는 것은 허용"을 더했다. 화면 명세의 장바구니 수량에 "−"가 한 번에 1로 내리는 동작을 더했다.
