# WORK-084: 할인 행사 등록 화면

상태: 검증 대기 · 작성일: 2026-10-23 · 담당: 준혁

## 목표와 완료 기준

- 관리자가 화면에서 특가(상품 여러 개)와 번개 드롭(상품 하나, 한정 수량)을 등록한다.
- 상품 표에서 상품을 고르고 그 행에서 바로 할인율을 입력한다.

## 근거와 범위

- 선행 작업: WORK-080 할인 행사 등록 API. 생성 클라이언트는 oag PR에서 만든 것을 쓴다.
- 경로는 `/admin/sale-events/new`, 진입은 관리자 헤더(넓은 화면 메뉴와 좁은 화면 메뉴)의 "할인 행사"다.
- 화면 구성은 "특가"·"번개 드롭"·"행사 목록" 탭이다. 행사 목록 탭은 자리만 있고 "준비 중" 안내를 보여 준다. 특가·번개 드롭 탭을 바꾸면 고른 상품을 비운다.
- 상품 표는 서버가 걸러 준 "등록할 수 있는 상품 목록"만 보여 준다. 행사 중·품절·판매 중지 상품은 아예 나오지 않는다.
- 처음에는 위 표에서 고르고 아래 "고른 상품" 표에서 값을 넣는 구조였으나 위아래를 오가야 해서, 고른 행 안에서 바로 입력하는 구조로 바꿨다. 아래에 붙어 따라오던 등록 바도 표와 겹쳐 보여, 시작·종료 시각 옆으로 옮겼다.
- 시작·종료 시각은 범위 선택기가 좁은 화면에서 달력이 화면 밖으로 나가 따로 받는다.

## 구현 결과

- `src/domains/sale`: `api.ts`(등록 두 개, 등록할 상품 목록), `queries.ts`, `format.ts`(할인가 계산, 할인율 범위), `components/SaleEventCreateSection`, `components/SaleProductPicker`.
- `src/pages/admin/AdminSaleEventCreatePage`, 라우트 `ROUTES.adminSaleEventNew`, 헤더 메뉴 두 곳, `clients.ts`에 `adminSaleEventApi`.
- 상품 표: 이름 검색, 종류 필터(전체·재료·밀키트), 10개 페이지. 열은 상품, 종류, 재고, 정가, 할인율, 할인가(번개 드롭은 한정 수량과 "/ 재고 N개"). 체크하면 그 행의 입력칸이 켜지고 할인가가 바로 계산된다(정가에서 할인율만큼 빼고 원 아래는 버림, 서버와 같은 계산). 여러 페이지에 걸쳐 고를 수 있고 "고른 상품 N개"를 누르면 목록과 제외 버튼이 나온다.
- 특가에는 "일괄 할인율" 입력칸과 "일괄 적용"이 있어 고른 상품 모두의 할인율을 한 값으로 맞춘다. 번개 드롭은 상품이 하나라 숨긴다.
- 시작·종료 시각은 고르는 즉시 입력되고(확인 버튼 없음) 지난 날짜와 시간은 비활성이다. 종료는 시작 이전이 비활성이다.
- 모든 입력(상품, 할인율, 번개 드롭이면 한정 수량)이 있어야 "등록"이 켜진다. 성공하면 입력을 비우고 상품 목록을 다시 읽는다. 실패는 서버 메시지 알림이다.
- `docs/requirements/screens.md`: 할인 행사 등록 화면 추가.
