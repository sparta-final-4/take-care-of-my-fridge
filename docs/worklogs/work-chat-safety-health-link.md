# 상담 안전 장치 ③ 건강 안내·답에 섞인 링크 지우기

상태: 검증 대기 · 작성일: 2026-11-07 · 담당: 상담

## 목표와 완료 기준
- 사용자 문제:
  - 질환·알레르기·임신·약 질문에도 의료 판단을 하지 않는다는 안내가 프롬프트 규칙뿐이라, 안내가 나온다는 보장이 없었다.
  - AI 답에 링크가 섞여도 걸러지지 않았다.
- 완료 조건:
  - 보낸 말에 건강 관련 말이 있으면 서버가 답 끝에 안내를 붙인다(막지 않고 하루 횟수도 센다).
  - AI 답의 링크는 조각 경계에서 쪼개져도 화면과 저장 모두에서 지운다. 숫자·단위는 그대로 둔다.

## 근거와 범위
- 근거: 상담 안전 장치 조사와 사용자 결정. 4개 PR 중 PR③(`feat/chat-safety-health-link`, `feat/chat-safety-off-topic` 위)
- 사용자 결정:
  - 다이어트는 감지에서 뺀다.
  - 안내는 답 끝에 빈 줄 하나를 두고 붙인다. 추천 답은 카드 바로 위다.
  - 서버가 정한 답(후보 없음·밀키트만)에도 붙이고, 안전 장치 안내에는 붙이지 않는다.
  - "신장"은 키(신장 170cm)로도 쓰여서 신장질환·신장병·신장 기능처럼 길게 쓴다.
  - 건강 감지는 사용자가 보낸 말만 본다.
  - 링크만 지우고 "(링크 생략)"은 넣지 않는다.
- 변경 영역: `domain/chat`(config, facade, service), `application.yml`
- API 모양·DB·에러 코드·프론트 변경 없음

## AI 활용과 개발자 판단
- AI에 맡긴 작업: 계획, 구현, 테스트
- 구현하며 정한 것:
  - **추천 답의 기존 안내(notice) 방식을 쓰지 않았다.** notice가 있으면 서버가 notice를 소개로 먼저 보내고 AI 소개 글을 버린다(`dropIntro`). 건강 질문마다 AI 소개가 사라지므로, 답이 끝난 뒤 `message`를 하나 더 보내 소개 글 끝(카드 바로 위)에 붙였다.
  - **안내는 "첫 조각"으로 치지 않는다.** 답 조각이 없으면 붙이지 않고, 지금처럼 `CHAT_010`을 보내고 횟수를 돌려준다.
  - **링크 필터는 AI가 만든 답에만 건다.** 처음에는 서버가 정한 글에도 걸었다. 그랬더니 끝 "?"·"." 같은 글자를 다음 조각까지 잡아 두면서 이벤트가 하나 더 나뉘었다(기존 테스트 13개 실패). 서버 글에는 링크가 없으므로 AI 답에만 건다.
  - **잡아 두는 글자를 좁혔다.** 처음에는 끝의 링크 글자 묶음과 끝 공백을 모두 잡아 두어, 숫자·마침표·공백이 작은 조각으로 따로 나갔다. 영문이 든 묶음만 잡아 두도록 바꿨다.
    - 끝 공백은 잡아 두지 않는다. 대신 앞 조각이 공백으로 끝나고 다음 조각이 링크로 시작하면, 지운 뒤 앞 공백을 빼서 공백이 겹치지 않게 했다.
    - 숫자로만 된 도메인("1688.com")이 조각 경계에서 쪼개지면 놓칠 수 있다.

## 후속: 알레르기 재료 빼기
- 문제: "땅콩 알레르기 있어, 뭐 먹지"에 건강 안내는 붙었지만 알레르기 재료를 빼는 규칙이 없었다. 의도 프롬프트는 "빼달라고 하거나 못 먹는다고 말한 재료"만 뺄 재료로 본다.
  - 이때 나온 콩비지찌개에는 땅콩이 없다(dev DB 읽기 전용 확인: 콩(흰콩)·돼지고기·배추 등). 땅콩 ↔ 콩처럼 이름만 비슷한 경우다.
- 사용자 결정: 재료 도메인에 조회 메서드 추가 허용, 넓히지 않을 이름·묶음 구성 계획대로, 콩 요리 이름으로 정렬을 뒤로 보내지 않음, 안내는 카드 바로 위, 상담 메시지를 다시 볼 때 filtered는 뺌, 안내 문장 지정
- 변경
  - 재료 도메인: `IngredientRepository.findByNameContaining`·`findByNameStartingWith`, `IngredientService.findContainingNames`
    - 두 글자 이상은 이름에 들어 있는 재료, 한 글자는 그 글자로 시작하는 재료다. 직접 입력·밀키트는 뺀다.
    - "버섯 → 표고버섯" 넓히기(`findSameKind`)는 끝나는 이름만 찾아서 땅콩버터·새우젓을 못 찾으므로 따로 뒀다.
  - `app.chat.allergy-words`(표시 말·조사·넓히지 않을 이름), `app.chat.allergy-groups`(실제 재료 사전 이름 기준)
    - 계란은 사전에서 달걀로 합쳐져 있다. 랍스터·요구르트는 사전에 없다.
  - `AllergyWordChecker`(순수, 표시 말 앞 낱말 후보), `AllergyExclusionFinder`(이번 말 + 이 상담의 걸러지지 않은 사용자 말 → 묶음·사전 확인 → 넓히기)
  - `ChatIntentFacade.resolve`: 추천이면(칩 포함) 알레르기 재료를 `RecipeQuery.withExcludedIngredients`로 뺄 재료에 더하고 고른 재료에서도 뺀다. `ChatIntentResolution.allergens`에 이름을 둔다.
  - 기존 뺄 재료 처리(ES `mustNot`, 정렬 단계 재료 거르기)가 콕 집은 요리도 빼므로 그대로 쓴다.
  - `ChatRecommendationFacade`: 밀키트는 연결 레시피가 뺄 재료를 쓰거나, 연결이 없으면 상품 이름에 뺄 재료 이름이 있으면 뺀다(땅콩호박 등은 끊어 보고).
  - `ChatStreamService.allergyNotice`: 추천 답 끝(카드 바로 위)에 알레르기 안내를 붙인다. 건강 안내가 있으면 한 메시지로 이어 붙인다.
  - `app.chat.taste-words.negation-after`에 "못먹"을 더했다("매운 거 못 먹어" → 피할 맛 SPICY).
- 계획과 달라진 점: 한 글자 재료를 처음에는 "이름이 같은 재료만"으로 했다. 그러면 잣가루·게살이 빠지지 않아 "그 글자로 시작하는 재료"로 바꿨다. 바게트·스파게티·멍게살은 "게"로 시작하지 않아 걸리지 않는다.

## 후속: 한 글자 알레르기 넓히기에서 다른 재료 빼기
- dev 재료 사전(읽기 전용, 2026-11-07)에는 한 글자 재료가 24개 있다(갓·게·굴·귤·김·꿀·딜·떡·마·무·묵·물·밤·밥·배·쌀·쑥·양·잣·조·콩·톳·팥·햄). 이 중 18개는 그 글자로 시작하는 다른 재료가 있다.
  - 모두 같은 계열: 게(게살·게맛살), 귤, 쌀(쌀가루·쌀국수 등 9개), 잣, 콩(콩가루·콩나물·콩비지 등), 톳, 팥
  - 굴: 굴소스(같은 계열). 굴비는 지금 사전에 없지만 사용자 예시라 넣었다.
  - 다른 재료가 섞인 것
    - 김 → 김장김치·김치·김칫국물·김칫잎
    - 떡 → 떡볶이양념파우더
    - 마 → 마늘 7종·마른오징어·마스카포네치즈·마요네즈·마카다미아
    - 무 → 무가당 4종·무염버터·무지개고추·무화과
    - 묵 → 묵은지
    - 물 → 5개 전부
    - 밤 → 밤고구마
    - 배 → 배추·배추김치
    - 쑥 → 쑥갓
    - 양 → 양고기 말고 13개
    - 조 → 8개 전부
- 구조를 바꿨다. 넓히지 않을 이름을 전체 공통 목록에서 **재료마다 목록**(`not-same-kind: - word, names`)으로 옮겼다.
  - 전체 공통으로 "마늘"·"배추"·"김치"를 넣으면 "마늘 알레르기"의 마늘가루와 "배추 알레르기"의 배추김치까지 안 빠지기 때문이다.
  - 이름은 이제 "들어 있음"이 아니라 이름이 똑같은지로 본다.
- 바꾸며 찾은 것: 갑각류 묶음의 "게살"(두 글자, 이름에 들어 있음으로 넓힘)이 "멍게살"을 걸었다. 전에는 공통 목록이 막았던 것이라 `게살 → 멍게살` 항목을 더했다.
- 밀키트 상품 이름은 모든 재료의 넓히지 않을 이름을 끊어 두고 본다. 다만 뺄 재료 자신인 이름은 끊지 않는다("마늘 알레르기"면 "마늘빵 밀키트"의 마늘을 끊지 않음).

  - 밀가루 → 메밀가루·호밀가루
  - 김 → 김장김치(김 묶음 목록에는 넣었다)
- 테스트

## 후속: 다시 추천에서 맛이 부딪히면 이번 말을 따르기
- 문제
  - 같은 맛이 원하는 맛과 피할 맛에 둘 다 남을 수 있었다("매운 거 말고" → "좀 더 매운 걸로").
  - 반대 맛이 원하는 맛에 같이 남을 수 있었다("짭짤한 거" → "담백한 거로"에서 SALTY가 남고 MILD가 더해짐). 다시 추천은 AI가 낸 최종값을 그대로 믿었다.
- 규칙: 이번 말에 나온 맛이 이긴다(맛 전체).
  - 원하는 맛은 직전 맛에 쌓는다.
  - 이번에 원한 맛은 피할 맛에서 빼고, 반대 맛(`app.chat.taste-opposites`: MILD ↔ SPICY, MILD ↔ SALTY)은 원하는 맛에서 지운다.
  - 이번에 피한 맛은 원하는 맛에서 뺀다.
- 변경
  - `TasteWordChecker.stances`: 맛 전체(매운·단·짠·감칠·순한)의 원함·피함을 같은 부정어 규칙으로 본다. 기존 `check`(매운맛·단맛만 AI 결과를 고침)는 그대로 둔다.
  - `ChatIntentFacade.mergeRefine`: 원하는 맛을 직전 + 이번으로 쌓는다(맛을 지우라는 말이면 이번 맛만). 전에는 이번 맛이 있으면 이번 맛만 썼다.
  - `ChatIntentFacade.followSpokenTastes`: 합친 뒤 이번 말의 맛으로 고친다. 바뀌면 로그를 남긴다.
