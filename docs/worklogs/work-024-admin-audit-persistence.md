# WORK-024: 관리자 작업 이력 저장 모델

상태: 검증 대기 · 작성일: 2026-10-17 · 담당: 관리자

## 목표와 완료 기준

- 작업자 회원, 동작, 대상 종류·ID, 결과를 admin_audit_logs에 저장할 수 있는 모델과 저장소를 만든다.
- 결과는 SUCCESS, FAILED, DENIED 중 하나다. 대상 ID는 생성 실패 등을 위해 비울 수 있다.

## 근거와 범위

- docs/database/data-dictionary.md의 admin_audit_logs 컬럼과 사용자 요청 13번.
- 변경 전후 값은 이번 저장 API에서 받지 않으므로 비밀번호 등 민감 값이 이 경로로 저장되지 않는다.
- 개별 관리자 기능의 기록 호출은 각 기능 PR에서 연결한다.

## 구현 결과

- AdminAuditLog JPA 엔티티와 JpaRepository를 추가했다.
- 작업자 회원 참조는 LAZY 관계다. 동작과 결과는 명세에 있는 enum 값으로 한정했다.
- 신규 HTTP API와 오류 코드는 없다.

## 검증

- Gradle compileJava: 통과.
- 전체 컴파일과 전체 테스트는 기록 서비스 단계에서 재실행한다.
- 실제 MySQL 저장은 로컬 DB 인증 오류가 해결된 후 확인해야 한다.

## 연결과 남은 작업

- 기록 서비스를 다음 작은 작업에서 추가한다.
