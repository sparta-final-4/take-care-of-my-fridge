# WORK-137: 상담 종료 뒤 채팅창은 항상 새 상담으로

상태: 검증 대기 · 작성일: 2026-11-02 · 담당: zcookiez

## 목표와 완료 기준

- 상담을 끝낸 뒤 채팅창을 다시 열면 언제 열든(바로·5분 뒤·새로고침·서버 재기동 뒤) 빈 새 상담이 열린다.
- 끝낸 직후 채팅창이 열려 있는 동안은 지금처럼 "상담이 끝났어요" + 대화 + [새 상담 시작]을 보여 주고, 지난 상담을 볼 곳을 안내한다.
- 진행 중 상담은 닫았다 열어도 이어진다.

## 근거와 범위

- 원인: 끝난 상담이 진행 중 상담 캐시(`['chat','activeSession']`, staleTime Infinity)에 남아, 캐시가 살아 있으면 끝난 상담이, 사라지면(새로고침·gcTime 5분) POST로 새 상담이 열렸다.
- 프론트만. 마이페이지 AI 상담 내역 오른쪽 칸, 백엔드는 바꾸지 않는다.

## 닫는 경로 확인

| 경로 | 처리 |
|---|---|
| ✕ 버튼(평소·로그인 안내 화면), ESC | `handleRequestClose` → `closeChat`. 답 받는 중이면 확인 후 중단(기존 그대로) |
| 로그인 안내의 [로그인하기] | `onCloseModal` → 위와 같음 |
| 새 안내 문구 링크 | `onCloseModal` 후 상담 내역으로 이동 |
| 상담 내역 화면 진입 | `setInlineHost`가 `isOpen: false`로 직접 닫음(`closeChat`·확인 창을 거치지 않음) |
| 로그아웃·세션 만료 | 채팅창을 닫지 않음. 세션 전환(`session.ts`)이 쿼리를 초기화하고 채팅창은 로그인 안내로 바뀜 |

- 캐시 비우기는 `ChatModal`의 `isOpen`이 false가 될 때 한 곳에서 하므로, 로그아웃을 뺀 모든 닫는 경로(상담 내역 진입 포함)가 같은 처리를 탄다.

## 구현 결과

- `domains/chat/queries.ts`: `removeEndedActiveSession(queryClient)`. 진행 중 상담 캐시가 COMPLETED·EXPIRED이면 `removeQueries`. 아직 이 캐시를 보는 곳(상담 내역 오른쪽 칸)이 있으면 비우지 않는다. 지우면 그 화면이 다시 받으며(POST) 새 상담이 생기기 때문.
- `ChatModal.tsx`: 닫힐 때 위 함수를 부른다. 닫히는 커밋에서 대화 칸(`ChatRoomSection`)의 관찰자가 먼저 빠지므로 이 시점엔 보는 곳이 없다.
- `ChatEndedNotice.tsx`(새로 만듦): 끝난 상담일 때 상태 줄 아래 작은 회색 글씨 "지난 상담은 마이페이지 > AI 상담 내역에서 볼 수 있어요". 누르면 상담 내역으로 이동하고 채팅창을 닫는다. 상태 줄을 숨기는 상담 내역 오른쪽 칸에는 나오지 않는다.
- 다른 창의 끝남 신호로 끝난 상태가 된 경우도 캐시 상태가 같으므로 같게 처리된다.
- `ChatHistorySection.tsx`: 상담 내역 화면을 떠날 때(오른쪽 칸이 사라질 때)도 `removeEndedActiveSessionAfterUnmount`로 끝난 상담 캐시를 비운다. 화면이 사라질 때는 부모 정리가 자식(오른쪽 칸)의 쿼리 구독 해제보다 먼저 돌아 아직 보는 곳이 남아 있으므로, 마이크로태스크로 정리가 모두 끝난 뒤에 비운다. 이때는 보는 화면이 없어 POST가 나가지 않는다.
