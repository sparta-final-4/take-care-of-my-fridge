# WORK-074: 주문 내역 화면

상태: 검증 완료 · 작성일: 2026-10-22 · 담당: 준혁

## 목표와 완료 기준

- 마이페이지 "주문 내역"에서 내 주문을 최신 주문부터 10개씩 본다.
- 결제 대기 주문은 상태만 보이고, 주문 확인 화면으로 들어가는 버튼은 없다.
- 페이지 번호는 새로고침·뒤로 가기에도 유지된다.

## 근거와 범위

- 선행 작업: WORK-073 내 주문 목록 조회. 이 화면의 PR은 WORK-073 PR 위에 쌓는다.
- 마이페이지 틀(`MyPageLayout`)의 "주문 내역" 자리를 채웠다.
- 화면 상세는 `docs/requirements/screens.md`에 "주문 내역" 항목으로 추가했다.

## 구현 결과

- `OrderListSection` (신규): 주문번호, 주문일(`YYYY-MM-DD`), 결제 금액, 상태, 버튼을 한 행에 둔다.
  - 상태는 결제 대기·결제 완료·구매 확정 세 가지다. 취소된 주문은 서버가 보내지 않는다.
  - 결제 대기 주문에는 버튼을 두지 않는다. 주문 확인 화면은 앱 안에서 나가면 주문을 취소한다(WORK-072). PG 결제 뒤 서버 확인을 기다리는 주문을 확인하러 들어갔다가 뒤로 가기에서 나가기를 고르면, 결제한 주문이 취소되고 결제는 웹훅에서 자동 취소된다. 목록에 보이는 것만으로 "결제했는데 주문이 없다"는 혼란은 막을 수 있어 주문 확인 화면으로 가는 버튼은 두지 않았다.
  - 결제 완료·구매 확정 주문의 "상세 보기"는 주문 상세 화면이 생길 때까지 비활성이고, 올리면 "주문 상세 기능은 준비 중입니다."를 보여 준다. 주문 확인 화면의 비활성 "결제하기"와 같은 방식이다.
  - 주문일이 비어 오면 `-`로 보인다. 생성 타입에서 응답 필드가 모두 선택 필드라, 값이 없을 때 오늘 날짜가 보이지 않게 했다.
  - 페이지 번호는 URL 쿼리(`?page=2`)에 두고, 1페이지는 쿼리를 지운다. 상품 목록과 같은 방식이다.
  - 로딩 `Skeleton`, 주문이 없으면 `Empty`, 첫 조회 실패는 `Result`와 다시 시도. 페이지를 바꾸는 동안은 이전 목록을 흐리게 보여 준다.
- 사용자 화면 목록은 카드 그리드가 기본이지만, 주문 내역은 한 건에 보일 정보가 칸 다섯 개라 장바구니·주문 확인 화면과 같은 행 목록으로 그렸다.
- 반응형: lg부터 한 행, lg 미만은 두 단(주문번호·상태 / 주문일·금액·버튼)이다. md에서는 마이페이지 메뉴가 옆에 붙어 목록 칸이 좁아지고, 한 행으로 두면 주문번호가 잘린다. 모바일 버튼 높이는 44px이다.
- 행마다 grid가 따로라, 버튼이 없는 결제 대기 행만 칸이 밀리지 않게 버튼 칸 너비를 `$order-action-width`로 고정했다.
