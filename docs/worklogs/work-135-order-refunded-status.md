# WORK-135: 주문 전액 환불 상태 추가

상태: 구현 완료 · 작성일: 2026-11-02 · 담당: 준혁

## 목표와 완료 기준

- 모든 상품이 환불된 주문을 주문 목록과 상세에서 "전액 환불"로 보여 준다.
- 환불 도메인이 환불을 끝낸 뒤 부를 주문 상태 변경 메서드를 둔다. 주문 도메인은 상태 전이 규칙만 갖고, 전액 환불인지는 환불 도메인이 판단한다.
- 특가·번개 드롭 상품이 있는 주문은 나머지가 모두 환불되면 7일을 기다리지 않고 바로 구매 확정한다.

## 근거와 범위

- 선행 작업: WORK-102 구매 확정 검증과 확정 수량, WORK-133 주문 구조 정리.
- 특가·번개 드롭 상품은 환불할 수 없다(환불 도메인 규칙). 그래서 이런 상품이 있는 주문은 모든 상품이 환불될 수 없다.
- 환불 도메인의 호출은 이 작업에 넣지 않는다. 환불 담당이 환불 완료 뒤 판단해 부른다.

## 변경 전후

- 전: 모든 상품이 환불된 주문도 결제 완료로 남았다. 구매 확정을 누르면 환불 기록을 다시 읽어 `ORDER_014`로 거절했고, 자동 구매 확정이 이 주문을 매시간 다시 골랐다.
- 후: 환불 도메인이 전액 환불 주문을 `REFUNDED`로 바꾼다. 구매 확정은 상태만 보고 `ORDER_014`로 거절하고, 자동 구매 확정은 이 주문을 고르지 않는다.
- 전: 특가·번개 드롭 상품만 남은 주문은 결제 7일 뒤 자동 구매 확정을 기다렸다.
- 후: 환불 도메인이 부르면 바로 구매 확정된다.

## 구현 결과

- `OrderStatus`: `REFUNDED`(전액 환불)를 추가했다. 구매 확정과 함께 끝 상태다.
- `Order.markRefunded`: 결제 완료 주문만 전액 환불로 바꾸고, 그 외에는 `ORDER_002`로 거절한다.
- `Order.confirm`: 전액 환불 주문은 `ORDER_014`로 거절한다.
- `OrderStatusFacade.markRefunded`, `confirmAfterRefund`: 환불 도메인이 부른다. 회원 확인 없이 주문 행을 잠그고, 없는 주문은 `ORDER_001`이다. `confirmAfterRefund`는 구매 확정과 같은 방법으로 확정 수량을 저장하고 구매 확정 이벤트를 보낸다.
- 구매 확정에서 환불 기록으로 전액 환불을 다시 확인하던 검사를 지웠다. 자동 구매 확정은 대상을 고른 뒤 잠그기 전에 전액 환불이 된 주문을 건너뛴다.
- 주문 목록에 전액 환불 주문을 넣었다.
- API 응답의 `status`에 `REFUNDED`가 추가된다. 요청 형식은 바뀌지 않는다.
- DB: `orders.status` ENUM에 `REFUNDED`를 추가한다.
- 문서: 주문 도메인 문서, API 명세, 데이터 사전, 테스트 전략(ORDER-09, ORDER-15).

## 연결과 남은 작업

- 환불 도메인: 환불 완료 뒤 판단해 `markRefunded` 또는 `confirmAfterRefund`를 부른다. `RefundQueryService.isFullyRefunded`는 주문 도메인에서 더 쓰지 않는다.
- 이미 생성된 DB의 `orders.status` 열이 ENUM이면 `REFUNDED`를 추가해야 한다.
