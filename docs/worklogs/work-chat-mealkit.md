# 상담 밀키트 추천

상태: 검증 대기 · 작성일: 2026-11-06 · 담당: zcookiez

브랜치 `feat/chat-mealkit`(`feat/chat-commerce` 위). 커밋은 로컬에만 있고 push하지 않았다.

## 목표와 완료 기준
- 사용자 문제: 요리하기 번거롭거나 밀키트를 찾는 사용자에게 상담이 레시피만 보여 줬다. 판매 중인 밀키트를 상담 안에서 볼 수도, 담을 수도 없었다.
- 완료 조건:
  - "밀키트"를 말하면 밀키트만 최대 3장, 레시피 카드 없음.
  - 번거로워하는 말("간단하게·귀찮")만 있으면 레시피 카드 3장 + 밀키트 1장.
  - "밀키트 말고"면 밀키트 없음.
  - 밀키트 카드는 상품 상세로 이어지고, 상담 창 안에서 장바구니에 담을 수 있다.
  - 저장·다시 불러오기에서도 보인다 (지금 가격·품절 기준).

## 근거와 범위
- 요구사항: 기획서 "부족 재료·밀키트 추천"(`project-plan.md:22`), 화면 "AI 상담 팝업 부족 재료·밀키트 제안"(`screens.md:38`)
- 변경 영역:
  - product: `mealkit_products.recipe_id` 칸, 판매 중·상품 ID 밀키트 조회 (상품 담당 준모님 허락)
  - chat: 밀키트 단어 확인, 밀키트 고르기, 카드 이벤트·저장·다시 불러오기
  - fe chat: 밀키트 카드
- 하지 않은 것:
  - 관리자 밀키트 등록 화면의 레시피 고르기 (recipe_id는 null로 둔다)
  - 조리 시간(`cook_time_min`)은 쓰지 않는다
  - 의도 프롬프트는 바꾸지 않는다

## 정한 정책
- 언제 보여 줄지 (`MealkitWordChecker`, 단어는 `app.chat.mealkit-words`):
  - "밀키트"를 부정 없이 말함 → 밀키트만 (ONLY)
  - 그게 아니고 번거로워하는 말(간단·간편·빨리·귀찮·요리하기 싫)이 부정 없이 있음 → 레시피 + 밀키트 1장 (WITH_RECIPES)
  - 부정 위치는 맛 단어 확인과 같다 ("안·덜"은 바로 앞, "말고·빼고·않·싫·없이"는 뒤 4글자 안). 밀키트 단어가 부정이면 다른 말이 있어도 보여 주지 않는다
  - "간단한 반찬", "빨리 되는 국"에도 밀키트 한 장이 붙는다 (사용자 확인)
- 고르기 (`MealkitPicker`, 순수 클래스):
  - 거르기: 판매 중이고 판매가 기준 품절이 아님, 레시피 카드와 같은 레시피 아님, 냉장고에 같은 이름(공백 무시) 밀키트 줄 없음, 연결 레시피가 피할 맛 아님
  - 정렬: 요청 일치 수(분류·원하는 맛·요리 이름 키워드) → 이 상담에서 안 보여 준 것 → 레시피 연결 있음 → 냉장고 재료 겹침 수 → 할인 중 → 판매 단가 → 상품 ID
  - 3개보다 적으면 있는 만큼만. 데이터가 적어 생기는 반복은 괜찮다 (사용자 확인)
- 밀키트만 보여 주는 답의 글: AI를 부르지 않고 서버 문장을 보낸다.
  - 이유: 레시피 카드가 없어 AI 설명 프롬프트(카드 [1]~[3] 표시)를 그대로 쓸 수 없고, 프롬프트에 "레시피 카드 없음"을 알려도 AI가 레시피를 소개할 위험이 남는다. 서버 문장은 그런 위험이 없고 AI 호출도 줄인다.
  - 문장: "지금 살 수 있는 밀키트를 골라 봤어요." / 조건이 맞으면 "말씀하신 조건에 맞춰 …" / 조건을 말했는데 맞은 게 없으면 "말씀하신 조건에 맞는 밀키트는 없어서, 지금 살 수 있는 밀키트를 골라 봤어요." + 담기 안내
- 판매 중 밀키트가 하나도 없으면(또는 거르고 남은 게 없으면) "지금은 추천드릴 밀키트가 없어요." 안내를 맨 앞에 두고 레시피 3장 (기존 안내 문장 방식)
- 레시피 카드 아래 한 장의 설명: "요리하기 번거로우면 {이름} 밀키트로 간편하게 드셔 보세요." 이름에 "밀키트"가 있으면 붙이지 않고, 조사 으로/로는 받침을 본다
- AI가 "밀키트 뭐 있어"를 일반 대화로 보면 서버가 추천으로 바꾼다 (밀키트 카드는 추천 답에만 붙는다)
- AI가 "밀키트"를 요리 이름 키워드로 뽑으면 서버가 뺀다 (레시피 검색이 "밀키트"를 찾지 않게)

## AI 활용과 개발자 판단
- AI에 맡긴 작업: 상품·냉장고·상담 저장 구조 조사, 구현·테스트, SQL 작성, oag 갱신
- oag 갱신: PR 1과 같이 임시 `@SpringBootTest`(Testcontainers MySQL)로 `/v3/api-docs`를 받아 스크립트와 같은 정리 후 `pnpm oag:generate:offline`. 스펙 변경은 `RecommendedMealkit`과 `ChatMessageResponse.mealkits`뿐이다. 임시 테스트는 지웠다
- 조사에서 확인한 것:
  - 상품 테이블 DDL·데이터 사전 문서가 없다 → 새 SQL 파일(`docs/database/product-mealkit-recipe.sql`)과 이 기록으로 대신한다
  - `chat_recommendations`에 이미 `product_id` 칸이 있다 (recipe_id·product_id 중 하나만). 테이블 변경 없음
  - 냉장고 밀키트 줄은 모두 밀키트 재료(ING_MEALKIT) 하나로 들어가고 상품 ID가 없다. `raw_name`(구매 때 상품 이름)으로 같은 밀키트를 가린다 (사용자 확인)
  - dev 밀키트 상품 이름은 끝에 " 밀키트"가 붙어 있어("된장국 밀키트") 레시피 이름("된장국")과 이름으로 맞출 수 없다. 처음 쓴 이름 매칭 채우기 SQL은 dev에서 0건이었다. 조회 결과에 이미 " 밀키트"가 보였는데 대조하지 않았다. 상품 ID → 레시피 ID 직접 매핑(24→544, 25→543, 26→542, 27→539, 28→555)으로 바꿨다
- 개발자 판단: 밀키트만 원하는 말일 때 밀키트만 최대 3장 (처음 제안은 레시피 3장 + 밀키트 1장이었으나 사용자가 바꿈)

## 추가: 묻는 말과 일반 답 추천 기준 (2026-11-06)
- 문제: "밀키트 추천 기준이 뭐야?"를 서버가 "밀키트" 단어 때문에 일반 대화에서 추천으로 바꿔 밀키트 카드가 나갔다 (sessionId 60).
- 점검: 서버가 의도를 추천으로 바꾸는 곳은 둘이었다. GENERAL + 밀키트 단어, AI 실패 + 선택 재료. 맛·분류 단어 보정은 모든 의도에서 돌았지만 일반 답·레시피 자세히에는 결과 영향이 없었다(로그만).
- 공통 규칙 (`2ef0ce49`): `AskWordChecker`(단어는 `app.chat.ask-words`). 서버가 의도를 바꾸는 것은 달라는 말이 있고 묻는 말이 없을 때만. "추천 기준"처럼 같이 있으면 묻는 말이 이긴다. AI 실패 + 선택 재료여도 묻는 말이면 일반 답. 바꿨을 때·안 바꿨을 때 모두 로그 한 줄. "국물 밀키트"처럼 달라는 말이 없는 말은 AI 판단을 따른다.
- 조건 보정 (`b1ed45fd`): 맛·분류 단어 보정은 RECOMMEND·REFINE(그리고 밀키트로 추천이 된 경우)일 때만.
- 일반 답 추천 기준: `prompts/chat-general.txt`를 일반 답에만 공통 프롬프트 뒤에 붙인다. 레시피 3줄 + 밀키트 1줄 + "기준 밖의 것은 말하지 않기" 1줄. 일반 답 시스템 프롬프트는 300자 → 748자(약 2.5배). 정렬 코드 세 곳(`RecipeCandidateScorer.order`, `RecommendationPicker`, `MealkitPicker`)에 "기준이 바뀌면 이 문장도 고치기" 주석.
- 검증: `./gradlew clean test` 2,018개 통과, 실패 0, 건너뜀 1. 실제 AI 답(기준 질문에 문장대로 답하는지)은 서버를 띄우지 않아 확인하지 못했다.
