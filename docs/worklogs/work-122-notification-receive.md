# WORK-122: 알림 요청 받아 저장

상태: 검증 완료 · 작성일: 2026-10-30 · 담당: 준혁

## 목표와 완료 기준

- `notification-requested` 토픽의 알림 요청을 받아 알림 테이블(`notifications`)에 저장한다.
- 같은 회원에게 같은 중복 방지 키가 두 번 이상 와도 알림은 하나만 남는다.

## 근거와 범위

- 선행 작업: 번개 드롭 등록·시작 알림 요청 발행. 메시지는 알림 테이블 칸(회원, 종류, 문구, 이동 경로, 중복 방지 키)과 같은 모양이다.
- 소비자는 어느 도메인이 보냈는지 보지 않고 메시지를 그대로 저장한다. 다음에 이 토픽을 쓰는 도메인도 소비자를 고치지 않는다.
- 알림 목록·안 읽은 수·전부 읽음 API는 다음 작업이다.

## 구현 결과

- `NotificationRequestedConsumer`: 소비 그룹 `notification`으로 메시지를 받아 저장 서비스를 부른다.
  - 회원과 중복 방지 키 유니크 제약(`uk_notifications_member_id_dedupe_key`) 위반이면 로그만 남기고 넘어간다.
  - 그 밖의 실패(다른 제약 위반, 빈 값으로 인한 엔티티 검증 실패)는 다시 던져 공용 설정대로 재시도 뒤 DLT로 보낸다.
- `NotificationCreateService`: 메시지로 알림 엔티티를 만들어 저장한다.
- `NotificationRepository`: 기본 저장 기능만 쓴다.
- API·DB 변경 없음. 테이블과 유니크 제약은 이미 있다.

### 중복 처리 방식

- 저장을 먼저 시도하고, 유니크 제약 위반을 잡아 건너뛴다.
- 저장 전 존재 확인은 쓰지 않았다. 두 소비자가 같은 메시지를 동시에 받으면(재조정 직후 등) 둘 다 "없음"을 보고 저장해 결국 제약 위반이 난다. 위반 처리가 어차피 필요하고, 확인을 더하면 같은 규칙이 두 곳에 생긴다.
- 위반은 저장 트랜잭션 바깥(소비자)에서 잡는다. 트랜잭션 안에서 잡으면 롤백 표시가 남아 커밋할 때 다시 실패한다.
- 위반을 제약 이름으로 가린다. 문구 길이 초과 같은 다른 위반까지 건너뛰면 실패한 요청이 DLT에 남지 않고 사라진다.

<details><summary>테스트 목록</summary>

- 알림 요청 하나를 받으면 메시지 내용 그대로 안 읽은 알림 하나를 저장한다.
- 같은 회원에게 같은 중복 방지 키가 두 번 오면 알림은 하나만 남고 DLT로 보내지 않는다.
  - 두 번 보낸 뒤 다른 메시지를 하나 더 보내고, 그 메시지가 저장된 시점에 그 회원의 알림을 센다. 파티션이 하나라 차례대로 처리된다.
  - 유니크 제약이 있어 건너뛰기가 고장 나도 알림은 하나만 남는다. 그래서 DLT에 아무것도 가지 않았는지까지 본다.
- 중복 방지 키가 같아도 회원이 다르면 회원마다 하나씩 저장한다.

</details>
