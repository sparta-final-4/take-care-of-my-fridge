# WORK-075: 재고에 따른 품절 상태 자동 전환

상태: 검증 완료 · 작성일: 2026-10-22 · 담당: 준혁

## 목표와 완료 기준

- 주문으로 재고가 0이 되면 상품 상태가 `SOLD_OUT`으로 바뀐다.
- 주문 취소·환불로 재고가 다시 1 이상이 되면 `ON_SALE`로 돌아온다.
- 판매 중지(`STOPPED`) 상품은 재고가 바뀌어도 상태가 그대로다.

## 근거와 범위

- 선행 작업: WORK-067 주문하기, WORK-071 주문 취소.
- 상품 목록·상세와 프론트 상품 카드·상세는 `status`로 품절을 표시한다(목록 응답에는 재고가 없다). 주문하기가 재고를 빼도 상태가 `ON_SALE`로 남아, 재고가 0인 상품이 판매 중으로 보이고 담기를 누르면 장바구니에서 409가 났다.
- `SOLD_OUT`은 재고 0일 때 자동으로 되는 상태로 본다. 상품 도메인과 확인했다.
- 결제 후 환불은 주문 상태를 바꾸지 않고, 환불 도메인이 상품 행을 잠근 뒤 `Product.increaseStock`을 직접 부른다. 상태 전환을 서비스가 아니라 엔티티 메서드에 둔 이유다. 환불의 중복 처리 방지와 상품 행 잠금은 환불 도메인이 맡는다.
- 상품 조회 API, 장바구니, 프론트는 바꾸지 않았다.

## 구현 결과

### 상태 전환 규칙

`Product` (상품 도메인 엔티티)

| 메서드 | 바뀌기 전 상태 | 조건 | 바뀐 뒤 상태 |
|---|---|---|---|
| `decreaseStock` | `ON_SALE` | 뺀 뒤 재고 0 | `SOLD_OUT` |
| `decreaseStock` | `STOPPED` | 뺀 뒤 재고 0 | `STOPPED` 그대로 |
| `increaseStock` | `SOLD_OUT` | 늘린 뒤 재고는 항상 1 이상 | `ON_SALE` |
| `increaseStock` | `STOPPED` | - | `STOPPED` 그대로 |

- 차감이 거절되면(0 이하 수량, 재고 부족) 재고와 상태 모두 그대로다.
- 주문하기와 주문 취소는 이미 상품 행을 잠근 뒤 이 메서드들을 부른다. 재고와 상태가 같은 엔티티에서 함께 바뀌어 한 UPDATE로 나가므로, 동시 주문에서 둘이 어긋나지 않는다. 서비스 코드는 바꾸지 않았다.

### 음수·범위 방어 (기존 그대로)

- 0 이하 수량은 차감·되돌림 모두 `INVALID_INPUT_VALUE`로 거절한다.
- 재고보다 많이 빼려 하면 빼지 않고 `INSUFFICIENT_STOCK`으로 거절한다. 재고는 음수가 되지 않는다.
- 되돌림 수량은 주문·환불 수량이고, 그 수량은 이미 재고에서 뺐던 값이라 되돌린 뒤 재고가 int 범위를 넘지 않는다.

### 장바구니에 미치는 영향

없다. 장바구니는 품절을 재고 숫자로 판단하고, 상태는 `STOPPED`만 본다.

- 담기·수량 변경: `STOPPED`면 409 `PRODUCT_NOT_ON_SALE`, 재고를 넘으면 409 `CART_QUANTITY_EXCEEDS_STOCK`. 자동으로 `SOLD_OUT`이 된 상품은 재고가 0이라 이전과 똑같이 재고 초과로 거절된다.
- 조회: `soldOut = 재고 0 || STOPPED`. 결과가 같다.
