# WORK-096: 할인 후보에서 행사 등록

상태: 검증 대기 · 작성일: 2026-10-26 · 담당: 할인 후보

## 목표와 완료 기준
- 관리자가 추천 후보를 선택한 뒤 행사 종류·시작·종료 시각을 입력해 등록한다.
- 번개 드롭이면 한정 수량을 입력한다.
- 실제 행사 생성에 성공한 후보만 생성된 행사 ID와 `APPROVED` 상태를 남긴다. 가상 데이터 분석은 등록하지 않는다.

## 근거와 범위
- 사용자가 추천 목록 화면에서 행사 종류·시각을 입력하는 흐름을 승인했다.
- 기존 행사 생성 서비스가 특가·번개 드롭을 즉시 생성하고 행사 ID를 반환한다.
- 이번 작업은 후보 한 건씩 등록한다. 할인율은 분석 결과의 값을 사용한다.

## 구현 결과
- `POST /api/admin/deal-analyses/{analysisId}/event-requests`를 추가했다.
- 선택된 후보인지 검사하고 행사 생성·후보 상태 기록을 한 트랜잭션에서 처리한다.
- 추천 목록 화면에서 후보 선택과 행사 등록 폼을 제공한다.
- API 명세와 후보 상태 설명을 현재 직접 등록 방식에 맞췄다.

## 검증
| 명령·시나리오 | 결과 | 근거 |
|---|---|---|
| 할인 후보 서비스·컨트롤러 집중 테스트 | 통과 | Gradle `--tests '*DealEventServiceTest' --tests '*AdminDealAnalysisControllerTest'` |
| 프론트엔드 타입 검사·린트·빌드·테스트 | 통과 | `pnpm typecheck`, `pnpm lint`, `pnpm build`, `pnpm test` |
| 백엔드 전체 테스트 | 환경 제약 | Docker가 없어 Testcontainers 기반 테스트 30개가 초기화에 실패 |
| 브라우저 화면 검증 | 미실행 | 실제 분석 데이터가 준비되지 않음 |

## 연결과 남은 작업
- 실제 분석 결과 생성(24번)은 데이터 제공 협의가 끝난 뒤 연결한다.
- 행사 담당 기능은 같은 애플리케이션의 `SaleEventCreateService`를 사용한다.
