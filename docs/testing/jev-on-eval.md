# Jev on 모드 상담 의도 평가

상태: **통과 기준 미달 (고치기 코드는 지우지 않음)** · 작성일: 2026-11-17 · 브랜치: `feat/chat-jev-shadow`

> 의도 선택지를 고친 재평가는 [jev-on-v2](#jev-on-v2-의도에서-빼기와-이어서-다시를-구분-2026-11-17) 절에 있다 (반대 허용 기준 112/121, all-on 대비 −8).
> 요리 이름 칸 정의·되돌림의 넓은 요청·이어짐을 따로 묻기를 반영한 3차 평가는 [jev-on-v3](#jev-on-v3-요리-이름-칸-정의-되돌림의-넓은-요청-이어짐을-따로-묻기-2026-11-17) 절에 있다 (반대 허용 기준 112/121, all-on-v2 대비 −8, 통과 못 함).

on 모드(Jev가 의도·요청 종류·맛을 정하고, Jev 의도 confidence < 0.8이거나 실패하면 보정 없는 OpenAI 결과를 쓰며, 서버 보정은 서비스 규칙만)로
상담 의도를 정하는 전체 흐름을 평가 세트로 돌려 지금 서비스(all-on, OpenAI + 보정 전체)와 비교했다. 설계: [jev-on-design.md](jev-on-design.md) 8절.

## 결론

| 물음 | 답 |
|---|---|
| 통과 기준(all-on 대비 3문장 이내) | **통과하지 못했다.** 같은 121문장에서 all-on 120, jev-on **102**(−18). 매운맛-순한맛 반대 답 6문장을 맞음으로 쳐도 108(−12)이다 |
| intent 폴더 고치기 코드 삭제 | **하지 않았다.** 통과 기준이 조건이었다 |
| 맛 단계(keep-other-tastes·spoken-tastes-only)를 빼도 되나 | **on 모드 안에서는 거의 차이가 없다.** jev-on 102 → 101(−1: T10, 3회 중 1회만 맞음. T10은 jev-on에서도 3회 중 2회가 OpenAI 되돌림이라 흔들림). 다만 on 모드 자체가 통과하지 못해 지금 TasteWordChecker를 지울 근거는 아니다. 다시 추천 맛 따르기(refine-spoken-tastes)·밀키트·분류 부정어도 TasteWordChecker를 쓴다 |

틀린 18문장의 원인은 다섯 가지다(아래 표).
1. **OpenAI 되돌림 + 고치기 보정 없음 (6문장)**: Jev confidence가 낮은 문장은 대개 OpenAI도 틀리는 문장이고, all-on에서는 보정이 그걸 고쳤다(R14·R15·R17·N08·F11·T17). 되돌린 회차의 정답률은 63%(54회차 중 34)다.
2. **Jev 맛: 매운맛 ↔ 순한맛 반대 (6문장)**: Jev는 "매운 거 말고"에 순한맛 원함, "매운 거 먹고 싶어"에 순한맛 피함을 붙인다(T01·T03·T08·T13·U01·U04). 이 평가는 all-on과 같은 기준이라 틀림으로 셌다(Jev 평가에서는 허용한 기준).
3. **Jev 판단 (4문장)**: 의도 P01(당근 사고 싶어 → 추천 0.94), F12(조미료 뭐 있어 → 일반 0.88), 요청 종류 R05(차가운 면 → 특정 요리), U03(국물 말고 볶음으로 → 넓은 요청).
4. **"○○ 같은 요리" 요리 이름 채우기를 건너뜀 (1문장, 되돌림의 T17 포함 2문장)**: R06은 OpenAI가 요리 이름을 비우자 넓은 요청으로 가서, 넓은 요청 요리 이름도 "김피탕 같은 요리" → 찌개류로 엉뚱하게 받았다.
5. **요청 종류 규칙 (1문장)**: R01 "김치찌개 먹고 싶어"는 특정 요리라 분류를 쓰지 않는데, 기대값에 분류 [찌개]가 있다. 기대값을 고칠지 검토가 필요하다.

## 측정 조건

- 평가: `ChatIntentEvalManualTest`, 평가 세트 `chat-intent-eval.yml`(122문장, P12 포함) × 3회 다수결. gpt-4o-mini(의도·넓은 요청 요리 이름), Jev `jev-1.14.0`.
- `OPENAI_INTENT_EVAL_JEV_MODE=on`: 실제 JevIntentShadow(on)·JevIntentClassifier·JevIntentResolver·OpenAiSimilarDishGenerator(넓은 요청 프롬프트)를 만든다(`ChatIntentEvalJevOn`). 넓은 요청 요리 이름 캐시는 메모리(같은 표현이면 다시 부르지 않아 문장마다 첫 회차만 AI 호출).
- 기대 kind가 넓은 요청(BROAD)인 17문장은 분류·키워드 기대값 대신 "Jev로 정했고 쓴 요청 종류가 BROAD, 요리 이름이 비어 있지 않음"으로 비교했다. 요청 종류 일치는 따로 셌다(일치 판단에는 넣지 않음).
- 맛은 all-on과 같은 엄격한 기준(매운맛-순한맛 반대 답도 틀림)이다.
- `jev-on-no-taste-steps`: 같은 on 모드에 `OPENAI_INTENT_EVAL_SKIP_TASTE_STEPS=true`(보정 스위치 keep-other-tastes·spoken-tastes-only를 끔. main 코드는 그대로).
- all-on·all-off는 2026-11-16 결과(121문장, kind·P12 추가 전). 비교 표는 네 결과에 모두 있는 121문장으로 셌다. P12 "지금 세일하는 밀키트 있어?"는 jev-on·no-taste-steps 모두 맞음.
- 결과 파일: [eval-results/jev-on](eval-results/jev-on/), [eval-results/jev-on-no-taste-steps](eval-results/jev-on-no-taste-steps/) (summary·cases. runs.csv는 커밋하지 않음)

## jev-on-v2: 의도에서 빼기와 이어서 다시를 구분 (2026-11-17)

jev-on에서 되돌린 문장 중 R15 "오이 빼고 반찬 추천해줘"는 Jev가 REFINE(0.70)으로 답했다. "말고·빼고"가 든 문장(T17·T03·T08·T10)에서도 같았다.

빼기(피할 맛, 뺄 재료·분류)는 의도가 아니라 추천의 조건이다(피할 맛은 Jev 맛 질문, 뺄 재료·분류는 OpenAI가 꺼낸 값).

## jev-on-v3: 요리 이름 칸 정의, 되돌림의 넓은 요청, 이어짐을 따로 묻기 (2026-11-17)

jev-on-v2에서 남은 9문장(R01·R05·R06·T17·R17·N08·F11·P01·U03)과 이어지는 말의 되돌림(U09·U16)을 사용자가 정한 방향으로 고쳤다.
**방향**: Jev 쪽 추천은 하나의 의도(추천)로 보고, 빼기(피할 맛·뺄 재료·뺄 분류)와 이어짐(직전 추천에 이어지는 말인지)은 추천 안의 항목으로 다룬다.
추천 뒤 흐름을 건드리지 않으려고 "추천 + 이어짐"은 안에서만 ChatIntent.REFINE으로 넘긴다. 단어 목록은 넣지 않고 뜻으로만 고쳤다.

바꾼 것:
1. `prompts/chat-intent.txt` dishText 정의: "사용자가 원하는 요리이거나, 비슷한 것을 찾을 기준으로 말한 요리의 이름. '○○ 같은 것'의 ○○도 여기에 쓴다. 빼 달라거나 피하고 싶다고 말한 요리는 쓰지 않는다. '말고'·'빼고'가 맛이나 재료에 붙었으면 요리 이름은 그대로 쓴다. 분류나 종류(찌개, 국물, 디저트)와 재료 이름은 요리 이름이 아니다"에 일반 예시 하나("짠 거 말고 된장찌개 같은 거" → 된장찌개 / "된장찌개 말고 다른 거" → 빈 문자열)를 더했다. 예전 "분류·요리 종류(…)나 특징(…)은 요리 이름이 아니라 빈 문자열이다" 줄은 새 정의로 바꿨다. 프롬프트는 2,919자에서 3,038자가 됐다(3,300자 기준 안이라 다른 문장은 줄이지 않았다). off 모드도 이 프롬프트를 쓴다.
2. 되돌림의 넓은 요청: Jev 의도 confidence가 0.8 미만이라 OpenAI로 되돌릴 때, OpenAI 의도가 추천 계열(RECOMMEND·REFINE)이고 이미 받아 둔 Jev 2차 요청 종류가 넓은 요청이면 의도·맛은 OpenAI 것으로 두고 넓은 요청 요리 이름 경로(LLM 요리 이름 → 검색)를 탄다. OpenAI를 다시 부르지 않는다. decision은 `OPENAI_LOW_CONFIDENCE_JEV_BROAD`다.
3. Jev 설명: 1차 "추천"에 "재료를 사고 싶다는 말은 추천이 아니라 장보기다", 2차 "특정 분류"에 "빼거나 피하는 말이 함께 있어도, 원하는 요리 종류를 하나 말했으면 특정 분류다"를 더했다.
4. 특정 요리에도 Jev 1등 분류를 넣는다(1등이 없음이면 넣지 않는다). 분류는 점수를 올리는 조건이라 같은 분류가 앞에 온다.
5. 1차 의도 선택지에서 "이어서 다시"를 뺐다(직전 추천이 있어도). 추천 설명은 새 추천과 이어서 받는 추천을 모두 포함한다. 직전 추천이 있을 때만 Noul `follows_previous`("[직전 추천]에 이어서 하는 말인가? …")를 더 묻고, 추천 + follows_previous ≥ 0.5(평가로 정할 상수)면 REFINE으로 넘긴다. 의도 confidence는 "추천" 선택지의 confidence다. 레시피 자세히는 직전 추천이 있을 때만 선택지로 남는다. 비교 로그에 `jevFollowsPrevious` 칸을 더했다.

평가 비교 기준: 특정 요리 문장은 기대값에 분류가 있으면 1등 분류와 비교하고(R01), 없으면 분류를 비교하지 않는다.
평가는 all-on-v2(off 모드, 보정 모두 켬 = 지금 서비스, dishText 정의만 바뀜)와 jev-on-v3(on 모드)를 122문장 × 3회 돌렸다. 결과: [eval-results/all-on-v2](eval-results/all-on-v2/), [eval-results/jev-on-v3](eval-results/jev-on-v3/).
