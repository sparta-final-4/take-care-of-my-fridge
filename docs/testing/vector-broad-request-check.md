# 넓은 요청 벡터 검색 확인

상태: 확인만 함 (기능 코드 변경 없음) · 작성일: 2026-11-16 · 브랜치: `feat/chat-jev-shadow`

분류 묶음 사전(`config/chat-words.yml`의 `app.chat.words.category.groups`: 반찬·국물·간식·술안주·간단한한끼)을 쓰지 않고,
넓은 요청("술안주", "반찬", "간단한 한 끼")을 그 말 그대로 레시피 벡터 검색으로 찾을 수 있는지 미리 본다.

> 판정(○ 맞음 · △ 부분 · ✗ 틀림)은 AI 보조(Claude)가 레시피 이름·분류만 보고 내린 것이다. 레시피 내용은 보지 않았다.
> 사람이 다시 확인해야 하며, 판정이 한두 개 바뀌어도 아래 결론은 같다.

## 결론

| 물음 | 판단 |
|---|---|
| 벡터만으로 넓은 요청을 처리할 수 있나 | **아니다.** 넓은 요청 10개의 상위 10개 중 맞는 것은 평균 4개 안팎이다(○ 기준, 문장 그대로 43/100, "요리 추천" 꼴 38/100). 간식(1/10, 0/10)·칼칼한 국물(1/10)·간단한 한 끼(1/10)는 쓸 수 없다 |
| 유사도 기준(`min-similarity` 0.5)을 바꿔야 하나 | **기준을 바꿔도 해결되지 않는다.** 넓은 요청은 1위도 대부분 0.5 미만이라 지금 기준이면 거의 0건이다. 그런데 맞는 결과와 틀린 결과의 유사도가 섞여 있어(손님 초대 9/10이 0.31~0.38, 간식 1/10이 0.35~0.46) 어떤 고정 기준으로도 가를 수 없다. 0.5를 넘은 넓은 요청 결과는 20번의 검색에서 6건뿐이고, 그중 4건은 다이어트국수·해물국수·바지락칼국수(2번)처럼 이름 글자가 요청과 겹친 것이다 |
| 문장 꼴("~ 요리 추천")이 영향을 주나 | **준다, 대체로 나쁘게.** 유사도가 0.05~0.1 오르지만, "요리"·"추천" 말에 끌려 어떤 요청에도 비슷한 레시피(빈대떡, 해물볶음밥, 돈까스, 두부오믈렛, "…요리" 이름)가 올라온다. 디저트 9 → 2, 간식 1 → 0, 손님 초대 9 → 6. 나아진 것은 간단한 한 끼(1 → 4) 정도다. 분명한 요청(찌개·김치찌개)은 꼴과 상관없이 10/10이다 |

- 벡터 검색이 잘 되는 것은 지금처럼 **이름·분류 이름과 글자가 가까운 요청**이다(찌개 0.61~0.65, 김치찌개 0.68~0.76). [이전 평가](recipe-vector-fallback-evaluation.md)의 "오타에는 쓸 만하고 의도·문장형 검색에는 쓸 만한 결과가 거의 없다"와 같다.
- 틀린 결과의 상당수는 **글자 조각이 겹친 것**이다: 술안주 → 숙주라면, 간식 → 간장, 반찬 → 찬밥이용닭죽·찬밥전, 칼칼한 → 칼국수.
- 분류 묶음 사전의 분류와 비교하면, 벡터 결과 10개 중 묶음 분류 안에 드는 것은 0~5개다(찌개·디저트 같은 분류 이름 요청은 9~10개).
- 그래서 넓은 요청을 벡터 검색 하나로 바꾸는 것은 권하지 않는다. 다른 방법(예: 분류 확률, 태그·조리 정보 필터, 넓은 요청용 별도 문장으로 임베딩)이 필요하다. 이 문서는 확인만 했고 방법은 정하지 않았다.

## 측정 조건

- 기존 경로: `RecipeSearchService.search` → 키워드 검색(`keywordRequest`)이 0건일 때만 `vectorSearch` → `QueryEmbeddingService.embed(keyword)` → ES kNN (`vectorRequest`).
- 설정 (`application.yml`): 임베딩 모델 `text-embedding-3-small`, 1536차원. `app.search.vector`의 `k` 10, `num-candidates` 100, `min-similarity` 0.5(코사인). 레시피 임베딩 글은 `RecipeDocumentReader.embeddingText`(이름, 요약, 분류, 재료, 태그).
- 로컬 ES 9.2.0, `recipes` 별칭 → `recipes_20261107205437`, 1,693건 모두 `embedding` 있음.
- 일회용 Node 스크립트(커밋하지 않음)로 검색어 26개를 한 번에 임베딩하고(OpenAI `/v1/embeddings`, 키는 `OPENAI_INTENT_EVAL_KEY`), ES에 `knn {k: 10, num_candidates: 100}`을 **유사도 기준 없이** 보냈다. 필터·정렬은 넣지 않았다(서비스는 요청의 필터·정렬을 같이 쓴다).
- 유사도는 ES `_score`에서 코사인으로 바꿨다(`cos = 2 × _score − 1`, 이전 평가와 같다).
- 키워드 건수는 `keywordRequest`와 같은 필드(`name^3`, `ingredients.text^2`, `summary`)·`cross_fields`·AND·`korean_search` 분석기로 `_count`만 셌다(서비스의 다른 필터는 넣지 않음). "~ 요리 추천" 꼴은 "추천"이 레시피 글에 없어 모두 0건이다. 그래서 상담처럼 문장을 그대로 넣으면 벡터 폴백이 늘 돈다.
- "~ 요리 추천" 꼴: 이미 "요리"로 끝나면 "추천"만 붙였다("따뜻한 국물 요리 추천").
- 분류 묶음 사전 칸은 `CategoryWordChecker` 규칙(단어 단위, 4글자 이상 묶음 말은 띄어 써도 찾음)과 `chat-words.yml`을 읽고 적었다. 실행해서 얻은 값은 아니다.
