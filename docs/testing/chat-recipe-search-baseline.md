# 상담 레시피 검색 기준 기록

상태: 초안 (0단계 기준 기록 + 1단계 검색 수정 + 2단계 비슷한 요리·의도 규칙) · 작성일: 2026-11-13 · 갱신: 2026-11-16 (2단계)

AI 상담에서 요리 이름("나가사키 짬뽕", "김피탕" 등)을 말했는데 엉뚱한 레시피가 나오는 문제의 기록입니다. 0단계에서 고치기 전 동작을 남겼고(기능 코드 변경 없음), 1단계에서 검색 단계를 고친 뒤 결과를 "1단계 후" 칸에 더했습니다(의도 판단 미변경). 2단계에서 의도 판단(비슷한 요리 칸 `similarDishes`, 요리 이름 보정, 추천 시도)과 검색 보완(이름 조각 조건, 요리 이름을 말한 추천의 카드 후보)을 바꾸고 "2단계 후" 칸에 더했습니다. 레시피 목록 API 동작은 바꾸지 않았습니다.

- 근거 코드: `RecipeCandidateCollector.searchKeywords`·`searchKeywordsOnce`·`searchDishFragmentsOnly`, `RecipeCandidateFacade.supplementKeywords`·`supplementDishFragments`·`rankableInfos`, `RecipeSearchService.searchKeywordOnly`·`analyzeTokens`, `IntentResult.searchKeywords`, `IntentCorrector.checkDishAndKeywords`·`tryDish`
- 관련 문서: [레시피 검색 벡터 폴백 평가](recipe-vector-fallback-evaluation.md), [1단계 작업 기록](../worklogs/work-chat-dish-name-search.md), [2단계 작업 기록](../worklogs/work-chat-similar-dishes.md)

## 1단계에서 바꾼 것

1. **벡터 뒤에도 글자 검색 계속**: 벡터 검색은 한 번의 추천에서 한 번만 쓰고, 그 뒤 키워드는 끊지 않고 글자로만 찾습니다. 로그는 `나머지 N개 생략` 대신 키워드마다 `짬뽕 1건(글자만)`으로 남깁니다.
2. **요리 이름 조각 보충**: 키워드로 제대로 맞은 레시피(`KeywordMatch.strong`)가 없을 때 도는 보충 단계에서만 합니다. 요리 이름(없으면 첫 키워드)이 글자로 0건이면 `korean_search` 토큰 중 두 글자 이상만 골라 글자로 찾습니다. 토큰이 1개뿐이거나 두 글자 이상 토큰이 없으면 하지 않고, `_analyze`가 실패하면 공백으로 나눈 단어로 대신합니다. 이렇게 찾은 레시피는 새 종류 `KeywordMatch.Type.FRAGMENT`("이름 조각")로 표시합니다. 카드 이유는 "나가사키 짬뽕과 이름이 비슷한 요리예요"이고, "찾으신 ○○"로 쓰지 않습니다.
3. **못 찾으면 카드를 채우지 않음**: 요리 이름을 말했는데(요리 이름이 있거나, 원한 표현 없이 키워드만 있음) 보충 뒤에도 제대로 맞은 후보가 없으면 분류·냉장고 점수로만 걸린 후보와 글자 일부로만 걸린(SPLIT) 후보를 뺍니다. 벡터로 찾은 후보(오타 "김치찌게" → 김치찌개)는 남깁니다. 남는 게 없으면 카드 0장 → 정해진 답 `ChatStreamFacade.NO_RECIPE_REPLY`가 나갑니다.

## 2단계에서 바꾼 것

1. **비슷한 요리를 AI 판단에 맡기지 않음 (2단계 평가 뒤 별도 호출로 바꿈)**: 처음에는 의도 판단 응답에 `similarDishes`를 더했으나, 실제 평가(gpt-4o-mini, 121문장 × 3번)에서 N09가 3번 모두 빈 목록, R06·N10이 프롬프트 예시(김치찌개의 비슷한 요리)를 그대로 베꼈습니다. 그래서 의도 판단에서 빼고, 후보 검색에서 **요리 이름이 있고 그 이름 그대로 맞은 레시피(NAME)가 없을 때만** 비슷한 요리 AI(`prompts/chat-similar-dishes.txt`, 응답 `{"dishes": [...]}` strict json_schema)를 한 번 부릅니다(`SimilarDishFinder`). 같은 요리 이름은 Redis(`chat:similar-dishes:{요리 이름}`, 7일)에 두어 다시 부르지 않습니다. 받은 비슷한 요리(최대 5개)는 키워드 뒤에 더하고 글자로 찾아 후보에 더하며(늘린 이름 EXPANDED), 호출이 실패하면 비슷한 요리 없이 이름 조각·벡터 보충으로 진행합니다. 검색 키워드는 `[요리 이름] + AI 키워드`(띄어쓰기 무시 중복 제외, 최대 6개)입니다.
2. **요리 이름 보정**: AI가 요리 이름을 비웠으면 메시지에 그대로 있는 첫 키워드를 요리 이름으로 씁니다(분류 이름·묶음 말, 밀키트 말, "칼칼한 국물"처럼 맛 단어로 꾸민 특징은 빼고). 그래도 비었으면(평가에서 R06은 요리 이름·키워드가 모두 빔) "○○ 같은 요리·거·것·음식·메뉴"의 ○○(바로 앞 낱말)를 씁니다(분류·묶음 말·밀키트 말·가리키는 말 제외). 프롬프트에도 특정 요리가 아닌 일반 예시("○○ 같은 요리 추천해줘" → dishText ○○, 처음 듣는 이름이어도 그대로)를 두었습니다.
3. **추천 시도**: AI가 일반 답(GENERAL)으로 봐도 요리 이름이 있고 묻는 말이 없으면 추천합니다(출처 `DISH_TRY`). 카드가 0장이면 "찾지 못했어요" 대신 일반 답으로 돌립니다. "김피탕이 뭐야?"는 묻는 말("뭐야"를 묻는 말 목록에 더함)이라 일반 답 그대로입니다.
4. **이름 조각 조건**: 키워드 보충(벡터 포함)을 하지 않았어도(비슷한 요리가 맞음) 요리 이름 그대로 맞은 레시피(NAME)가 없으면 이름 조각만 찾습니다. 키워드(요리 이름·비슷한 요리)와 같은 조각은 이미 찾았으므로 다시 찾지 않습니다. 늘어난 ES 호출: 비슷한 요리 수(최대 5) + 분석 1번 + 조각 수(나가사키짬뽕 + 짬뽕이면 짬뽕 1 + 분석 1 + 조각 "나가사키" 1 → 3번).
5. **요리 이름을 말한 추천의 카드 후보**: 맞은 후보가 일부 있어도 키워드로 찾은 후보(이름·비슷한 요리·재료·조각·벡터)만 정렬·카드에 씁니다(상위 10개로 자르기 전에 뺌). 1~2장이어도 분류·냉장고 후보나 피할 맛 레시피로 채우지 않습니다. 요리 이름 없는 추천("뭐 먹지", "시원한 국물")은 지금처럼 3장을 채웁니다.

| `skipsLaterKeyword_whenFirstKeywordFallsBackToVector_현재동작` | `searchesLaterKeywordByText_whenFirstKeywordFallsBackToVector` | 첫 키워드가 벡터로 가도 "짬뽕"을 글자로 찾아 짬뽕해물탕밥(늘린 이름)이 후보에 들어감. "나가사키"는 조각으로 찾음 |
| `fillsCardsWithCategoryAndFridgeHits_whenNoKeywordMatches_현재동작` | `returnsNoCandidates_whenDishMatchesNothing` | 글자·벡터·조각 모두 0건이면 분류·냉장고 후보로 카드를 채우지 않음 (후보 0개, `keywordsNotFound` true) |

조각 보충 테스트: 띄어 쓴 이름(`searchesDishFragments_whenSpacedDishNotFound`), 붙여 쓴 이름(`…_whenJoinedDishNotFound`), 원래 이름으로 찾으면 나누지 않음(`skipsDishFragments_whenDishFoundByText`), 한 글자 토큰만(`…_whenAllTokensAreSingleCharacters`), 분석 실패 시 공백 대체(`splitsByWhitespace_whenAnalyzeFails`). 못 찾음 처리 테스트: 벡터 후보만 남김(`keepsOnlyVectorHits_whenDishMatchesNothingByText`), 특징만 말한 추천은 그대로(`keepsFridgeCandidates_whenOnlyFeatureAsked`).

## 회귀 테스트에 넣은 방식

- `chat-intent-eval.yml`: 기대값(정답)을 적는 곳이라 N09, N10, G14, T17, T18을 더했습니다. "김피탕 같은 요리 추천해줘"는 이미 R06(요리 이름 김피탕)이 있어 더하지 않았습니다. 이 평가는 `OPENAI_INTENT_EVAL=true`일 때만 도는 수동 테스트이고, 기대와 달라도 실패시키지 않고 일치율만 남기므로 CI에 영향이 없습니다.
- 2단계: N11 "나가사키짬뽕 레시피 추천해줘"(RECOMMEND, 요리 이름 나가사키짬뽕)를 더했습니다. 처음 더한 기대 칸 `similarDishes`는 비슷한 요리를 의도 판단에서 빼면서 지웠고, R06의 `categories: [튀김]`·`keywordsFirst`·`keywordsAny: [탕수육, 깐풍기]`(AI가 키워드를 늘리던 설계의 기대값)도 지워 `dish: 김피탕`만 남겼습니다. 비슷한 요리 AI는 `SimilarDishEvalManualTest`(같은 환경 변수, 일치 판정 없이 CSV)로 따로 봅니다.
- `chat-intent-replay`: 더하지 않았습니다. `inputs.csv`는 실제 AI가 낸 원래 결과를 기록한 것이고 `expected.csv`는 정답이 아니라 현재 서버 보정 결과의 스냅숏입니다(다른 줄이 하나라도 있으면 실패, 허용 실패 목록 없음). AI 키가 없어 원래 결과를 기록할 수 없고, 정답을 적으면 CI가 깨집니다.

## 남은 결정

- (해결) 카드 0장 답: 요리 이름을 못 찾으면 "{요리 이름} 레시피는 아직 없어요. …", 뺄 재료 때문에 뺐으면 "{요리 이름}에는 {재료}이(가) 들어 있어서 추천에서 뺐어요. …"를 보냅니다(`NoRecipeReplyWriter`). 그 밖(시간 등 다른 조건)은 기존 `NO_RECIPE_REPLY` 그대로입니다.
- "나가사키" 같은 지명 조각이 부대찌개·조림까지 데려옵니다. 2단계부터는 비슷한 요리가 맞아도 조각을 찾으므로 더 자주 나옵니다. 조각 중 마지막 토큰(요리 종류 말)만 쓸지는 실제 로그로 다시 봅니다.
- 요리 이름을 말한 추천은 맞은 후보가 1~2장이어도 그대로 보냅니다. 비슷한 요리 중 피할 맛인 것은 빠지고 다른 것으로 채우지 않습니다.
- 추천 시도(AI 일반 답 + 요리 이름 + 묻는 말 없음)가 "어제 김치찌개 먹었는데 맛있더라" 같은 잡담도 추천으로 바꿀 수 있습니다. 실제 로그(`상담 요리 이름이 있고 묻는 말이 없어 일반 대화를 추천으로 시도`)로 봅니다.
- 콕 집은 요리가 알레르기·시간 조건으로 빠지면 다른 요리로 채우지 않고 "찾지 못했어요"가 나갑니다(`dropsNamedDish_whenItUsesExcludedIngredient`). 이게 맞는지 확인이 필요합니다.
