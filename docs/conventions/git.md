# Git 협업 규칙

상태: 제안 · 근거: 초기 저장소 및 공유 자료 · 팀 규칙 미제공

## 확인된 상태

초기 확인 시 origin의 dev 추적 설정과 Initial commit이 있었습니다. 기본 브랜치, 보호 규칙, 병합 방식, CI는 확인되지 않았습니다. 작업 시 Git 상태를 다시 확인합니다.

## 협의용 초안

- 브랜치 생성 전 기준 브랜치와 현재 변경을 확인합니다. 기존 작업을 덮어쓰지 않습니다.
- 브랜치 명명은 팀 합의 전까지 기능을 알 수 있는 짧은 이름을 씁니다. 예시: feat/signup-validation. AI 도구가 붙이는 접두사도 이 규칙에 맞춥니다.
- 커밋은 하나의 설명 가능한 변경으로 묶습니다. 예시 형식: feat: 회원가입 입력 검증.
- PR에는 목적, 변경 범위, 관련 요구사항, 검증 결과, 연동 영향, 미해결 항목을 씁니다.
- 보호 브랜치 직접 푸시, 강제 푸시, 병합·배포는 팀 정책과 사용자 승인 범위를 확인합니다.
- 자격 증명·개인정보·실제 쿠키·토큰은 커밋하지 않습니다.

## 결정할 항목

| 항목 | 상태 |
|---|---|
| 기본·개발 브랜치와 기능 브랜치 명명 | 미정 |
| 리뷰 인원, 필수 CI, 병합 방식 | 미정 |
| 배포 대상·주기·승인 담당 | 미정 |
| 실패 시 롤백 단위·절차 | 미정 |

## PR 본문 템플릿

저장소 루트의 [`.github/pull_request_template.md`](../../.github/pull_request_template.md)를 기본 PR 양식으로 사용합니다.

```markdown
## 📌 작업 개요
- 작업 목적 및 배경을 간단히 작성해주세요.

## 🛠️ 작업 내용
- [ ] 주요 구현 및 변경 사항 1
- [ ] 주요 구현 및 변경 사항 2

## 📸 스크린샷 / 테스트 결과 (선택)
- Postman 결과나 실행 화면 캡처 첨부
```
