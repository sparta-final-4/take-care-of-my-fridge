# 화면 명세

상태: 초안 · 근거: S4 개인 담당 와이어프레임, S5 전체 서비스 설명  
실제 이미지 파일은 미제공이므로 텍스트 동작만 반영했습니다. S4의 예시 데이터는 실측값이 아닙니다.

## 화면별 작성 기준

각 화면에 ID, 담당, 진입·권한, 입력·데이터 출처, 동작, 로딩·빈 상태·실패, 이동 결과, 관련 API와 테스트를 연결합니다. 아직 없는 API 경로를 확정하지 않습니다.

## 개인 담당 화면

아래는 요약입니다. 화면별 입력 칸·버튼·실패 문구의 상세는 S4 화면 명세서에 있습니다. 구현할 화면부터 이 문서에 옮겨 적습니다.

| A-02 /admin/products/:id | ADMIN 목록 선택 | 상품 정보(보관 방법·유통기한 포함), 재고·판매·특가 읽기, 기준 시각, 해당 상품 작업 이력. 정상가 수정 가능(1원 이상, 작업 이력 기록) |

| A-06 /admin/deal-candidates | ADMIN | 요일·가상 할인율·최소 재고로 후보 분석. 미검토·선택·보류 저장. 제외 이유 표시. 실제 가격 변경 없음 |
| A-09 /admin/audit | ADMIN, 조회 화면은 제안 | 관리자 작업 이력. 성공·실패·권한 거부 이력. 작업자·대상·변경 전후·시각. 수정·삭제 없음 |
| A-10 /admin/members | ADMIN | 회원 검색·역할 필터. ACTIVE USER 승격 확인·기록. 정지 계정 승격 금지. 권한 해제 제외 |
| A-11 /admin/promotions | ADMIN, 담당 협의 | 행사 요청·등록·반려·종료. S5의 특가·번개 드롭 운영과 통합 범위 Q-05 |

U-01~05 5개와 A-01~06·09~11 9개로 총 14종입니다. U-05는 공통 상태입니다. A-07(후보 분석 기록)·A-08(모델·재학습)은 삭제된 화면이라 번호를 비워 둡니다. 다른 화면에 이 번호를 다시 쓰지 않습니다.

### 1 메인 할인 섹션 `/`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 메인 화면 오른쪽 위 칸(lg 미만은 전체 폭). 로그인 불필요 |
| 데이터 | `GET /api/sales/popular`. 진행 중인 특가·번개 드롭을 최근 7일 검색 클릭이 많은 순으로 최대 6개. 클릭이 같으면 할인율 순. 품절·판매 중지·번개 드롭 소진 상품은 오지 않습니다 |
| 제목 | 화면 문구 "지금 뜨는 할인". 대괄호 없이 보입니다 |
| 카드 | 이미지, 할인 구분 태그(번개 드롭은 옆에 "N/M개 남음"), 남은 시간, 상품 이름(두 줄까지), 할인율·할인가와 취소선 정가(두 줄). 담기 버튼은 없고 카드를 누르면 상품 상세로 이동합니다 |
| 넘기기 | 2장씩 보입니다. 3개 이상이면 머리글에 ←/→ 버튼이 생기고 5초마다 다음 2장이 밀려 들어옵니다. 마지막 다음은 처음 페이지가 같은 방향으로 이어서 들어오고, 화살표도 양쪽으로 돕니다. 마우스나 손가락으로 보이는 영역 폭의 20% 넘게 옆으로 끌어도 넘어가고, 덜 끌면 제자리로 돌아옵니다. 끌기를 마친 뒤에는 상품 상세로 이동하지 않습니다. 화살표나 끌기로 넘기면 5초를 다시 셉니다 |
| 멈춤 | 카드 위에 마우스를 올리거나 키보드로 카드에 들어가 있거나 끄는 동안은 넘기지 않습니다. 움직임 줄이기 설정이면 넘기는 애니메이션 없이 바뀝니다 |
| 로딩·빈 상태·실패 | 로딩 `Skeleton`, 할인이 없으면 `Empty`("진행 중인 할인 없음"), 실패는 "할인 상품 불러오기 실패"와 다시 시도 |
| 반응형 | 모든 폭에서 2장씩. 모바일에서 화살표 버튼 44px |

### 7-3 주문 내역 `/mypage/orders`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 마이페이지 "주문 내역", 주문 확인 화면의 "주문 내역 보기". 로그인 필요(`RequireAuth`) |
| 데이터 | `GET /api/orders?page=&size=10`. 결제 대기·결제 완료·구매 확정 주문을 최신 주문부터 보여 줍니다. 취소된 주문은 보이지 않습니다 |
| 목록 | 주문번호, 주문일(`YYYY-MM-DD`), 결제 금액, 상태(결제 대기·결제 완료·구매 확정). lg부터 같은 칸 이름의 머리글 |
| 결제 대기 | PG 결제는 끝났지만 서버 확인을 기다리는 주문일 수 있어 보입니다. 버튼은 없습니다. 주문 확인 화면은 나가면 주문을 취소하므로, 확인하러 들어간 사용자가 주문을 취소하지 않게 주문 확인 화면으로 가는 버튼을 두지 않습니다 |
| 상세 보기 | 결제 완료·구매 확정 주문. 주문 상세 화면으로 이동 |
| 페이지 | 10개씩. 페이지 번호는 URL 쿼리(`?page=2`)에 두어 새로고침·뒤로 가기에도 유지합니다 |
| 로딩·빈 상태·실패 | 로딩 `Skeleton`, 주문이 없으면 `Empty`, 첫 조회 실패 `Result`와 다시 시도 |
| 반응형 | lg 미만은 주문이 두 단(주문번호·상태 / 주문일·금액·버튼), 버튼 높이 44px. 버튼 칸은 너비를 고정해 버튼이 없는 결제 대기 주문도 다른 칸이 같은 위치에 옵니다 |

### 7-4 주문 상세 `/mypage/orders/:orderId`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 주문 내역의 "상세 보기". 로그인 필요(`RequireAuth`). 마이페이지 메뉴는 "주문 내역"이 켜진 채로 보입니다 |
| 데이터 | `GET /api/orders/{orderId}`. 주문할 때 저장한 상품·가격만 씁니다. 지금 상품 가격은 쓰지 않습니다 |
| 위쪽 | "주문 상세", 상태(결제 대기·결제 완료·취소·구매 확정), 주문번호와 주문 시각(`YYYY-MM-DD HH:mm`), 구매 확정 주문이면 구매 확정일(`YYYY-MM-DD (ddd)`), "목록으로" |
| 주문 상품 | 이미지, 할인 표시(정가 취소선, 특가·번개 드롭), 상품 이름, 수량, 단가, 금액. 주문 확인 화면과 같은 모양입니다. md부터 머리글(상품·수량·단가·금액). 이미지나 상품 이름을 누르면 상품 상세로 이동합니다 |
| 결제 금액 | 상품 금액(정가 합), 할인 금액, 결제 금액 |
| 구매 확정·환불 | 결제 완료·구매 확정 주문에 있습니다. "구매 확정 후에는 환불할 수 없습니다." 안내와 "구매 확정"·"환불 신청" |
| 구매 확정 | 결제 완료 주문: 확인 창("구매 확정할까요?") 뒤 `PATCH /api/orders/{orderId}/confirm`. 성공하면 "구매 확정되었습니다." 알림 후 주문을 다시 불러옵니다. 구매 확정 주문: 서버에 요청하지 않고 "이미 구매 확정된 주문입니다." 알림 |
| 환불 신청 | 결제 완료 주문: API가 붙기 전까지 비활성. 구매 확정 주문: "구매 확정된 주문은 환불이 불가합니다." 알림 |
| 환불 | 환불 여부와 금액은 이 화면에 두지 않고 환불 상세 화면이 보여 줍니다 |
| 로딩·실패 | 로딩 `Skeleton`. 없는 주문·남의 주문(`ORDER_001`)은 404 안내와 "목록으로", 그 밖의 실패는 다시 시도. 구매 확정 실패는 서버 메시지 알림 후 주문을 다시 불러옵니다 |
| 반응형 | lg 미만은 구매 확정·환불이 결제 금액 아래로, md 미만은 상품이 두 단(상품 정보 / 수량·단가·금액) |

### 8 장바구니 `/cart`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 헤더 "장바구니". 로그인 필요(`RequireAuth`). 헤더 배지는 장바구니 줄 수 |
| 데이터 | `GET /api/cart-items`. 줄마다 상품 이름·이미지·정가·지금 단가·할인 구분·할인율·종료 시각·번개 드롭 남은 수량·품절 여부. 재고 수는 받지 않습니다 |
| 목록 | 담은 순서. 할인 중이면 상품 화면과 같은 모양으로 할인율·할인가·취소선 정가를 나란히 보여 주고, 그 아래에 "특가"·"번개 드롭" 태그와 남은 시간, 번개 드롭은 "남은 수량 N / M개"(남은 수량 / 한정 수량)를 둡니다. 항목 금액은 지금 단가 × 수량. 남은 시간은 1초마다 세다가 0이 되면 "할인 종료"로 바뀌고, 가격은 새로고침하면 바뀝니다. 담은 뒤에 가격·한도가 바뀐 경우는 주문하기에서 서버가 막습니다. 이미지나 상품 이름을 누르면 상품 상세로 이동합니다 |
| 체크 | 품절이 아닌 줄은 처음부터 체크됩니다. 품절 줄은 체크할 수 없습니다. "전체 선택 (체크 수/전체 줄 수)" |
| 수량 | "−"·"+"로 1개씩 바꿉니다(`PATCH /api/cart-items/{cartItemId}`). 1 아래로 내려가지 않고, 번개 드롭은 1에서 "+"가 막힙니다. 요청 중에는 그 줄의 버튼을 막습니다 |
| 삭제 | 줄의 X, "선택 삭제", "전체 삭제"(`DELETE /api/cart-items?cartItemIds=`). 선택·전체 삭제는 확인 후 삭제 |
| 품절 항목 | 흐리게 "품절". 금액은 "-". 수량은 바꿀 수 없고 X로 지울 수 있습니다. 할인 정보는 품절이 아닌 항목과 똑같이 보입니다. 상품이 품절·판매 중지 상태이거나 번개 드롭 남은 수량이 0인 상품입니다 |
| 결제 예정 금액 | 체크한 줄의 상품 금액(정가 합), 할인 금액, 합계. 가격은 주문할 때 확정됩니다 |
| 주문하기 | "주문하기 (체크 수개)". 체크한 항목으로 주문을 만들고(`POST /api/orders`) 주문 확인 화면으로 이동. 요청 중에는 버튼을 잠근다. 멱등 키는 응답을 받을 때까지 같은 값을 쓰고, 체크한 항목이나 수량이 바뀌면 새로 만든다 요청에 장바구니에서 본 단가와 할인 구분을 함께 보내고, 주문 시점과 다르면 거절(`ORDER_010`)되어 장바구니를 다시 불러 새 가격을 보여 줍니다 |
| 로딩·빈 상태·실패 | 로딩 `Skeleton`, 빈 장바구니 `Empty`, 첫 조회 실패 `Result`와 다시 시도. 수량 변경·삭제 실패는 서버 메시지 알림(예: 재고 초과 `CART_002` "재고보다 많이 담을 수 없습니다."), 수량은 다시 불러온 값 |
| 반응형 | lg 미만은 결제 예정 금액이 목록 아래로, md 미만은 줄이 두 줄(상품 정보 / 수량·금액·삭제) |

### 9 주문 확인 `/orders/:orderId/checkout`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 장바구니 "주문하기" 뒤 이동. 로그인 필요(`RequireAuth`). 새로고침·재방문에도 같은 화면 |
| 데이터 | `GET /api/orders/{orderId}/checkout`. 주문할 때 확정한 가격이라 화면에 있는 동안 바뀌지 않습니다 |
| 위쪽 | "주문 확인", "결제 대기" 표시, 주문번호 |
| 주문 상품 | 이미지, 할인 표시(정가 취소선, 특가·번개 드롭), 상품 이름, 수량, 단가, 금액 |
| 결제할 금액 | 상품 금액(정가 합), 할인 금액, 결제할 금액 |
| 결제하기 | 연락처를 받아 결제창을 연다. 결제를 마치고 떠나는 이동은 나가기 확인 없이 진행한다. 주문이 생성 5분 뒤 지워져 결제 시작이 `ORDER_001`이면 "주문 시간이 지났습니다. 다시 주문해 주세요." 안내와 함께 장바구니로 이동한다 |
| 취소하기 | 확인 창("주문을 취소할까요?", "주문 취소"/"머무르기") 뒤 `PATCH /api/orders/{orderId}/cancel`. 성공하면 "주문이 취소되었습니다." 알림과 함께 장바구니로 이동한다. 이미 지워졌거나(`ORDER_001`) 취소된(`ORDER_008`) 주문이면 알림 없이 장바구니로 이동한다. 결제를 시도한 주문(`ORDER_012`)은 "결제를 시도한 주문이라 바로 취소되지 않습니다. 잠시 뒤 자동으로 취소됩니다." 안내와 함께 장바구니로 이동한다. 그 밖의 실패는 화면에 남는다 |
| 나가기 확인 | 앱 안 이동(뒤로 가기, 메뉴)은 확인 창("나가면 주문이 취소됩니다.", "나가기"/"머무르기")으로 붙잡는다. 나가기를 고르면 주문을 취소한 뒤 가려던 곳으로 간다. 취소가 `ORDER_001`·`ORDER_008`·`ORDER_012`로 끝나도 취소하기와 같은 알림 규칙으로 가려던 곳으로 간다. 새로고침·탭 닫기에는 묻지 않는다. 이렇게 남은 주문은 결제를 시도하지 않았으면 생성 5분 뒤 서버가 지우고, 결제를 시도했으면 마지막 결제 뒤 10분이 지나 서버가 취소한다 |
| 로딩·실패 | 로딩 `Skeleton`. 결제 완료(`ORDER_007`)는 안내와 "주문 내역 보기", 취소(`ORDER_008`)는 안내와 "장바구니로 가기", 없는 주문·남의 주문(`ORDER_001`)은 404 안내, 그 밖의 실패는 다시 시도 |
| 반응형 | lg 미만은 결제할 금액이 목록 아래로, md 미만은 상품이 두 단(상품 정보 / 수량·단가·금액) |

### 12 할인 행사 관리 `/admin/sale-events/new`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 관리자 헤더 "할인 행사". ADMIN만 |
| 구성 | "특가"·"번개 드롭"·"행사 목록" 탭. 특가·번개 드롭 탭을 바꾸면 고른 상품을 비웁니다. "행사 목록" 탭은 아래 "목록"을 보여 줍니다 |
| 기간 | 시작·종료 시각. 시작은 지금 이후, 종료는 시작보다 늦어야 합니다 |
| 상품 고르기 | 등록할 수 있는 상품 목록(`GET /api/admin/sale-events/products`)을 이름 검색·종류 필터(전체·재료·밀키트)·10개 페이지로 보여 줍니다. 판매 중이고 재고가 있으며 예정·진행 중인 행사에 들지 않은 상품만 나오고, 정가와 재고를 함께 보여 줍니다. 특가·번개 드롭 모두 여러 페이지에 걸쳐 여러 개를 고릅니다. 체크박스 말고 행의 다른 곳을 눌러도 선택이 바뀝니다 |
| 고른 상품 | 체크한 행에서 바로 할인율(1~99)을 입력하면 그 옆에 할인가가 계산됩니다. 번개 드롭은 한정 수량(1~재고)도 입력합니다. 기간 옆의 "고른 상품 N개"를 누르면 다른 페이지에서 고른 것까지 목록으로 보고 제외할 수 있고, 모두 입력해야 "등록"이 켜집니다 |
| 등록 | 특가 `POST /api/admin/sale-events/special`(고른 상품마다 같은 기간의 행사가 하나씩 따로 만들어집니다), 번개 드롭 `POST /api/admin/sale-events/flash-drop`(번개 드롭도 상품 여럿을 고를 수 있고 고른 상품마다 행사가 하나씩 만들어집니다). 성공하면 입력을 비웁니다. 실패는 서버 메시지 알림(예: 이미 행사가 있는 상품 `SALE_001`) |
| 목록 | `GET /api/admin/sale-events`. 행사에 든 상품 하나가 한 행입니다. 열은 상품·종류·상태·정가·할인가·할인율·한정 수량·남은 수량·판매량·시작·종료입니다. 시작·종료는 날짜와 시간을 두 줄로 보여 줍니다. 종료된 행사는 등록 당시 정가, 예정·진행 중 행사는 상품의 현재 정가를 보여 주고, 한정·남은 수량은 번개 드롭만 값이 있습니다. 판매량은 결제 완료·구매 확정 주문의 수량입니다. 상품 이름을 누르면 손님용 상품 상세로 이동합니다. 상품 이름 검색, 상태·종류 선택, 시작일·종료일(날짜 하나는 그날만) 조건과 판매량을 뺀 열 머리글 정렬이 있고 조건은 주소에 남습니다. 마지막 열 "작업"에서 예정 행사는 수정·삭제, 진행 중 행사는 종료 아이콘을 보이고 종료된 행사는 비웁니다. |
| 수정 | 예정 행사는 행 어디를 눌러도(수정 아이콘 포함) 그 행 아래로 수정 칸이 펼쳐지고(한 번에 하나, 다시 누르거나 취소하면 접힘, 검색·정렬·페이지를 바꾸면 접힘), `GET /api/admin/sale-events/{saleEventId}`로 행사 하나를 받아 시작·종료 시각과 행사 항목마다 할인율(1~99), 번개 드롭은 한정 수량(1 이상)을 보여 주고 입력한 할인율로 정가와 할인가를 바로 보여 줍니다. 행사 항목이 하나면 할인율·한정 수량 입력칸, "정가 → 할인가", 시작·종료 시각, 취소·저장을 이 순서로 한 줄에 놓고(상품 이름은 행에 이미 있어 생략), 여럿이면 줄마다 이름과 입력칸을 한 줄씩 보여 준 뒤 시각을 둡니다. 시각과 모든 행사 항목을 "저장" 하나로 `PATCH /api/admin/sale-events/{saleEventId}`에 보냅니다. 상품을 넣거나 빼지는 않습니다. 예전에 묶어 등록해 상품이 여럿인 행사는 "이 행사의 상품 N개가 같은 시각을 씁니다"를 위에 보여 줍니다. 성공하면 접고 목록을 다시 불러옵니다. 실패(예: 한정 수량이 재고보다 많음, 시작한 행사 `SALE_003`)는 서버 메시지 알림이고 수정 칸은 열려 있습니다 |
| 종료·삭제 | 진행 중인 할인 행사의 종료 아이콘이나 예정 할인 행사의 삭제 아이콘을 누르면 확인 창이 열립니다. 문구에 상품 이름과 할인 종류(특가·번개 드롭)가 들어가며, 종료는 "진행 중인 {상품 이름} {종류} 할인 행사를 종료합니다. 종료한 할인 행사는 다시 진행할 수 없습니다.", 삭제는 "예정된 {상품 이름} {종류} 할인 행사를 삭제합니다. 삭제한 할인 행사는 되돌릴 수 없습니다."입니다. 확인하면 종료는 `PATCH /api/admin/sale-events/{saleEventId}/end`, 삭제는 `DELETE /api/admin/sale-events/{saleEventId}`를 부릅니다. 종료는 상태만 바꾸고 등록한 종료 시각은 그대로여서 종료 열에는 그 시각이 보입니다. 삭제는 할인 행사와 행사 항목을 지웁니다. 성공하면 "{종류} 할인 행사를 종료했습니다" 또는 "{종류} 할인 행사를 삭제했습니다" 알림을 띄우고 목록을 다시 불러옵니다. 실패(예: 이미 시작한 할인 행사 삭제 `SALE_005`, 진행 중이 아닌 할인 행사 종료 `SALE_004`)는 서버 메시지 알림이고 목록을 다시 불러옵니다 |
| 반응형 | 상품 표는 가로 스크롤, 시작·종료 시각은 좁으면 아래로 넘어감. 목록 표는 쓸 수 있는 폭보다 좁을 때만 표 안에서 가로 스크롤 |

## 공통 UI 상태

아래는 구현 시 구체화할 검증 기준 제안입니다.

- 조회: 로딩, 빈 결과, 첫 조회 실패·재시도.
- 제출: 입력 오류, 요청 진행 중, 성공·실패 후 입력 유지 정책.
- 접근: 비로그인·권한 없음·없는 리소스 구분.
- 동시 변경: 조회 이후 재고·권한·행사 상태가 바뀐 경우 서버 결과 반영.
- 반응형·접근성은 [프론트 규칙](../conventions/frontend.md)에 따릅니다.
- 개인 소유 데이터는 화면 숨김뿐 아니라 서버 접근 제어로 보호합니다.
