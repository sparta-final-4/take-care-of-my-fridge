# 화면 명세

상태: 초안 · 근거: S4 개인 담당 와이어프레임, S5 전체 서비스 설명  
실제 이미지 파일은 미제공이므로 텍스트 동작만 반영했습니다. S4의 예시 데이터는 실측값이 아닙니다.

## 화면별 작성 기준

각 화면에 ID, 담당, 진입·권한, 입력·데이터 출처, 동작, 로딩·빈 상태·실패, 이동 결과, 관련 API와 테스트를 연결합니다. 아직 없는 API 경로를 확정하지 않습니다.

## 개인 담당 화면

아래는 요약입니다. 화면별 입력 칸·버튼·실패 문구의 상세는 S4 화면 명세서에 있습니다. 구현할 화면부터 이 문서에 옮겨 적습니다.

| U-01 /login | 비로그인 마이페이지 진입 | 이메일·비밀번호 로그인. 없는 계정·오류 비밀번호는 같은 문구. 정지 안내는 자격 확인 후. ADMIN은 관리자 상품 화면으로 이동. 30분 미사용 시 로그아웃(Q-01) |

| A-06 /admin/deal-candidates | ADMIN | 요일·가상 할인율·최소 재고로 후보 분석. 미검토·선택·보류 저장. 제외 이유 표시. 실제 가격 변경 없음 |

| A-11 /admin/promotions | ADMIN, 담당 협의 | 행사 요청·등록·반려·종료. S5의 특가·번개 드롭 운영과 통합 범위 Q-05 |

U-01~05 5개와 A-01~06·09~11 9개로 총 14종입니다. U-05는 공통 상태입니다. A-07(후보 분석 기록)·A-08(모델·재학습)은 삭제된 화면이라 번호를 비워 둡니다. 다른 화면에 이 번호를 다시 쓰지 않습니다.

### 7-3 주문 내역 `/mypage/orders`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 마이페이지 "주문 내역", 주문 확인 화면의 "주문 내역 보기". 로그인 필요(`RequireAuth`) |
| 데이터 | `GET /api/orders?page=&size=10`. 결제 대기·결제 완료·구매 확정 주문을 최신 주문부터 보여 줍니다. 취소된 주문은 보이지 않습니다 |
| 목록 | 주문번호, 주문일(`YYYY-MM-DD`), 결제 금액, 상태(결제 대기·결제 완료·구매 확정). lg부터 같은 칸 이름의 머리글 |
| 결제 대기 | PG 결제는 끝났지만 서버 확인을 기다리는 주문일 수 있어 보입니다. 버튼은 없습니다. 주문 확인 화면은 나가면 주문을 취소하므로, 확인하러 들어간 사용자가 주문을 취소하지 않게 주문 확인 화면으로 가는 버튼을 두지 않습니다 |
| 상세 보기 | 결제 완료·구매 확정 주문. 주문 상세 화면으로 이동 |
| 페이지 | 10개씩. 페이지 번호는 URL 쿼리(`?page=2`)에 두어 새로고침·뒤로 가기에도 유지합니다 |
| 로딩·빈 상태·실패 | 로딩 `Skeleton`, 주문이 없으면 `Empty`, 첫 조회 실패 `Result`와 다시 시도 |
| 반응형 | lg 미만은 주문이 두 단(주문번호·상태 / 주문일·금액·버튼), 버튼 높이 44px. 버튼 칸은 너비를 고정해 버튼이 없는 결제 대기 주문도 다른 칸이 같은 위치에 옵니다 |

### 7-4 주문 상세 `/mypage/orders/:orderId`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 주문 내역의 "상세 보기". 로그인 필요(`RequireAuth`). 마이페이지 메뉴는 "주문 내역"이 켜진 채로 보입니다 |
| 데이터 | `GET /api/orders/{orderId}`. 주문할 때 저장한 상품·가격만 씁니다. 지금 상품 가격은 쓰지 않습니다 |
| 위쪽 | "주문 상세", 상태(결제 대기·결제 완료·취소·구매 확정), 주문번호와 주문 시각(`YYYY-MM-DD HH:mm`), 구매 확정 주문이면 구매 확정일(`YYYY-MM-DD (ddd)`), "목록으로" |
| 주문 상품 | 이미지, 할인 표시(정가 취소선, 특가·번개 드롭), 상품 이름, 수량, 단가, 금액. 주문 확인 화면과 같은 모양입니다. md부터 머리글(상품·수량·단가·금액) |
| 결제 금액 | 상품 금액(정가 합), 할인 금액, 결제 금액 |
| 구매 확정·환불 | 결제 완료 주문에만 있습니다. "구매 확정 후에는 환불할 수 없습니다." 안내와 "구매 확정"·"환불 신청". 두 기능의 API가 붙기 전까지 비활성 |
| 환불 | 환불 여부와 금액은 이 화면에 두지 않고 환불 상세 화면이 보여 줍니다 |
| 로딩·실패 | 로딩 `Skeleton`. 없는 주문·남의 주문(`ORDER_001`)은 404 안내와 "목록으로", 그 밖의 실패는 다시 시도 |
| 반응형 | lg 미만은 구매 확정·환불이 결제 금액 아래로, md 미만은 상품이 두 단(상품 정보 / 수량·단가·금액) |

### 8 장바구니 `/cart`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 헤더 "장바구니". 로그인 필요(`RequireAuth`). 헤더 배지는 장바구니 줄 수 |
| 데이터 | `GET /api/cart-items`. 줄마다 상품 이름·이미지·정가·지금 단가·할인 구분·품절 여부. 재고 수는 받지 않습니다 |
| 목록 | 담은 순서. 할인 중이면 정가에 줄을 긋고 지금 단가와 "특가"·"번개 드롭" 표시. 줄 금액은 지금 단가 × 수량 |
| 체크 | 품절이 아닌 줄은 처음부터 체크됩니다. 품절 줄은 체크할 수 없습니다. "전체 선택 (체크 수/전체 줄 수)" |
| 수량 | "−"·"+"로 1개씩 바꿉니다(`PATCH /api/cart-items/{cartItemId}`). 1 아래로 내려가지 않고, 번개 드롭은 1에서 "+"가 막힙니다. 요청 중에는 그 줄의 버튼을 막습니다 |
| 삭제 | 줄의 X, "선택 삭제", "전체 삭제"(`DELETE /api/cart-items?cartItemIds=`). 선택·전체 삭제는 확인 후 삭제 |
| 품절 줄 | 흐리게 "품절". 금액은 "-". 수량은 바꿀 수 없고 X로 지울 수 있습니다. 재고가 0이거나 판매 중지인 상품입니다 |
| 결제 예정 금액 | 체크한 줄의 상품 금액(정가 합), 할인 금액, 합계. 가격은 주문할 때 확정됩니다 |
| 주문하기 | "주문하기 (체크 수개)". 체크한 항목으로 주문을 만들고(`POST /api/orders`) 주문 확인 화면으로 이동. 요청 중에는 버튼을 잠근다. 멱등 키는 응답을 받을 때까지 같은 값을 쓰고, 체크한 항목이나 수량이 바뀌면 새로 만든다 |
| 로딩·빈 상태·실패 | 로딩 `Skeleton`, 빈 장바구니 `Empty`, 첫 조회 실패 `Result`와 다시 시도. 수량 변경·삭제 실패는 서버 메시지 알림(예: 재고 초과 `CART_002` "재고보다 많이 담을 수 없습니다."), 수량은 다시 불러온 값 |
| 반응형 | lg 미만은 결제 예정 금액이 목록 아래로, md 미만은 줄이 두 줄(상품 정보 / 수량·금액·삭제) |

### 9 주문 확인 `/orders/:orderId/checkout`

| 항목 | 내용 |
|---|---|
| 담당 | 주문 도메인 |
| 진입·권한 | 장바구니 "주문하기" 뒤 이동. 로그인 필요(`RequireAuth`). 새로고침·재방문에도 같은 화면 |
| 데이터 | `GET /api/orders/{orderId}/checkout`. 주문할 때 확정한 가격이라 화면에 있는 동안 바뀌지 않습니다 |
| 위쪽 | "주문 확인", "결제 대기" 표시, 주문번호 |
| 주문 상품 | 이미지, 할인 표시(정가 취소선, 특가·번개 드롭), 상품 이름, 수량, 단가, 금액 |
| 결제할 금액 | 상품 금액(정가 합), 할인 금액, 결제할 금액 |
| 결제하기 | 연락처를 받아 결제창을 연다. 결제를 마치고 떠나는 이동은 나가기 확인 없이 진행한다 |
| 취소하기 | 확인 창("주문을 취소할까요?", "주문 취소"/"머무르기") 뒤 `PATCH /api/orders/{orderId}/cancel`. 성공하면 "주문이 취소되었습니다." 알림과 함께 장바구니로 이동, 실패하면 화면에 남는다 |
| 나가기 확인 | 앱 안 이동(뒤로 가기, 메뉴)은 확인 창("나가면 주문이 취소됩니다.", "나가기"/"머무르기")으로 붙잡는다. 나가기를 고르면 주문을 취소한 뒤 가려던 곳으로 간다. 새로고침·탭 닫기에는 묻지 않는다 |
| 로딩·실패 | 로딩 `Skeleton`. 결제 완료(`ORDER_007`)는 안내와 "주문 내역 보기", 취소(`ORDER_008`)는 안내와 "장바구니로 가기", 없는 주문·남의 주문(`ORDER_001`)은 404 안내, 그 밖의 실패는 다시 시도 |
| 반응형 | lg 미만은 결제할 금액이 목록 아래로, md 미만은 상품이 두 단(상품 정보 / 수량·단가·금액) |

## 공통 UI 상태

아래는 구현 시 구체화할 검증 기준 제안입니다.

- 조회: 로딩, 빈 결과, 첫 조회 실패·재시도.
- 제출: 입력 오류, 요청 진행 중, 성공·실패 후 입력 유지 정책.
- 접근: 비로그인·권한 없음·없는 리소스 구분.
- 동시 변경: 조회 이후 재고·권한·행사 상태가 바뀐 경우 서버 결과 반영.
- 반응형·접근성은 [프론트 규칙](../conventions/frontend.md)에 따릅니다.
- 개인 소유 데이터는 화면 숨김뿐 아니라 서버 접근 제어로 보호합니다.

## 연동과 미정 사항

닉네임·맛 선호는 회원, 재고는 재고 담당, 주문 당시 가격은 주문, 환불 금액·가능 여부는 결제·환불, 실제 할인가·행사 상태는 프로모션이 제공합니다. 분석 지표의 집계 기준과 제공 방식은 미정입니다.
