## 목적과 책임
- 해결할 사용자 문제: 냉장고 재료와 취향으로 요리를 추천받고, 레시피·재료·장보기를 물어본다.
- 이 도메인이 소유하는 데이터: 상담(`chat_sessions`), 메시지(`chat_messages`), 추천 카드(`chat_recommendations`), 직전 추천(Redis `chat:context:{sessionId}`), 답 받기 잠금과 하루 횟수(Redis).
- 다른 도메인에 맡기는 책임: 냉장고 재료(냉장고), 레시피·재료 사전(레시피·재료), 상품·할인 가격(상품·할인 행사), 장바구니 담기(장바구니), 요리 완료로 상담 끝내기(요리 기록).

## 메시지 처리
메시지 보내기는 아래 순서입니다.

1. 상담 확인: 본인 상담이 아니면 404 `CHAT_001`, 끝났으면 409 `CHAT_005`, 마지막 대화에서 30분(`app.chat.session-timeout`)이 지났으면 409 `CHAT_006`.
2. 답 받기 잠금: `chat:streaming:{sessionId}`에 SET NX + 요청 토큰으로 겁니다(유지 `app.chat.reply-lock-ttl` 150초). 실패하면 409 `CHAT_009`이고 하루 횟수를 쓰지 않습니다. 잠금은 스트림이 완료·오류·끊김 중 어느 쪽으로 끝나도 풀고, 토큰이 같을 때만 지웁니다.
3. [단어 차단](#단어-차단): 걸리면 안내 답만 보내고 끝냅니다.
4. 하루 횟수 차감: 실패하면 잠금을 풀고 그 오류(429 `CHAT_007`)를 돌려줍니다.
5. 의도 판단(`mode=AUTO`일 때): [의도 판단](#의도-판단), [이어지는 말](#이어지는-말).
6. 답: 의도마다 정해진 이벤트 순서로 보냅니다([AI 상담 API 명세](../../api/chat-api.md#메시지-보내기-sse)의 의도별 이벤트 순서 표).
7. 저장: 사용자 말과 답을 같이 저장하고 `done`을 보냅니다.

- Redis 장애면 503 `CHAT_008`입니다. 1~4의 오류는 스트림을 열기 전 JSON 응답이고, 그 뒤의 오류는 `error` 이벤트입니다.
- AI 호출은 메시지 하나에 의도 판단 1번 + 답 1번입니다. 추천 칩은 의도 판단이 없고, 서버가 정한 답은 답 생성이 없습니다. 단어 차단은 AI 호출이 없고, 서버 안내 의도는 의도 판단 1번만 합니다.
- 종료·만료된 상담도 본인 것이면 메시지 조회로 대화를 볼 수 있습니다.

## 안전 장치

### 단어 차단
- 잠금 뒤, 하루 횟수 차감 전에 보낸 말을 단어(`app.chat.safety.words`)로 거릅니다.
- 소문자로 바꾸고 공백·숫자·기호를 뺀 글로 비교합니다("시1발" → "시발"). 제외 목록(죽 먹고·마약김밥·폭탄주·칼국수·독일·약불·약간 등)은 먼저 지우고 봅니다.
- 자해 → 금지어(욕설·불법·위험) → 탈취(지시 무시·프롬프트 공개) 순으로 봅니다. "너는 이제부터 ~야"처럼 역할만 정하는 말은 거르지 않습니다.
- 걸리면 의도 판단·AI 답 없이 안내 답 하나를 `message`로 보내고 `done`을 보냅니다. 새 에러 코드는 없고 하루 횟수는 세지 않습니다.
- 안내 답:
  - 자해: "많이 힘드시죠. 혼자 견디지 마시고 자살예방상담전화 109(24시간, 무료)에 이야기해 주세요."
  - 금지어: "그 이야기는 도와드릴 수 없어요. 요리나 식재료에 대해 물어봐 주세요."
  - 탈취: "그 요청은 들어드릴 수 없어요. 요리나 냉장고 재료에 대해 물어봐 주세요."
- 보낸 말과 안내 답은 `chat_messages.filtered = true`로 저장합니다. 메시지 조회에는 그대로 나오고(필드 추가 없음), 다음 답의 이전 대화(최근 6개)와 상담 목록 첫 질문·미리보기에서는 빠집니다.
- 로그에는 걸린 종류만 남기고 보낸 말은 남기지 않습니다. 저장이 실패하면 `error` 이벤트이고, 세지 않았으므로 돌려줄 횟수도 없습니다.

### 서버 안내 의도
- `OFF_TOPIC`: 요리·식재료·냉장고·장보기·밀키트와 상관없는 요청("주식 추천해줘", "숙제 풀어줘", "파이썬 코드 짜줘").
- `BLOCKED`: 단어 목록 밖의 욕설·혐오·불법·위험, 지시 무시·프롬프트 공개 요청.
- `SELF_HARM`: 자해·자살을 말함.
- 셋 다 답 생성 AI 없이 서버 안내 답 하나를 `message`로 보내고 `done`을 보냅니다. 의도 판단 AI를 썼으므로 하루 횟수는 셉니다.
- 안내 답: `OFF_TOPIC` "저는 요리, 냉장고 재료, 장보기 상담만 도와드릴 수 있어요. 냉장고 재료로 만들 요리를 추천해 드릴까요?", `BLOCKED`는 단어 차단의 금지어 안내, `SELF_HARM`은 단어 차단의 자해 안내(109).
- 저장: `OFF_TOPIC`은 걸러진 표시 없이 저장해 이전 대화에 남고, `BLOCKED`·`SELF_HARM`은 `filtered = true`로 저장해 이전 대화·목록 미리보기에서 빠집니다.
- 다음은 OFF_TOPIC이 아닙니다: "주식으로 먹을 거 추천해줘", "장보기 목록 짜줘", "냉장고 정리 방법", 인사·짧은 잡담("안녕", "밥 먹었어?").
- 다음은 BLOCKED·SELF_HARM이 아닙니다: 역할만 정하는 말("너는 이제부터 요리사야"), 과장한 말("배고파 죽겠어", "죽여주는 맛").

### 건강 안내
- 보낸 말에 건강 관련 말(`app.chat.safety.health`: 당뇨·혈당·고혈압·신장질환·콩팥·투석·통풍·알레르기·임신·수유·복용·처방·약 먹 등, 공백 무시)이 있으면 답이 끝난 뒤 `message` 이벤트를 하나 더 보냅니다. 빈 줄 하나와 "일반적인 정보예요. 질환·알레르기·임신·복용 중인 약과 관련된 판단은 의사나 약사와 상담해 주세요."를 붙입니다. AI 답은 보지 않습니다.
- 약불·약간·약한 불·신장개업 등 제외 목록은 먼저 지웁니다. "약"·"신장"·다이어트는 넣지 않습니다.
- 일반 답, 추천 답(소개 글 끝, 곧 카드 바로 위), 레시피 자세히 답, 서버가 정한 답(후보 없음·밀키트만)에 붙입니다. 저장되는 AI 메시지도 `답 + "\n\n" + 안내`입니다. 추천 답의 AI 소개 글은 그대로 둡니다.
- 안전 장치 안내(단어 차단, OFF_TOPIC·BLOCKED·SELF_HARM)와 답 조각이 없는 실패(`CHAT_010`)에는 붙이지 않습니다. 막지 않고 하루 횟수도 셉니다.

### 링크 지우기
- AI가 만든 답(일반·추천·레시피 자세히)에서 `http://`·`https://`·`www.`로 시작하는 링크와 도메인 형태(영문·숫자 이름 + `.com .net .org .kr .co.kr .io .me .shop .info .app .dev .ly`, 뒤 경로 포함)를 지웁니다.
- "(링크 생략)" 같은 말은 넣지 않고, 링크 앞 공백과 링크만 있던 괄호도 같이 지웁니다.
- 조각 경계에서 쪼개진 링크("https:/" + "/naver.com")도 지웁니다. 영문이 든 끝 글자 묶음만 다음 조각까지 잠시 모아 두고, 한글·숫자·문장 부호는 바로 보냅니다. "1.5배", "3.5cm", "약 2.5kg"은 그대로입니다.
- 화면에 보내는 글과 저장되는 글(소개·카드 설명) 모두 지운 뒤의 글입니다. 추천 답은 `[소개]`·`[n]`으로 나누기 전에 지웁니다. 서버가 정한 글은 거치지 않습니다.
- 링크만 있던 답은 빈 답으로 보고 `CHAT_010`을 보내며 하루 횟수를 돌려줍니다.

## 알레르기
- "○○ 알레르기/알러지", "○○ 못 먹어", "○○ 먹으면 안 돼"(`app.chat.safety.allergy`)의 ○○을 추천(새 추천·다시 추천·추천 칩)에서 뺄 재료로 더합니다. AI가 뺄 재료로 넣지 않아도 서버가 확인합니다.
- ○○은 묶음 말(`app.chat.safety.allergy-groups`: 견과류·갑각류·유제품·달걀·계란·밀가루)이거나 재료 사전에 이름이 그대로 있을 때만 씁니다("매운 거 못 먹어"의 "거"는 버림). 조사("새우를")는 떼어 보되, 붙은 이름("오이")을 먼저 봅니다.
- 넓히기: 재료 사전에서 이름에 ○○이 들어 있는 재료로 넓힙니다(땅콩 → 땅콩가루·땅콩버터·땅콩잼, 새우 → 건새우·새우젓). 한 글자(게·잣·굴)는 그 글자로 시작하는 재료만입니다(게살·잣가루·굴소스).
- 넓히지 않는 것:
  - 같은 계열이 아닌 이름은 재료마다 정해 그 재료를 넓힐 때만 뺍니다(`app.chat.safety.allergy.not-same-kind`: 땅콩 → 땅콩호박, 굴 → 굴비, 마 → 마늘·마요네즈, 김 → 김치, 배 → 배추, 게살 → 멍게살 등). "마늘 알레르기"면 마늘가루는 뺍니다.
  - 대신 쓰는 재료(우유 → 아몬드우유, 버터 → 땅콩버터). 땅콩버터는 땅콩·견과류 알레르기에서 빠집니다.
  - 땅콩 ↔ 콩처럼 이름이 비슷한 다른 재료.
- 견과류 묶음에는 마카다미아도 있습니다.
- 이번 말과 이 상담의 사용자 말(안전 장치로 걸러진 말은 뺌)을 모두 봅니다. 그래서 같은 상담에서는 다시 추천("다른 거", "오이 넣어도 돼" 뒤에도)·새 추천 모두 계속 뺍니다. 뺄 재료라 콕 집은 요리여도 뺍니다(피할 맛과 다름). 고른 재료에 있으면 고른 재료에서도 뺍니다.
- 밀키트도 연결 레시피가 뺄 재료를 쓰면 빼고, 연결 레시피가 없으면 상품 이름에 뺄 재료 이름(두 글자 이상)이 있으면 뺍니다.
- 추천 답(카드·후보 없음·밀키트만) 끝, 곧 카드 바로 위에 "땅콩이 들어간 레시피는 뺐어요. 양념이나 가공품에 성분이 들어 있을 수 있으니 재료를 꼭 확인해 주세요."를 붙입니다(여러 개면 "땅콩·새우가 …"). 건강 안내도 붙으면 같은 메시지에 한 줄 바꿔 이어 붙이고, 저장 글에도 같이 들어갑니다.
- 알레르기 재료는 맛 부딪힘 규칙과 상관없이 계속 뺍니다.

## 의도 판단

### 의도 종류
| 의도 | 뜻 | 나오는 때 |
|---|---|---|
| `RECOMMEND` | 새 추천 | 늘 |
| `GENERAL` | 일반 질문 | 늘. AI 의도 판단이 실패해도 GENERAL(거절하지 않음) |
| `REFINE` | 다시 추천("좀 더 매운 걸로", "다른 거 없어?", "국물 말고 볶음으로") | 직전 추천 카드가 있을 때 |
| `RECIPE_DETAIL` | 추천한 레시피 하나 자세히("두 번째 거 어떻게 만들어?", "아까 그 깐풍기 시간 얼마나 걸려?") | 직전 추천 카드가 있을 때 |
| `FRIDGE` | 냉장고 보기 | 늘 |
| `SHOP` | 사기 | 늘 |
| `OFF_TOPIC`·`BLOCKED`·`SELF_HARM` | [서버 안내 의도](#서버-안내-의도) | 늘 |

- 메시지를 보낼 때 같은 상담의 최근 3턴(메시지 6개)과 직전 추천을 읽어 의도를 정합니다.
- 추천 칩(`mode=RECOMMEND`, [알아서 추천해줘]·[이 재료로 추천받기])은 의도 판단 없이 추천합니다. `AUTO`(기본)는 AI가 메시지를 읽어 정합니다.
- `selectedIngredientIds`는 내 냉장고에서 고른 재료 ID입니다(null·중복 제거). `useSelectedOnly=true`면 고른 재료를 하나도 안 쓰는 레시피는 추천하지 않습니다.

### OFF_TOPIC 되살리기
- AI가 `OFF_TOPIC`이라고 해도 보낸 말에 아래 중 하나가 있으면 거절하지 않습니다: 음식 말(`app.chat.words.food`: 먹·요리·레시피·밥·반찬·끼니·아침·점심·저녁·야식·간식·재료·냉장고·장보기·밀키트, 공백 무시), 분류 단어(묶음 말 포함), 재료 사전 이름, 레시피 이름.
- 달라는 말(`app.chat.words.ask.request`)이 있으면 `RECOMMEND`(맛·분류 보정 포함), 없으면 `GENERAL`입니다.
- 예) "주식으로 먹을 거 추천해줘" → 추천, "장보기 목록 짜줘" → 일반 답, "주식 추천해줘" → OFF_TOPIC 그대로.
- `BLOCKED`·`SELF_HARM`은 음식 말이 있어도 되살리지 않습니다.

### 서버 단어 안전망
AI 의도 위에 서버가 단어로 한 번 더 봅니다. 이름만 말하기·밀키트 달라는 말처럼 의도를 바꾸는 규칙은 AI가 GENERAL로 본 말에만 겁니다.

- **밀키트 말**: AI가 일반 대화로 본 말은 밀키트를 말하고 달라는 말(추천·뭐 있·보여줘 등)이 있으며 묻는 말(기준·어떻게·왜·방법·얼마나·보관·가격·차이 등, `app.chat.words.ask`)이 없을 때만 추천으로 바꿉니다("밀키트 추천 기준이 뭐야?"는 일반 답). 밀키트와 같이 쓴 "있어·있나·있을까·없어·뭐가 좋아·살 만한"도 달라는 말로 봅니다.
- **이름만 말하기**: 묻는 말 없이 이름만 말한 짧은 말(공백 뺀 15자 이하: "국물 밀키트", "디저트", "두부", "김치찌개")도 밀키트·분류(묶음 말 포함)·재료 사전·레시피 이름 중 하나가 있으면 추천으로 바꿉니다.
- **분류 단어 보정**: "국물" → 국·찌개·전골·수프·스튜처럼 묶음 말(`app.chat.words.category`)도 씁니다. 키워드가 모두 고른 분류 이름이면 요리 이름이 아니므로 키워드를 비웁니다.
- **요리 이름**: 첫 키워드가 메시지에 띄어쓰기와 상관없이 그대로 있을 때만 그 키워드를 요리 이름으로 씁니다.
- **맛 단어**: 맛 단어(`app.chat.words.taste`) 앞의 안·덜, 뒤의 말고·않·싫·없이·못 먹·빼 줘·제외·안 들어간·없는(공백 무시)은 피할 맛입니다("매운 거 못 먹어", "매운 건 빼줘"). AI가 피할 맛으로 낸 맛은 원하는 말이 확실히 붙었을 때(앞의 "더", 뒤의 걸로·먹고 싶·땡·원해 등)만 서버가 원하는 맛으로 바꿉니다. 이번 말에 피할 맛 단어가 있으면 다른 맛 조건은 지우지 않고, "맛 상관없이"·"맛은 아무거나"는 맛 조건을 지웁니다.
- **냉장고 보기·사기**(`app.chat.words.fridge-shop`): AI가 `RECOMMEND`·`GENERAL`로 봐도(OFF_TOPIC을 음식 말로 되살린 것 포함) 아래처럼 바꿉니다.
  - 냉장고 보기 말(남았·아직 있·냉장고에 뭐·냉장고에 있·냉장고에서·버려야·유통기한 지난·소비기한 지난·처리해야 할 거·처리할 거)이면 `FRIDGE`.
  - 사기 말(사고 싶·어디서 사·장바구니·담아·주문해)이나 할인 말(세일·할인·특가·번개)이면 `SHOP`. 둘 다 있으면 FRIDGE.
  - 묻는 말(`app.chat.words.ask.question`, "먹어도 돼·괜찮" 포함)이나 요리 말(추천·만들·해먹·요리·레시피·뭐 먹·먹지·먹을까)이 있으면 바꾸지 않고, AI가 FRIDGE·SHOP으로 봤어도 요리 말이 있으면 추천으로 둡니다.
  - 짜 달라는 말(짜줘·짜줄)은 일반 답으로 둡니다.
  - 예) "냉장고에 있는 재료로 뭐 먹지" → 추천, "냉장고에서 꺼낸 고기 어떻게 해동해?"·"유통기한 지난 거 먹어도 돼?"·"주문한 거 언제 와?" → 일반 답, "두부 있으면 두부 요리 추천해줘" → 추천.

## 이어지는 말

### GENERAL
- 최근 3턴을 이전 대화로 넣어 답합니다. 이전 대화의 AI 답은 300자까지이고 보여 준 카드 이름을 포함합니다.

### REFINE (다시 추천)
- 직전 추천 조건에 이번 말을 합쳐 다시 추천합니다. 맛·분류·시간·키워드는 AI가 낸 최종값(비운 칸은 직전 값)을 쓰고, 재료는 직전 선택 재료를 이어 갑니다.
- "매운 거 말고"처럼 조건을 빼는 말은 의도의 `removed`(TASTE, CATEGORY, MAX_MINUTES, KEYWORD, INCLUDE, EXCLUDE)에 있는 조건의 직전 값을 지웁니다.
- 요리 이름·원한 표현은 이어 가지 않습니다. 그래서 "김피탕 레시피는 없어서…" 안내가 다시 나오지 않습니다.
- 맛을 피하는 말은 `avoidTastes`(피할 맛)로 받아 그 맛인 레시피를 후보에서 빼고(3개가 안 되면 뒤에 채움) 다시 추천에서도 이어 갑니다. 원하는 맛·회원 선호 맛보다 피할 맛이 앞섭니다.
- 매운 레시피는 맛 데이터 SPICY 또는 매운 재료(`app.chat.candidate.spicy-ingredients`, 재료 사전 이름·레시피에 적힌 이름 모두, 그냥 "고추"는 제외)로 가립니다.
- 직전 카드는 후보에서 빼고, 빼서 3개보다 적으면 뒤에 다시 넣습니다.
- 직전 조건이 없으면(Redis 만료·장애) 이번 말만으로 새 추천합니다.

### 맛 부딪힘
- 원하는 맛은 직전 맛에 이번 맛을 쌓습니다("매운 걸로" → "단 것도" → 매운맛 + 단맛).
- 맛이 부딪히면 이번 말에 나온 맛(서버 맛 단어 확인, AI가 앞 대화에서 따라 넣은 맛과 구분)을 따릅니다.
- 같은 맛이 원하는 맛·피할 맛에 둘 다 있으면 이번 말 쪽만 남깁니다("매운 거 말고" → "좀 더 매운 걸로" → 원하는 맛 SPICY, 피할 맛 없음).
- 이번에 원한 맛과 반대인 맛(`app.chat.words.taste-opposites`: MILD ↔ SPICY, MILD ↔ SALTY. 단맛·감칠맛은 반대 없음)은 원하는 맛에서 지웁니다("짭짤한 거" → "담백한 거로" → MILD만).
- 새 추천은 원래 이번 말의 맛만 씁니다.

### RECIPE_DETAIL (레시피 자세히)
- 물어본 레시피를 직전 카드 이름 → 직전 카드 번호 → 이 상담의 최근 추천 30개 이름 순으로 찾고, 못 찾으면 GENERAL로 답합니다.
- 카드 1개의 `reason`과 `description`은 모두 "물어보신 레시피예요"이고, 다시 불러와도 같습니다.
- AI에는 사용자 말 대신 질문 종류 `detailQuestion`(HOW_TO·TIME·INGREDIENTS·TIP·OTHER)으로 만든 질문을 넘깁니다. 레시피 정보에 있는 내용만 쓰고, 단계는 레시피대로 모두 "1. …" 한 줄씩 10줄까지 씁니다. 글은 표시 없이 그대로 `message`로 보냅니다.
- 레시피가 지워졌으면 카드 없이 "물어보신 레시피는 지금 볼 수 없어요. 다른 레시피를 물어봐 주세요."입니다.

### 직전 추천
- Redis `chat:context:{sessionId}`에 조건과 카드 레시피 ID를 둡니다. TTL은 30분이고 답을 저장할 때마다 다시 늘립니다.
- 새 추천·다시 추천 답을 저장하면 바뀌고, 일반·레시피 자세히 답은 바꾸지 않습니다(레시피 자세히 뒤의 "첫 번째 거는?"도 직전 추천 기준).
- Redis 장애면 문맥 없이 답합니다.

## 추천 카드

### 카드 이유
- `reason`은 25자 안팎 한 줄입니다. 우선순위: 요리 이름 키워드·요청 일치 > 선택 재료 > 임박 재료 > 겹친 맛.
- 예: "찾으신 냉면 요리예요", "버섯·두부가 주재료예요", "내일까지인 고추를 쓸 수 있어요".
- `matchedTastes`는 메시지로 말한 맛, 없으면 회원 선호 맛입니다.
- `missingSelectedIngredients`는 고른·말한 재료 중 냉장고에 없는 것입니다. 같은 종류로 넓혔으면 레시피에 쓰인 이름입니다(버섯 → 표고버섯).

### 카드 설명
- 추천 답은 `[소개]`·`[1]`~`[3]` 표시로 나눠 보냅니다. 소개 글은 `message`, 카드 설명은 `recommendation_text`입니다.
- AI가 표시를 빼먹으면 전체가 `message`(소개)로 오고 카드 설명은 비어 있습니다. 설명이 빠진 카드는 화면에서 카드 이유 한 줄로 대신하고, 서버는 빠진 번호를 경고 로그로 남깁니다.
- 후보 검색이 실패하면 카드 없이 일반 답을 합니다.

### 장볼 재료 상품
- `missingIngredients`는 기본 양념을 뺍니다. `product`는 그 재료로 담을 상품이고, 판매 상품이 없으면 null입니다.
- 판매 중지 상품은 넣지 않고 품절 상품은 `soldOut=true`로 넣습니다.
- 재료 하나에 상품이 여러 개면 살 수 있는 것 → 할인 중 → 판매 단가 낮은 순 → 상품 id 순으로 하나를 고릅니다.
- 가격·품절은 상품 목록·장바구니와 같은 판매가 계산을 씁니다. 다시 불러올 때는 지금 가격·품절 기준으로 다시 계산합니다.
- 담기는 장바구니 담기 API(`POST /api/cart-items`, productId·quantity)를 그대로 씁니다.

### 밀키트 카드
- 사용자 말에 밀키트 단어(`app.chat.words.mealkit`, 공백 무시, 부정어는 맛 단어와 같음)가 있으면 밀키트를 함께 고릅니다. 의도 프롬프트는 바꾸지 않습니다.
- "밀키트"를 말함("밀키트 추천해줘", "국물 밀키트"): 레시피 카드 없이 밀키트 최대 3개입니다. 글은 AI 없이 서버 문장 하나입니다. 고를 밀키트가 없으면 "지금은 추천드릴 밀키트가 없어요." 안내를 맨 앞에 두고 레시피 카드를 보여 줍니다.
- 번거로워하는 말만 있음("간단하게·간편·빨리·귀찮·요리하기 싫"): 레시피 카드 3장 + 밀키트 1개입니다. 레시피 카드와 같은 레시피 밀키트는 뺍니다.
- "밀키트 말고"처럼 부정이면 밀키트를 고르지 않습니다. 밀키트를 보여 줄 때는 키워드·요리 이름에서 "밀키트"를 뺍니다.
- 고르기:
  - 판매 중이고 살 수 있는 것만 고릅니다. 냉장고에 있는 밀키트는 품절이어도 둡니다.
  - 연결된 레시피가 피할 맛이면 뺍니다. 피할 맛이 매운맛이면 레시피 매운 정도 MILD·HOT도 뺍니다.
  - 순서: 요청 일치 수(연결된 레시피의 분류·원하는 맛·요리 이름) → 냉장고에 있는 밀키트 → 이 상담에서 아직 안 보여 준 것 → 레시피 연결 있음 → 냉장고 재료와 겹치는 수 → 할인 중 → 판매 단가 낮은 순 → 상품 id.
  - 냉장고에 있는지는 `fridge.product_id`로 보고, product_id가 없는 예전 줄은 등록 이름(raw_name, 공백 무시)으로 봅니다. 기한이 지난 줄은 넣지 않습니다.
  - 레시피 연결도 없고 요청 조건도 안 맞는 밀키트는 한 장까지만 보여 주고(냉장고 밀키트는 세지 않음), 3장이 안 차면 빈자리로 둡니다.
- 서버 문장:
  - 레시피 카드 아래 한 장이면 `description`이 "요리하기 번거로우면 ○○ 밀키트로 간편하게 드셔 보세요."이고, 밀키트만 보여 주면 null입니다.
  - 냉장고 밀키트가 있으면 밀키트만 보여 주는 글에 "냉장고에 이미 있는 밀키트는 먼저 보여 드려요."를, 레시피 카드 아래 한 장이면 "요리하기 번거로우면 냉장고에 있는 ○○ 밀키트로 …"를 씁니다.
- `inFridge`가 true면 화면은 "냉장고에 있어요" 태그를 붙이고 담기를 숨깁니다. `fridgeDDay`가 D-3 이내면 임박 태그입니다. 다시 불러올 때도 `inFridge`·`fridgeDDay`는 지금 냉장고 기준입니다.

## 냉장고 보기와 사기

### 냉장고 보기 (FRIDGE)
- 예: "냉장고에 뭐 있어", "밀키트 뭐 남았어", "두부 아직 있어?", "곧 버려야 할 거 있어?". 답 생성 AI 없이 서버 문장으로 답합니다.
- 범위(`fridgeScope`):
  - ALL: 기본 양념을 뺀 전체.
  - MEALKIT: 밀키트 줄만.
  - IMMINENT: D-3 이내·지난 줄.
  - SEASONING: 기본 양념 줄만("기본 양념 뭐 있어?"). 양념 말(`app.chat.words.fridge-shop.seasoning`: 기본 양념·조미료)이 있으면 서버도 이 범위로 정합니다. "양념"만으로는 보지 않고, 냉장고를 말하지 않은 "조미료 뭐 있어?"도 냉장고 보기입니다. 답 끝에 "살 수 있는 조미료가 궁금하시면 '간장 사고 싶어'처럼 이름으로 말씀해 주세요."를 붙이고, 이 말은 찾을 재료 이름으로 보지 않습니다.
- 재료를 말했으면(`includeIngredients`) 범위와 상관없이 그 재료(같은 종류 포함, 기본 양념도) 줄만 봅니다. 사전에 없는 이름·밀키트 이름은 등록 이름에 그 이름이 들어간 줄로 봅니다.
- 순서는 소비기한 순이고 지난 줄은 맨 아래입니다. 카드는 최대 10장입니다.
- 전체 보기(ALL, 재료 이름 없음) 문장: 가짓수를 먼저 말하고 D-3 이내만 앞 3개 + "외 N개"로 씁니다.
  - 예: "냉장고에 재료 12가지가 있어요. 곧 끝나는 건 대파(오늘까지), 버섯(오늘까지), 서울우유(내일까지) 외 6개예요. 양파, 깻잎, 고추 외 4개는 지났어요."
  - 곧 끝나는 재료가 없으면 "소비기한이 곧 끝나는 재료는 없어요."
- 임박·밀키트 보기와 이름으로 물은 답의 문장:
  - 예: "냉장고에 두부(내일까지), 대파(3일 남음), 된장국 밀키트가 있어요. 우유는 지났어요."
  - 남은 날은 D-3 이내만 씁니다(오늘까지·내일까지·모레까지·3일 남음). 남은 줄은 앞 6개, 지난 줄은 앞 3개까지 쓰고 나머지는 "외 N개"입니다.
  - 말한 재료가 없으면 "두부는 지금 냉장고에 없어요." + 그 재료의 상품 카드.
  - 보여 줄 줄이 없으면 "냉장고에 등록된 재료가 없어요." / "냉장고에 밀키트가 없어요." / "소비기한이 곧 끝나는 재료는 없어요."
- `FridgeItemCard.name`은 일반 재료면 재료 이름, 밀키트·직접 입력이면 등록 이름입니다. `imageUrl`은 밀키트 줄이면 연결 상품 이미지입니다.

### 사기 (SHOP)
- 예: "당근 사고 싶어", "두부 어디서 사", "대파 장바구니에 담아줘". 답 생성 AI 없이 서버 문장으로 답합니다. 서버는 장바구니에 직접 담지 않고 카드의 담기로 담습니다.
- 이름(`includeIngredients`, 비었으면 서버가 말에서 재료 사전 이름을 찾음)마다 상품 하나를 고릅니다.
  - 재료 사전 이름이면 장볼 재료 상품과 같은 방법입니다(살 수 있는 것 → 할인 중 → 판매 단가 낮은 순).
  - 사전에 없거나 이어진 상품이 없으면 상품 검색 1등으로 보충합니다(ES를 쓰지 않으면 DB 검색, 검색이 실패하면 상품 없음).
- 서버 문장 예: "당근은 아래 상품으로 담을 수 있어요. 참치캔은 지금 파는 상품이 없어요." 이름을 못 뽑았으면 "어떤 재료를 찾으시는지 이름으로 말씀해 주시면 살 수 있는 상품을 찾아 드릴게요."
- `ProductCard.name`은 말한 이름입니다. 상품 검색으로 찾았거나 다시 불러온 카드는 `unitAmount`·`unit`이 null입니다.

### 할인 질문
- 말에 할인 말(`app.chat.words.fridge-shop.sale`: 세일·할인·특가·번개)이 있으면 할인 중인 상품만 봅니다. "재료·밀키트·상품"은 찾을 이름으로 보지 않습니다.
- 이름이 없을 때("세일하는 재료 있어?", "할인하는 밀키트 뭐 있어?", "세일하는 거 있어?"):
  - 진행 중 할인 전체에서 밀키트 단어면 밀키트만, "재료"면 재료 상품만, 둘 다 없으면 모두 봅니다. 지금 살 수 없는 것(상품 품절·번개 드롭 수량 0)은 뺍니다.
  - 할인율 높은 순 → 상품 id 순으로 3장까지 보여 주고, 더 있으면 "더 많은 할인 상품은 재료/밀키트 메뉴에서 확인해 주세요."를 붙입니다.
  - 문장: "지금 할인 중인 재료예요." / 없으면 "지금 할인 중인 재료가 없어요." 상품 카드의 name은 상품 이름입니다.
- 이름이 있을 때("두부 세일해?"): 사기와 같이 상품을 찾고 "두부는 지금 할인 중이에요." / "대파는 지금 할인 중이 아니에요."로 답합니다.

## 저장
| 답 | 저장하는 것 | 다시 불러올 때 |
|---|---|---|
| 추천 | 소개 글이 AI 메시지 content, 카드 설명이 `chat_recommendations.description` | `recommendations[].description`. 장볼 재료 상품은 지금 가격·품절 기준 |
| 레시피 자세히 | 글이 content, 카드 1개가 그 메시지의 `recommendations` | 같음 |
| 밀키트 | 레시피 카드 다음 순서로 product_id와 description | `mealkits`. 지금 가격·품절 기준, 판매 중지된 밀키트는 빠짐 |
| 사기·냉장고 보기의 상품 | product_id와 description(말한 이름) | `products`. 지금 가격·품절 기준, 판매 중지된 상품은 빠짐 |
| 냉장고 보기 | 서버 문장만. 냉장고 카드는 저장하지 않음 | 그때 상태의 글만 보임 |

- 밀키트 카드와 재료 상품 카드는 같은 product_id 칸에 저장하므로, 다시 만들 때 상품 종류(MEALKIT·INGREDIENT)로 나눕니다.
- 냉장고 카드: 화면은 답을 다 받은 뒤 기록을 다시 받아 그리므로, `done`의 `assistantMessageId`에 받은 냉장고 카드를 붙여 그 화면에 있는 동안만 보여 줍니다.
- 카드가 없으면 메시지만 저장합니다. 안전 장치로 걸러진 답은 `filtered = true`로 저장합니다.

## 하루 횟수
- 하루 `app.chat.daily-limit`(30)번입니다. 이어지는 말도 메시지 하나에 1번입니다.
- 세지 않음: 단어 차단(AI를 쓰지 않음).
- 셈: 서버 안내 의도(의도 판단 AI를 씀), 건강 안내가 붙은 답.
- 돌려줌: 첫 답 조각을 보내기 전에 실패한 경우. `recommendations`는 첫 조각으로 치지 않으므로, 카드를 보낸 뒤 설명 글 첫 조각 전에 실패해도 돌려줍니다. 링크만 있던 빈 답(`CHAT_010`)도 돌려줍니다.

## 상담 목록
- 본인 상담만, 최근 시작순(startedAt 내림차순, 같으면 id 내림차순)입니다. 메시지가 0개인 상담은 목록·건수에서 빠집니다.
- 상태:
  - ACTIVE: 진행 중이면서 마지막 대화가 30분(`app.chat.session-timeout`) 안.
  - ENDED: 종료(COMPLETED) + 만료(EXPIRED).
  - 시간이 지났는데 아직 ACTIVE로 남은 상담(다음 상담 시작 때 만료 처리됨)은 status를 EXPIRED로 주고 ENDED 필터·종료 건수에 넣습니다.
- `firstQuestion`은 첫 USER 메시지, `lastMessagePreview`는 마지막 메시지(역할 무관)의 앞 50자이고 코드 포인트 기준으로 자릅니다.
- 걸러진 메시지(단어 차단, BLOCKED·SELF_HARM)는 `messageCount`에 세고, `firstQuestion`·`lastMessagePreview`는 걸린 메시지를 빼고 고릅니다. 걸린 메시지뿐인 상담은 목록에 남고 두 값이 null입니다.
- `recommendedRecipes`는 상담마다 최근 추천 레시피 최대 3개입니다.
- 쿼리: 세션 목록 1회 + 메시지 수·첫 질문·마지막 메시지 1회(그룹 집계 + 상관 서브쿼리) + 탭 건수 1회(조건 합계) + 추천 1회 + 레시피 이름 1회. 전체 개수가 필요할 때만 count 1회를 더합니다.
- 상담 시작: 진행 중 상담이 있으면 그 상담을 돌려줍니다. 30분이 지났으면 만료시키고 새로 만듭니다. 동시 요청으로 유니크 제약(`uk_chat_sessions_active_member_id`)에 걸리면 먼저 만든 상담을 다시 읽어 돌려줍니다.
- 상담 단건의 `cookedRecipe`: 요리 완료로 끝난 상담만 `cooking_logs.chat_session_id`로 요리 기록 1번 + 레시피 이름 1번 읽습니다. 직접 끝냈거나 진행 중·만료거나 레시피가 지워졌으면 null이고, 상담 시작·끝내기 응답은 늘 null입니다.

## 변경 이력
- 하루 횟수: "AI를 썼으면 센다"로 바꿨습니다. 서버 안내 의도는 세고, 단어 차단은 세지 않습니다.
- 밀키트 고르기: 냉장고에 있는 밀키트를 빼지 않고 앞에 둡니다.
- 요리 완료의 상담 잇기: 잇지 못하는 상담이어도 오류 없이 요리 완료를 진행합니다([요리 기록 설계](cooking.md)).
