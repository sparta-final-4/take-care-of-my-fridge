# 회원 도메인 설계

상태: 초안 · 담당: 개인 담당(회원·인증·관리자) · 관련 화면: U-01~U-05, A-10 · 근거: S4, 2026-10-14 사용자 결정

## 목적과 책임

- 해결할 사용자 문제: 회원이 이메일로 가입·로그인하고, 자기 정보와 맛 선호를 관리합니다. 관리자는 가입한 회원을 관리자로 승격합니다.
- 이 도메인이 소유하는 데이터와 정책: 계정(이메일·비밀번호 해시·닉네임·역할·상태), 맛 선호, 로그인 세션, 역할 검사.
- 다른 도메인에 맡기는 책임: 후기 표시(후기), 주문 내역(주문), 냉장고(냉장고), 알림 수신(알림). 이 도메인은 닉네임·맛 선호·역할을 제공만 합니다.

## 기능·정책

| 요구사항 | 정책·제약 | 근거 | 확정 상태 |
|---|---|---|---|
| 회원가입 | 이메일·비밀번호·닉네임 필수. 약관 동의 없음. 역할은 항상 USER | U-02, Q-09 | 결정 |
| 이메일·닉네임 중복 | 둘 다 중복 불가. 화면에서 중복 확인 후 값을 바꾸면 다시 확인. 가입 요청 때 서버가 최종 검증 | U-02 | 결정 |
| 비밀번호 규칙 | 8~30자, ASCII 영문·숫자·특수문자 각각 필수, 공백·한글 제외 | U-02, 2026-10-16 사용자 확정 | 결정 |
| 이메일 인증 | 도입 여부 미정 | Q-09 | 미정 |
| 맛 선호 | 짠맛·단맛·매운맛·감칠맛·슴슴한맛 중 0개 이상. 가입·마이페이지에서 수정 | U-02, U-04 | 결정 |
| 로그인 실패 문구 | 없는 이메일과 틀린 비밀번호를 같은 문구로 안내 | U-01 | 결정 |
| 로그인 유지 | 30분 동안 사용이 없으면 로그아웃 | Q-01 | 결정 |
| 관리자 진입 | 별도 로그인 화면 없음. ADMIN이 로그인하면 관리자 화면으로 이동 | U-01 | 결정 |
| 관리자 승격 | ADMIN만 실행. 정지 계정은 승격 불가. 첫 관리자는 시드 데이터 | A-10 | 결정 |
| 권한 해제 | 이번 범위에 없음 | A-10 | 제외 |
| 회원 탈퇴 | 이번 범위에 없음 | U-04 | 제외 |
| 계정 정지 | 상태값은 있으나 정지 처리 주체·화면 미정 | A-10 | 미정 |

## 상태와 전이

| 현재 상태 | 행동 | 조건 | 다음 상태 | 실패 |
|---|---|---|---|---|
| (없음) | 회원가입 | 이메일·닉네임 미사용, 입력 규칙 통과 | ACTIVE, USER | 중복이면 해당 칸 오류, 계정 미생성 |
| ACTIVE | 로그인 | 비밀번호 일치 | ACTIVE, 세션 생성 | 불일치면 공통 실패 문구 |
| SUSPENDED | 로그인 | 비밀번호 일치 | 변화 없음 | 정지 안내, 세션 미생성 |
| ACTIVE · USER | 관리자 승격 | 요청자가 ADMIN | ACTIVE · ADMIN | USER가 요청하면 403, 작업 이력에 DENIED |
| SUSPENDED · USER | 관리자 승격 | | 변화 없음 | 승격 거부 |
| ACTIVE | 정지 | 처리 주체 미정 | SUSPENDED, 모든 세션 폐기 | 미정 |

세션 상태: 생성 → (30분 미사용 또는 만료) 만료 → 로그아웃·비밀번호 변경·정지 시 폐기(revoked_at 기록).

## 대표 흐름

- 정상 가입: 형식 확인 → 이메일 중복 확인 → 닉네임 중복 확인 → 계정 생성(ACTIVE·USER) → 맛 선호 저장 → 가입 완료 화면.
- 동시 가입: 두 사람이 같은 닉네임을 동시에 확인·가입하면 DB 유일 제약으로 한 명만 성공. 나머지는 중복 문구.
- 권한 거부: USER가 관리자 API를 호출하면 403, 데이터 변화 없음, 관리자 작업 이력에 DENIED 기록.
- 비밀번호 변경: 현재 비밀번호 확인 → 변경 → 다른 기기 세션 폐기. 현재 세션 유지 여부는 Q-08.
- 세션 만료: 401 → 갱신 시도 → 실패하면 U-05 "로그인 필요". 세부 흐름은 Q-02.

## 데이터·API·이벤트

- ERD·데이터 사전: [ERD](../../database/erd.md), [데이터 사전](../../database/data-dictionary.md)의 members, member_tastes, refresh_sessions, admin_audit_logs.
- 제공·호출 API: [API 계약](../../api/api-spec.md)의 회원 API 제안.
- 발행·수신 이벤트와 중복 처리: 없음. 후기는 회원 정보를 조회해 표시합니다.
- 보관 기간·삭제 정책: 회원 탈퇴가 없어 계정 삭제 없음. 폐기된 세션 정리 주기는 미정.

## 구현 방향

- 트랜잭션 범위: 회원 생성과 맛 선호 저장을 한 트랜잭션으로 묶습니다. 승격과 작업 이력 기록도 함께 커밋합니다.
- 동시성 제어 필요성과 근거: 중복 가입은 DB 유일 제약으로 막습니다. 별도 분산 락은 두지 않습니다.
- 외부 I/O 및 실패 복구: 이메일 인증을 도입하면 메일 발송을 트랜잭션 밖(AFTER_COMMIT)으로 분리합니다.
- 성능 목표와 측정 방법: 미정.
