# 상품 삭제 한 기능으로 문서 연결 이해하기

> **학습용 가상 예시** — 실제 구현·팀 결정·테스트 결과가 아닙니다. 상품 논리 삭제 기능의 설계가 구체화된 상황을 가정했습니다. 실제 문서로 옮길 때 정책과 증거를 다시 확인하세요.

## 예시 기능

관리자가 판매 중인 일반 상품을 삭제한다. 고객에게는 숨기되 과거 주문과 관리자 기록은 보존한다. 진행 중인 행사 상품 처리는 별도 협의로 남긴다.

---

## 1. 구현 전에

[기획서](docs/requirements/project-plan.sample.md)에서 사용자 문제와 REQ-PRODUCT-DELETE-01~05를 정합니다. [화면 명세](docs/requirements/screens.sample.md)에서 확인 모달·진행 중·성공·실패를 정합니다.

이 시점에는 “개발 완료”가 아니라 “요구사항 합의”로 기록합니다.

---

## 2. 책임과 계약을 정하기

[상품 도메인](docs/architecture/domains/product.sample.md)에서 상태 전이와 트랜잭션을, [API](docs/api/api-spec.sample.md)에서 200·401·403·404·409를 정합니다. [ERD](docs/database/erd.sample.md)와 [데이터 사전](docs/database/data-dictionary.sample.md)은 상품 행과 주문 스냅샷의 관계를 설명합니다.

“이미 삭제한 상품에 다시 요청하면 어떻게 되는가”도 이 단계에서 정합니다. 이 예시는 200·원래 삭제 시각 유지로 가정했습니다.

---

## 3. 선택 이유 기록하기

[ADR](docs/decisions/ADR-001-logical-delete.sample.md)에 물리 삭제, 논리 삭제, 별도 보관 테이블을 비교합니다. 단순히 “좋아서”가 아니라 과거 주문 조회·운영 추적이라는 요구사항과 연결합니다.

---

## 4. AI에 작업 맡기기

아래는 사용자가 실제 개발을 요청할 때 참고할 프롬프트 예시입니다. 이 샘플 작성 자체가 구현 요청은 아닙니다.

> A-01 상품 삭제를 구현해 줘. 먼저 공통·영역별 지침과 상품 도메인·API 계약을 읽어. REQ-PRODUCT-DELETE-01~05를 기준으로 기존 구현을 확인하고 변경 범위와 테스트를 정리해. 주문 영역 수정이 필요하면 사유와 범위를 먼저 알려줘. 완료 후 변경 파일·실행한 검증·미검증 항목을 작업 기록에 남겨.

실제로 사용할 때는 guide/의 예시 문서를 현재 프로젝트의 합의된 docs 문서로 바꿉니다.

---

## 5. 구현과 검증 기록하기

[테스트 전략](docs/testing/test-strategy.sample.md)의 입력·기대 결과를 검증합니다. [작업 기록](docs/worklogs/WORK-001-product-delete.sample.md)에는 AI에 맡긴 일과 개발자가 수정한 판단을 남깁니다.

삭제 성공 후 목록에 계속 나타나는 문제가 실제 발생하면 [문제 해결 예시](docs/troubleshooting/deleted-product-visible.sample.md)와 같은 구조로 재현·원인을 기록합니다. 발생하지 않은 사건은 실제 트러블슈팅으로 옮기지 않습니다.

---

## 6. 제출 자료로 정리하기

[README 예시](project-readme.sample.md)에 문제·개인 기여·선택 이유·검증 링크를 요약합니다. API 본문을 복사하는 대신 상세 문서로 연결합니다.

---

## 요구사항 추적표

| 요구사항 | 화면·계약 | 설계·검증 |
|---|---|---|
| 01 관리자만 변경 | A-01·A-02, API 401·403 | 서버 권한 검사, T-02·T-03 |
| 02 삭제 후 고객 목록 제외 | 목록 재조회, API 200 | DELETED 필터, T-01·T-08 |
| 03 관리자·과거 주문 보존 | 관리자 필터·주문 상세 | 논리 삭제·스냅샷, T-04 |
| 04 중복·동시 변경 처리 | 재시도·409 안내 | version·재요청 정책, T-05·T-06 |
| 05 감사 기록 | 작업자·시각·결과 | 성공 원자성·거부 기록, T-07 |

이 표는 “문서가 많다”를 “같은 요구사항이 어디서 검증되는가”로 바꿔 주는 안내입니다.
