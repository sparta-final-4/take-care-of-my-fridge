# 문서 운영 규칙 작성 예시

> **학습용 가상 예시** — 실제 구현·팀 결정·테스트 결과가 아닙니다. 상품 논리 삭제 기능의 설계가 구체화된 상황을 가정했습니다. 실제 문서로 옮길 때 정책과 증거를 다시 확인하세요.

**읽는 법**: 파일 문법보다 누가 언제 어떤 사실을 갱신하는지를 정합니다.

## 상태와 ID

예시의 요구사항은 REQ-PRODUCT-DELETE-01~05, 화면은 A-01·A-02, 테스트는 T-01~08로 연결한다. 문서 합의 상태와 코드 검증 상태를 따로 적는다.

예: “설계: 검토 완료(가상 사례) / 실제 코드: 없음 / 테스트: 미실행”.

---

## 한 변경으로 갱신할 문서

“이미 삭제된 상품 재요청을 성공 처리한다”는 정책을 바꾸면 도메인 상태표·API 응답·화면 안내·T-05를 함께 확인한다. 변경 이유가 구조적 선택이면 ADR을 연결한다. 작업 기록은 이 정책이 바뀐 계기와 실제 검증을 남긴다.

---

## 좋은 기록과 불충분한 기록

| 불충분한 문장 | 구체적으로 쓰는 방식 |
|---|---|
| 테스트 완료 | 실행 명령·환경·대상 커밋·결과·로그 위치를 기록 |
| 성능이 좋아짐 | 전후 같은 조건의 측정이 있을 때 수치와 조건을 함께 기록 |
| 오류 해결 | 재현 입력·원인·수정·같은 입력으로 재검증 결과 기록 |
| 팀이 결정함 | 실제 결정 날짜·참여자·합의 근거 기록 |

이 표는 작성 방법이다. 실제 테스트·합의가 없으면 미실행·미정으로 유지한다.
