# 상품 논리 삭제 — 기획서 예시

> **학습용 가상 예시** — 실제 구현·팀 결정·테스트 결과가 아닙니다. 상품 논리 삭제 기능을 가정한 문서이며, 실제 프로젝트에 적용하기 전 정책과 증거를 확인하세요.

**읽는 법**: 전체 기획서 중 한 기능의 범위를 충분히 구체화한 예입니다. 프로젝트 전체 계획에는 다른 기능과 일정·역할도 포함합니다.

## 문제와 사용자

관리자는 더 판매하지 않을 상품을 고객 목록에서 제외해야 한다. 기존 주문을 확인하는 고객과 운영자는 주문 당시 상품명·금액을 계속 볼 수 있어야 한다.

---

## 범위

| 구분 | 내용 |
|---|---|
| **포함** | ADMIN 삭제, 삭제 확인 모달, 사용자 목록 제외, 관리자 목록 보존, 기존 주문 정보 보존, 재요청·동시 충돌, 감사 기록. |
| **제외** | 복구, 물리 데이터 정리, 행사 연결 상품, 주문 취소·환불, 일반 상품 삭제로 인한 재고 수량 변경. |

이 제외 범위는 예시 가정이며 실제 팀 합의가 필요하다.

---

## 요구사항

| ID | 요구 | 수용 기준 |
|---|---|---|
| REQ-PRODUCT-DELETE-01 | ADMIN만 삭제 | 비로그인 401, USER 403, 상품 불변 |
| REQ-PRODUCT-DELETE-02 | 고객 목록에서 제외 | 성공 후 조회한 사용자 상품 목록에 대상이 없음 |
| REQ-PRODUCT-DELETE-03 | 운영·주문 보존 | 관리자 목록에 판매 중지 표시, 기존 주문 이름·가격 불변 |
| REQ-PRODUCT-DELETE-04 | 재요청·경합 대응 | 삭제 재요청은 200·시각 유지, 동시 갱신 충돌은 409 |
| REQ-PRODUCT-DELETE-05 | 결과 추적 | 최초 성공의 작업자·시각·상태 변화 기록, 권한 거부 기록 |
