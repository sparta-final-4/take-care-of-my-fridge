# A-01·A-02 상품 삭제 — 화면 명세 예시

> **학습용 가상 예시** — 실제 구현·팀 결정·테스트 결과가 아닙니다. 상품 논리 삭제 기능을 가정한 문서이며, 실제 프로젝트에 적용하기 전 정책과 증거를 확인하세요.

**읽는 법**: 화면을 그리는 설명뿐 아니라 버튼을 누르기 전후와 실패 상태까지 작성합니다.

## 기본 정보

| 항목 | 내용 |
|---|---|
| **화면** | A-01 상품 목록, A-02 상품 상세. |
| **권한** | ADMIN. 프론트 라우트 보호와 서버 API 인가는 별도로 확인한다. |
| **경로** | /admin/products, /admin/products/:productId. |
| **데이터** | 상품 도메인의 현재 상태. 기존 주문 정보는 이 화면에서 변경하지 않는다. |
| **관련 요구사항** | REQ-PRODUCT-DELETE-01~05. |

---

## 삭제 확인

판매 중 상품의 “삭제”를 누르면 확인 모달을 연다.

제목: “상품을 삭제할까요?”  
본문: 상품명과 정상가. “판매가 중지되고 고객 화면에서 사라집니다. 이미 주문한 고객의 주문 명세는 그대로 조회됩니다.”  
버튼: 취소 / 삭제(danger).

취소는 요청 없이 모달을 닫는다. 삭제 요청 중에는 제출을 다시 할 수 없게 한다. 정확한 닫기 동작은 UI 구현 시 확정한다.

---

## 상태별 동작

| 상황 | 화면 동작 | 데이터 영향 |
|---|---|---|
| 성공 200 | 모달 닫기, 성공 안내, 목록·상세 재조회 | DELETED 반영 |
| 이미 삭제됨 200 | 동일하게 재조회 | 기존 삭제 시각 유지 |
| 401 | 공통 인증 흐름 적용 | 화면만으로 삭제 성공 판단 금지 |
| 403 | 권한 없음 안내, 성공 알림 없음 | 상품 변경 없음 |
| 404 | 대상이 없다는 안내 후 목록 재조회 | 추가 삭제 없음 |
| 409 | “상품 정보가 변경되었습니다. 새로고침 후 다시 시도해 주세요.” | 새 상태 확인 후 사용자 재시도 |
| 5xx·연결 실패 | 실패 안내, 상태 재확인 가능 | 서버 반영 여부를 응답 없이 단정하지 않음 |

전역 mutation 오류 알림과 화면 알림이 중복되지 않게 실제 프론트 규칙에 맞춰 처리한다.

---

## 목록·상세 표시

관리자 목록의 삭제 상품은 “판매 중지”와 삭제 날짜를 보여준다. 삭제 버튼은 다시 제공하지 않는다. 사용자 목록은 해당 상품을 제외한다. 상세와 목록에 서로 다른 상태가 남지 않도록 서버 데이터를 재조회한다.

실제 작성 시 API·캐시 키·권한 만료 흐름을 현재 구현과 맞춘다. 이 예시가 미정인 인증 갱신 정책을 확정하지는 않는다.
