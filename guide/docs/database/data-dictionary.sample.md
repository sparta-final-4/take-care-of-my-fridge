# products 데이터 사전 — 컬럼 작성 예시

> **학습용 가상 예시** — 실제 구현·팀 결정·테스트 결과가 아닙니다. 상품 논리 삭제 기능을 가정한 문서이며, 실제 프로젝트에 적용하기 전 정책과 증거를 확인하세요.

**읽는 법**: 각 필드의 타입뿐 아니라 값의 의미·단위·제약까지 적습니다. MySQL 8 계열과 JPA 시간 관리를 가정한 학습용 설계입니다.

## products — 판매 상품

등록·이미지·보관 등 전체 상품 스키마가 아닌 **논리 삭제 설명에 필요한 컬럼 발췌**입니다.

| 컬럼 | 타입 | NULL | 기본값·생성 | 제약 | 의미 |
|---|---|---|---|---|---|
| id | BIGINT | 불가 | AUTO_INCREMENT | PK | 내부 상품 식별자 |
| member_id | BIGINT | 불가 | 입력 | FK members.id | 등록 관리자 |
| name | VARCHAR(200) | 불가 | 없음 | 빈 문자열 금지(업무 검증) | 현재 상품명 |
| price | INT | 불가 | 없음 | 1 이상(업무·DB 검증 대상) | 현재 정상가, 원 단위 |
| status | ENUM('ON_SALE','DELETED') | 불가 | ON_SALE | 허용 상태 | 판매·논리 삭제 상태 |
| deleted_at | DATETIME(6) | 허용 | NULL | 상태 조합 검증 | 최초 삭제 시각, UTC |
| version | BIGINT | 불가 | 0 | 갱신 충돌 감지 | 동시 변경 버전 |
| created_at | DATETIME(6) | 불가 | 애플리케이션 | 감사 | 생성 시각, UTC |
| updated_at | DATETIME(6) | 불가 | 애플리케이션 | 감사 | 최종 변경 시각, UTC |

상품명 길이·가격 기본값 없음·JPA 시간 생성은 예시 선택이다. 실제 규칙의 금액 DEFAULT 0, DB 자동 시간 갱신과 다르므로 팀 결정 없이 옮기지 않는다.

---

## 제약과 상태

- FK: fk_products_member, member_id → members.id, DELETE RESTRICT. 팀 규칙상 FK 컬럼은 `[참조 테이블 단수형]_id`이므로 "등록자"라는 뜻은 COMMENT로 남긴다.
- ON_SALE이면 deleted_at=NULL, DELETED이면 deleted_at이 존재.
- 이미 삭제된 상품 재요청은 deleted_at·version을 바꾸지 않음.
- 이름·가격을 주문 스냅샷에 복사하는 시점은 주문 생성 계약에서 정의.
- 테이블·컬럼 COMMENT는 위 한국어 의미를 기반으로 작성.

---

## 인덱스

관리자 목록은 상태·등록 시각을 사용한다. 후보는 (status, created_at, id)이나 최종 채택은 실제 데이터와 실행 계획을 보고 결정한다. 인덱스가 효과적이라고 측정 없이 단정하지 않는다.

---

## 마이그레이션 확인

기존 데이터가 있다면 status·version 초기값과 삭제 시각 누락 여부를 확인한다. 전체 행의 삭제 시각을 일괄 현재 시각으로 채우지 않는다. 정확한 마이그레이션 파일·도구는 실제 환경에서 정한다.

계정·주문·감사 테이블 정의는 별도 데이터 사전이 필요하며 이 발췌에 포함되지 않는다. 회원·작업 이력 테이블의 실제 정의는 [실제 데이터 사전](../../../docs/database/data-dictionary.md)을 본다.
