# WORK-001: 상품 논리 삭제 — 작업 기록 예시

> **학습용 가상 예시** — 실제 발생한 사건·팀 결정·검증 결과가 아닙니다. 서술 방식과 필요한 근거를 설명하기 위한 사례입니다. 실제 증거가 없는 부분을 완료 실적으로 제출하지 마세요.

**읽는 법**: 계획부터 완료 보고까지 어떤 정보를 남기는지 보여줍니다. 아래 AI 제안·판단도 실제 대화 이력이 아닌 가상 예입니다.

## 목표와 범위

A-01·A-02에서 상품을 삭제하고 REQ-PRODUCT-DELETE-01~05를 만족한다. 상품 API·상태·관리자 화면이 기본 범위다. 주문 코드 수정이 필요하면 기존 스냅샷 계약과 담당자 승인 범위를 확인한다.

## AI 활용 기록을 쓰는 예

**맡긴 작업**: 기존 구현 탐색, 계약에 맞춘 삭제 흐름·테스트 초안, 문서 갱신 초안.

| 가상 제안 | 개발자 판단 예 | 검토 포인트 |
|---|---|---|
| “상품 행을 삭제하고 목록에서 제거한다.” | 기존 주문과 관리자 확인 요구를 대조해 논리 삭제로 수정 요청. | 상품 행 유지와 주문 가격 보존은 별개이므로 주문 스냅샷도 확인. |
| “삭제 후 화면 배열에서만 항목을 제거한다.” | 서버 조회·캐시 정책과 맞추기 위해 목록·상세 재조회 및 사용자 조회 조건 검증 요청. | — |

실제로는 자신이 받은 제안과 확인한 근거만 적는다.

실제 구현 파일이 없으므로 파일 경로나 변경 완료를 만들지 않는다. 구현 후 아래처럼 책임별로 채운다.

| 영역 | 적을 내용 | 현재 증거 |
|---|---|---|
| API·서비스 | 실제 파일과 권한·상태·트랜잭션 변경 | 없음 |
| 화면·API 모듈 | 실제 파일과 요청·알림·재조회 변경 | 없음 |
| 조회 | 삭제 상품 제외 조건의 실제 변경 | 없음 |
| 테스트 | 실제 테스트 파일과 재현·기대 결과 | 없음 |
