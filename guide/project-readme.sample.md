# 냉장고를 부탁해 — 포트폴리오 README 작성 예시

> **학습용 가상 예시** — 실제 구현·팀 결정·테스트 결과가 아닙니다. 상품 논리 삭제 기능의 설계가 구체화된 상황을 가정했습니다. 실제 문서로 옮길 때 정책과 증거를 다시 확인하세요.

**읽는 법**: 프로젝트 전체가 완성됐다는 주장 대신, 완료한 기능을 어떤 근거와 함께 소개할지 보여줍니다. 전체 README에는 실제 실행 방법과 전체 기능도 추가합니다.

## 서비스와 담당

냉장고 재료와 레시피·상품을 연결하는 서비스다. 이 예시의 개인 기여는 관리자 상품 삭제 흐름, API 계약, 상태 관리, 삭제 후 조회 정책을 설계하는 것으로 한정한다.

---

## 해결한 문제를 설명하는 방식

상품 행을 지우면 운영 이력을 확인하기 어렵다. 또한 고객 화면에서 판매를 중단하는 동작과 과거 주문 정보를 유지하는 동작을 함께 다뤄야 한다. 예시에서는 삭제 상태와 시각을 기록하고, 사용자 목록과 관리자 목록에 서로 다른 조회 정책을 적용하는 방식을 선택했다.

위 문장은 **가상 사례의 설명**이다. 실제 제출 시에는 구현 및 검증이 확인된 문장만 남긴다.

## 실행·시연 증거

실제 프로젝트의 필수 버전, 환경 변수 이름, 실행 순서, 테스트 계정 준비 방법을 적는다. 예시에서는 실행 가능한 코드가 없으므로 명령·배포 URL·계정 정보를 만들지 않는다.

실제 제출 전 추가할 것: 본인 커밋·PR 링크, 재현 가능한 테스트 결과, 삭제 전후 화면, 실제 구현 범위와 남은 제한.

## 한계

행사 진행 중 상품 삭제 정책은 이 사례 범위 밖이다. 삭제 조건 누락 위험이 있어 사용자 목록·검색·추천의 실제 제공 경로를 확인해야 한다. 측정하지 않은 성능 개선 수치는 제시하지 않는다.
